# 스토리 스크립트 작성 가이드 (제미나이용, 초안 v0.1)

작성일: 2026-10-01 · 대상: 스토리 스크립트를 쓰는 AI(제미나이)와 그것을 게임에 넣는 사람·AI
태그: ✅확정 / 🟡제안 / ❓미정

## 1. 역할과 흐름 ✅
- **제미나이 = 스토리 스크립트(대사·장면 구성) 담당.** 코드·수치·이미지는 건드리지 않는다.
- 흐름: ① 제미나이가 **초안 CSV**를 쓴다 → ② `python tools/validate_story.py . <초안 파일>`로 형식 검사 → ③ Claude가 선물·조건 **밸런스를 확인** → ④ 사용자가 내용을 보고 승인 → ⑤ `data/story/story_beats.csv`에 합친다.
- 초안 위치: `docs/drafts/story/` (예: `story_beats_gemini_001.csv`). **`data/`에 직접 쓰지 않는다.**
- 브랜치: `feature/story-script` (기능 브랜치, `AI_협업_규칙.md` 2장).

## 2. 출력 형식 (게임이 읽는 그대로) ✅
파일: `data/story/story_beats.csv`, 열은 정확히 이 순서입니다.

```
beat_id,npc_id,conditions,gifts,repeat_days,lines
```

| 열 | 형식 | 설명 |
|---|---|---|
| `beat_id` | 소문자·숫자·밑줄 | 장면 이름. 중복 금지 (`welcome_oven`) |
| `npc_id` | `data/story/story_npcs.csv`의 `npc_id` | 현재는 `neighbor`(이웃 주민)만 있음. 새 NPC는 사용자 승인 후 추가 |
| `conditions` | `;`로 이은 조건, **모두 맞아야** 나옴 | 아래 3장 목록만 사용 |
| `gifts` | `종류:아이디:수량`을 `;`로 이음. 종류 = `item` / `furniture` / `money` | 없으면 빈 칸 |
| `repeat_days` | 숫자 | 0 = 한 번만, N = N일마다 반복 가능 |
| `lines` | 대사 한 칸을 `\|`로 이음 | 한 칸 = 대화창 한 번 |

예:
```
welcome_oven,neighbor,day>=2;expedition_done;furniture_missing:magic_oven,furniture:magic_oven:1,0,개업 축하해요!|마을 사람들이 조금씩 모아서 만들었어요.|잘 써 줘요.
```

## 3. 쓸 수 있는 조건 ✅ (`story_conditions.gd`와 같은 목록)
- `day>=N` — 게임에서 N일 이상 지남
- `expedition_done` — 원정을 한 번 이상 다녀옴
- `money<N` — 소지금이 N 미만
- `item_below:아이템아이디:N` — 그 아이템이 N개 미만
- `furniture_missing:가구아이디` — 그 가구가 인벤토리에도 배치된 것에도 없음
- `product_stock_empty` — 팔 수 있는 상품이 모두 0개

**이 목록에 없는 조건은 게임에서 항상 거짓**이라 장면이 영원히 안 나옵니다. 새 조건이 필요하면 쓰지 말고 `docs/AI_소통.md`에 요청합니다(코드는 ChatGPT).

## 4. 아이디는 실제 파일에서 가져온다 ✅
- 아이템: `data/core/items.csv`의 `id`. 가구: `data/shop/catalogs/furniture_items.csv`의 `id`. **없는 아이디를 만들어 쓰지 않는다**(검사기가 오류로 잡음).

## 5. 글쓰기 규칙 🟡
- 한 칸 **40자 이내**, 장면당 **6칸 이하**(대화창 크기에 맞춘 값, ❓ 실제 화면 확인 필요).
- 말투: 편의점이 있는 작은 마을의 이웃. 따뜻하고 짧게. 게임 수치(골드, 확률, 숫자 능력치)를 대사에 직접 쓰지 않는다.
- 원정 규칙의 결정을 어기지 않는다: 포션은 원정에서 쓰지 않고, 공격력·방어력 숫자는 공개하지 않으며, 원정은 요일 제한이 없다.
- 선물은 **도움이 필요한 상황(조건)에 맞는 것만**, 수량은 적게. 돈 선물은 밸런스 영향이 커서 Claude 확인 후에만 넣는다. 선물 목록은 `docs/원정_v2_규칙서_초안.md` 6.6을 참고(시작 자금은 임시값).
- **세계관 배경과 NPC 반응 지침은 `docs/drafts/story/world_setting.md`에 있고**(🟡 시험용: "이세계 숲 한가운데 떨어진 현대 24시 편의점", 신기해하는 반응 1줄 이상, 게임 용어 대신 소문·부탁 형태) 초안 생성기가 시스템 프롬프트에 자동으로 붙인다. 고치려면 그 문서만 고친다. 게임에 "퀘스트"라는 시스템은 없고 **"부탁"**이 있으므로(5.1) 대사에서는 퀘스트·보상·레벨 같은 게임 용어 대신 사람이 하는 부탁으로 말한다.
- 미정(❓) 설정(지역·마을·인물의 고유 이름, 최종 스토리)은 임의로 정하지 말고 초안 맨 위 주석 대신 `docs/AI_소통.md`에 질문으로 남긴다.

## 5.1 부탁(퀘스트 성격) 콘텐츠의 분업 🟡 (2026-10-01 제안)
게임에는 "퀘스트"라는 이름의 시스템은 없지만 **주민 부탁**(`resident_request_*`, 데이터 `scenes/shop/requests/default_resident_requests.tres`)과 **마을 부탁 게시판**(ChatGPT의 `feature/village-life`, `default_community_requests.tres`)이 있다. 이 데이터는 지금 코드 리소스(`.tres`) 안에 한 줄씩 들어 있어 제미나이가 직접 쓰기 어렵고, 같은 항목을 ChatGPT와 제미나이가 둘 다 쓰면 겹친다. 그래서 **한 항목을 "기계 부분"과 "글 부분"으로 나눠 담당을 가른다.**

| 부분 | 내용 | 담당 |
|---|---|---|
| 기계 | `id`, 필요한 `item`·`amount`, `reputation`·`money`, `landmark`, `after`(선행 부탁), `friendship` | 구조는 ChatGPT, **수치는 Claude(밸런스)** |
| 글 | `title`, `summary`, `lines`(부탁하는 대사), `completion`(완료 문장), 주민 인사말(`greetings`) | **제미나이** |

- **승인됨(2026-10-01 사용자 결정): 이 분업으로 진행한다.**
- 같은 `id`로 이어 붙인다. 제미나이는 이미 있는 `id`의 글 열만 쓰고, 새 `id`와 수치는 만들지 않는다.

**글 CSV 규격** (`data/shop/requests/requests_text.csv`로 갈 형식, 지금은 초안으로 `docs/drafts/story/requests_text_*.csv`)
```
id,kind,title,summary,lines,completion
```
| kind | 채우는 열 | 원본(기계 부분이 있는 곳) |
|---|---|---|
| `resident_request` (주민 부탁) | title, lines(부탁 대사 `\|` 구분), completion(완료 대사) | `default_resident_requests.tres` |
| `community_request` (마을 게시판) | title, summary, completion | `default_community_requests.tres` |
| `resident_greeting` (주민 인사말) | lines(아침·안부·하루 이야기·밤 순서) | `default_village_life.tres`의 `greetings` |
- 길이: title 20자, summary 60자, lines·completion 한 칸 45자(lines 6칸 이하). 게임 용어(퀘스트·의뢰·보상·레벨·경험치·미션·임무·스탯·수락·클리어) 금지. **수량·돈·평판 숫자 금지**(수치를 바꾸면 글이 틀려지므로 재료 이름만 말한다).
- 기준 문장: `docs/drafts/story/requests_text_baseline.csv`(현재 원본 11행의 글). 검사하면 **수량 표현 6건**(예: "빵 두 개")과 **한 칸 46자 1건**(`healer_moss`)이 걸린다. 수치와 글이 어긋나기 쉬운 곳이라 제미나이가 새로 쓸 때 고치게 한다.

**도구** (`feature/story-script`의 `dev/gemini/`, 파이썬 불필요)
```
dev\gemini\run_request_text.bat export                  현재 글을 기준 문장 CSV로 내보내기
dev\gemini\run_request_text.bat draft [kind]            제미나이가 글을 새로 쓰고 자동 검증
dev\gemini\run_request_text.bat validate <csv 경로>      CSV 검사
```
- 검사: `id`가 원본에 있는지, kind별 열 규칙, 길이, 금지어(오류), 수량 표현(주의), 중복. 시험: `dev/scenes/check_request_text.tscn`(21개).
- 프롬프트에는 인물·필요한 재료 이름·완성 장소만 주고 **보상 수치는 주지 않는다.** 세계관 설정(`world_setting.md`)이 자동으로 붙는다.
- 같은 `id`의 글만 바뀌므로 코드·수치는 영향이 없다.

**ChatGPT가 할 일(제안)**: 글 필드(`title`, `summary`, `lines`, `completion`, `greetings`)를 `.tres`에서 위 CSV로 빼서 코드가 `id`로 읽게 한다. 새 부탁은 기계 부분만 만들고 글은 비워 두면(또는 임시 문장) 제미나이가 채운다. 수치는 Claude에게 확인을 받는다.

### 5.1 구현 보충: 기존 콘텐츠 CSV 분리 (2026-10-01)

- `feature/village-life`에서 게임이 읽는 글 파일은 **`data/shop/requests/requests_text.csv`**. 열은 `id,kind,title,summary,lines,completion`, 여러 대사 칸은 `|`로 구분합니다. 쉼표·따옴표·줄바꿈은 표준 CSV 인용 규칙을 사용합니다.
- 기존 문구 **35행**을 그대로 이전했습니다. 기계 설정 `.tres`의 ID·재료·수량·보상·선행 조건·배치 경로는 유지됩니다. 수량/평판/돈/상태 버튼은 기존 UI가 설정 값에서 조합합니다. 인물의 기존 이름·직업과 관계 호칭도 기능 설정에 유지합니다.
- 추가 kind: `resident_introduction`(첫 방문, lines), `trade_offer`(교환 품목 제목, title), `tutorial_step`(title/summary=행동 안내/lines/completion), `tutorial_dialogue`(첫 결제 안내, lines), `service_text`(시설 제목·이용 안내·완성 장소, 현재 채워진 글 열만). 기존 `resident_request`에는 정착 부탁 3개도 포함합니다. 첫 방문 ID는 기존 손님 type이며 kind와 함께 식별합니다.
- 제미나이는 **기존 kind/id와 대사 칸의 역할을 유지**한 CSV 초안을 `docs/drafts/story/`에 작성합니다. 튜토리얼의 조작 키와 실제 행동 안내는 이야기로 바꾸더라도 의미를 유지해야 합니다. 기계 설정에 없는 ID는 검사기가 거부합니다.
- `dev/gemini/run_request_text.bat export`는 현재 게임 CSV를 읽어 `docs/drafts/story/requests_text_baseline.csv`로 내보냅니다. `draft [kind]`와 `validate <csv>`도 35개 항목을 인식합니다. 검토·검사·사용자 승인 후 글 행을 게임 CSV에 반영하고 실행을 다시 시작합니다. 이번에는 API 호출과 새로운 글 생성은 하지 않았습니다.
- 기존 문장을 보존했으므로 원본 35행은 현재 글 규칙 검사에서 **길이 초과 13개/주의 13개**가 나옵니다. 기계적인 CSV 이전 검사는 통과했지만, 새 글 작성 규칙을 통과한 최종 대사는 아닙니다. 제미나이의 후속 문장 정리 대상입니다.

### NPC 설정 참고 (2026-10-06)

- 외형·성격·생활 습관·관계 방향의 초안은 `docs/drafts/story/character_profiles.md` 한 곳에서 관리한다. 기존 이름/말투 원본과 별도로 같은 이름표·말투 CSV를 만들지 않는다.
- 부탁 글 `draft`/`polish`는 현재 화자의 설정만 자동으로 붙인다. 기존 `neighbor` 장면 생성은 오렐 설정만 참고한다. 역할 방문자를 같은 직업의 이름 있는 주민으로 바꾸지 않는다.
- 외형·취향·후속 관계는 제작/서사 제안이다. 실제 모델 변경·선물 취향 시스템·새 방문/개인 사건을 구현한 것으로 쓰지 않는다. 속마음을 첫 소개에서 공개하지 않고 실제 장면 단계가 우선한다.
- 사용자 도구 실행 시 참고 문맥이 포함된다. 이번 설정 작성에서는 API를 호출하지 않았다.

## 6. 제미나이 API 사용 (Google AI Studio, 사용자 PC에서) ✅

구현: `feature/story-script` 브랜치의 `dev/gemini/` (`gemini_client.gd`, `story_draft_generator.gd`, `story_draft.tscn`). 게임 본편에는 들어가지 않는 개발 도구입니다.

**API 키 규칙 (보안)**
- 키를 저장소·채팅·문서·커밋·스크린샷에 붙이지 않는다(Pixel Lab 토큰이 이미 한 번 노출됨). 클라우드(Claude 환경)에서는 사용자 키를 쓰지 않는다.
- `GeminiClient`가 키를 찾는 순서: ① 환경 변수 `GEMINI_API_KEY` ② 프로젝트 설정 `gemini/api_key` — 단 **저장소에 올라가는 `project.godot`이 아니라 올리지 않는 `override.cfg`**(프로젝트 폴더, `.gitignore` 등록)에 적었을 때만 ③ `user://gemini.cfg`의 `[gemini] api_key`(저장소 밖).
- **`project.godot`에는 키를 쓰지 않는다.** 그 파일은 저장소에 올라가고, 게임을 내보내면 안에 들어가 버린다.
- 권장은 ①. Windows(cmd) 한 번만: `setx GEMINI_API_KEY "여기에_키"` 후 터미널을 새로 연다. (키 값을 채팅에 붙이지 말 것)
- `override.cfg`를 쓸 때 형식(프로젝트 폴더에 만든다, 올라가지 않음):
  ```
  [gemini]
  api_key="여기에_키"
  ```
- 모델은 환경 변수 `GEMINI_MODEL`로 바꾼다. 기본값은 `gemini-3.8-flash`다(2026-10-01 웹 검색: 2.5 계열은 9/18부터 기존 사용자만 접근 가능, 새 프로젝트에는 3.8 Flash 또는 3.5 Flash-Lite 권장). 모델 이름은 자주 바뀌므로 AI Studio에서 확인하고 `GEMINI_MODEL`로 바꾼다.

**초안 만들기**
```
godot --headless --path . res://dev/gemini/story_draft.tscn -- --topic "첫 원정을 앞둔 날 이웃의 응원" --count 3
```
- 코드가 `items.csv`·`furniture_items.csv`의 아이디 목록을 프롬프트에 자동으로 넣는다(없는 아이디 방지).
- 결과는 `docs/drafts/story/story_beats_gemini_<시각>.csv`에 저장되고, 코드블록 표시와 중복 머리글을 정리한다.
- 저장 뒤 바로 `python tools/validate_story.py . docs/drafts/story/<저장된 파일>`을 돌린다. `data/`는 직접 고치지 않는다.
- 키가 없으면 네트워크에 나가지 않고 안내 메시지를 낸다. 요청에는 키를 헤더(`x-goog-api-key`)로만 싣고 주소와 로그에는 쓰지 않는다.
- 검사: `dev/scenes/check_gemini_client.tscn`(요청 본문·응답 해석·키 찾기·CSV 정리, 네트워크 불필요).

## 7. 제미나이에게 줄 프롬프트 틀 🟡
```
너는 편의점 경영 + 판타지 원정 게임의 스토리 작가다. 아래 규칙에 맞는 장면 CSV 행만 출력한다(설명·머리말 없음).
- 열: beat_id,npc_id,conditions,gifts,repeat_days,lines  (쉼표 구분, 대사 안에 쉼표가 있으면 칸 전체를 큰따옴표로 감쌈)
- npc_id는 neighbor만 사용. 조건은 day>=N, expedition_done, money<N, item_below:아이디:N, furniture_missing:아이디, product_stock_empty 만 사용.
- 선물은 item/furniture/money 중 하나, 아이디는 내가 준 목록에 있는 것만 사용.
```
