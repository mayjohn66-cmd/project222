# 장터 뒤의 먹거리와 후일담 (2026-10-03)

첫 장터 다음에 이어지는 주민 개인 부탁 3개와 후일담 3개다. 원정에서 재료·레시피를 찾고, 가게의 기존 제작 상품을 이웃과 나누는 흐름을 추가했다.

## 새 부탁

| 주민 | 부탁 | 전달 물품 | 앞선 개인 부탁 | 기존 레시피·시설 |
|---|---|---|---|---|
| 타블렌 | 장터 뒤의 달콤한 한 모금 | 열매 주스 2개 | 타블렌의 이웃 간식 | `berry_juice` · 음료 제조기 |
| 코르빈 | 일을 마친 뒤의 따뜻한 식사 | 버섯 스튜 1개 | 코르빈의 도구 손질 | `mushroom_stew` · 마법 오븐 |
| 이세르 | 장터 소리를 적는 오후 | 약초 음료 2개 | 이세르의 우물 곁 기록 | `herb_drink` · 음료 제조기 |

- 공통 조건: 튜토리얼, 해당 주민 정착·안부 7일, 앞선 개인 부탁, 실제 우물 곁 저녁 모임, 실제 첫 장터 완료. 선행 부탁·모임·장터 중 가장 늦게 끝난 날의 **다음 날부터** 가능하다.
- 필요한 레시피를 배워야 부탁을 맡을 수 있다. 미학습 상태에서는 수첩·게시판이 원정 두루마리 사용을 안내한다. 레시피·시설·두루마리를 새로 지급하거나 자동 해금하지 않는다.
- 기존 주민에게 E로 대사를 듣고, 기존 마을 게시판에서 직접 부탁을 맡고 창고의 완제품을 전달한다. 부탁은 세 개 중 자유로운 순서로 진행하며 기한은 없다.
- 전달 보상은 각 **30 G·평판 1**, 한 번만 지급한다. 수량·친밀도·대기일·보상은 `default_market_afterglow.tres`의 초기 조정값이며 Claude 검토 대상으로 남긴다.
- 재료를 그대로 대신 전달할 수 없다. 기존 창고의 완제품을 받아 사용하는 구조이며, 상품을 이번 부탁 때문에 직접 제작했는지 출처까지 추적하지는 않는다.

## 전달 이후

1. 전달을 마치면 수첩의 해당 개인 부탁에 **주민에게 후일담 듣기 [E]**가 나타난다. 목적지는 움직이는 실제 주민이다.
2. 주민에게 말을 걸면 기존 하루 안부 뒤에 후일담이 이어진다. 타블렌은 내일 펼칠 노점, 코르빈은 일을 내려놓은 식사, 이세르는 기록한 얼굴을 이야기한다.
3. 대화를 끝까지 읽었을 때만 후일담을 들은 날짜와 짧은 기억이 저장된다. 중단·씬 종료 시에는 다음에 다시 들을 수 있다.
4. 후일담에는 추가 물품 소비나 별도 답례가 없다. 기존 하루 인사 선물·친밀도는 기존 규칙대로 적용된다.
5. 다 읽은 뒤에는 해당 부탁의 수첩에서 기억을 확인할 수 있다. 이후 주민에게 새 후일담을 계속 강제로 붙이지 않는다. 이세르의 기존 선택 기억 대화는 후일담을 마친 다음 다시 이용할 수 있다.

## 구현

- 새 `MarketAfterglowSettings`와 `default_market_afterglow.tres`에 부탁 3개·장면 3개를 모았다. `MarketAfterglowFlow`가 후일담의 대기·완독·기억을 처리한다.
- 기존 `PersonalRequestFlow`에 새 설정 목록을 연결하고 장터·레시피 조건을 추가했다. 기존 6개 부탁은 같은 설정과 조건을 사용한다. 새 개인 부탁을 포함한 합계는 9개다.
- 기존 게시판과 수첩이 개인 부탁 목록을 자동으로 표시한다. UI·지도·NPC·`main.tscn`에 새 노드를 추가하지 않았다.
- 전달 기록은 기존 `personal_request:<id>:accepted/done`에, 후일담은 `market_afterglow:<id>:heard`에 저장한다. 저장 형식 변경은 없다.
- 새 부탁이 기존 주민 정착 완료 개수나 특별 손님의 방문 조건을 바꾸지는 않는다.

## 제미나이 글 보강

`requests_text.csv`에 기존 종류 **`personal_request` 3개 + `service_text` 3개**를 등록했다. `content_voices.csv`에 상황·말투를 보충했고 정식 인물 기준 파일은 수정하지 않았다. API는 호출하지 않았다.

| 종류 | ID |
|---|---|
| 개인 부탁 | `naru_market_juice`, `doyun_market_soup`, `sora_market_drink` |
| 후일담 | `market_afterglow_naru`, `market_afterglow_doyun`, `market_afterglow_sora` |

물품은 창고에 준비하여 게시판에서 직접 전달하는 안내를 유지한다. 후일담은 이미 전달한 먹거리를 사용한 뒤의 이야기이며 추가 물품·답례·새 손님·시설·책을 약속하지 않는다. 수량·돈·평판 수치는 대사에 쓰지 않는다. `completion`은 실제 수첩에 표시하므로 짧은 기억으로 유지한다.

```bat
dev\gemini\run_request_text.bat draft personal_request --ids naru_market_juice,doyun_market_soup,sora_market_drink
dev\gemini\run_request_text.bat draft service_text --ids market_afterglow_naru,market_afterglow_doyun,market_afterglow_sora
```

글 도구에 첫 장터·레시피·후일담 조건을 연결했다. 또한 `speaker`가 있는 장터 장면의 기존 `stage`를 우물 모임 문맥으로 덮어쓰던 문제를 수정했다. 우물 모임의 기존 프롬프트는 유지한다. 초안은 검사와 검토 뒤 별도로 반영한다.

## 검증

- Godot 4.7.1 가져오기 2회, 전체 `.gd/.tscn` 427개 로드 실패 0.
- `check_market_afterglow` 97개 통과: 세 부탁의 선행·날짜·레시피 조건, 실제 주민 대사·게시판 버튼, 재고 부족·완제품 소비·일회성 보상, 기존 손님 조건 보존, 후일담의 중단·완독·저장·수첩·추가 보상 없음·씬 종료·새 게임, 글 도구의 종류·맥락을 확인했다.
- 기존 개인 부탁·게시판·주민 일상·수첩·이세르 이야기 70개·첫 장터 57개·글 작성 도구·글 런타임 검사 통과. 대사 CSV 오류·주의 0.
- 593×523 렌더에서 새 개인 부탁·전달 이후 안내와 닫기 버튼을 확인했다. 목록은 기존 스크롤을 사용한다.
- `tools/balance_baseline.py` 실행 성공. 이 도구는 새 부탁의 일회성 상품 소비와 답례를 직접 계산하지 않는다.
- 기존 인증서 저장소 오류·아이콘 누락·빈 데이터 행 경고는 남아 있다. 최종 로그에 `SCRIPT ERROR`는 없다. 처음부터 끝까지 사람이 직접 플레이한 확인은 아직 하지 않았다.
