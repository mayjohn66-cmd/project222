# 소문에서 진열대로: 매장 행사 안내

> 2026-10-04 공용/계절 구분과 반복 일정이 추가되었다. 현재 사양은 `docs/콘텐츠/2막/공용과_계절_매장_행사.md`를 따른다. 아래의 일회성 일정·봄 장터 food 범주·3개/18장면 집계는 당시 구현 기록이다.

## 방향

사용자 요청: 손님에게 마을 이야기를 듣고 필요한 재료와 상품을 준비한 뒤, 실제 구매와 품절 반응으로 준비의 의미를 알아차리게 한다. 날짜별 판매 공지보다 주민의 생활 사정과 경험을 중심으로 안내한다.

이번에는 기존 매장 행사 3개(던전 공략 채비, 봄맞이 장터, 길손들의 여행 준비)에 연결했다. 새로운 행사·날씨·군중·건물은 추가하지 않았다. 사계절 생활 사건 4개와 마을 첫 장터 부탁은 독립 콘텐츠이며 이 판매 행사와 같은 사건으로 집계하지 않는다.

## 플레이 흐름

1. 기존 소문 손님에게 E로 이야기를 듣는다. 장터에서 나눠 먹을 음식, 동료 몫의 포션, 길에서 먹을 빵과 물처럼 구매 이유를 먼저 듣는다.
2. 관리 메뉴의 일정 탭에 들은 말과 준비 메모가 남는다. 포션은 제조법을 알고 있을 때 약초·수액·채집한 물, 빵은 밀, 생수는 채집한 물을 준비하는 단서다. 만들거나 확보한 완제품은 **창고에만 두지 않고 진열대에 올려야** 손님이 구매한다. 준비 메모에서 진열을 안내한다.
3. 내부 날짜 설정에 따라 기존 추가 수요가 실제 손님의 구매 요청에 섞인다. 행사 소문을 듣지 않았어도 수요는 적용된다. 방문 비중·구매 가중치·수량·가격은 기존 CSV를 유지한다.
4. 행사 수요를 실제 선택한 손님이 결제하면 짧은 말이 자동 표시된다. 찾던 상품의 진열 재고가 전혀 없을 때는 품절 반응이 나온다. 평소 수요, 다른 상품으로 추천 구매한 손님, 종료된 행사에는 행사 구매 반응을 붙이지 않는다. 반응에 재고·돈·보상 변경이 없다.
5. 준비 중 / 한창 / 마지막 날 / 지나간 이야기로 메모가 바뀐다. 내일과 마지막 날은 알아볼 수 있게 안내하되 날짜 범위와 배율 공지는 표시하지 않는다. 끝난 이야기는 일정 탭에 남아 당시 실제 영업 기록과 함께 읽는다.

## 정확한 판매와 안내의 관계

| 행사 | 소문에 나오는 이유 | 실제 추가 수요 | 재료 단서 |
|---|---|---|---|
| 던전 공략 | 동료 몫까지 출발 준비 | 포션 | 포션 제조법을 아는 경우 숲 약초·호박 수액·채집한 물 |
| 봄맞이 장터 | 이웃·아이들과 함께 먹기 | 음식 범주, 빵과 물은 준비 예시 | 밀·채집한 물 |
| 길손들의 여행 준비 | 보따리에 넣을 먹거리 | 여행자의 빵·물 | 밀·채집한 물 |

- 원재료 자체가 이번 행사의 추가 수요 대상이 되는 것은 아니다. 실제 식품·포션 제조 경로의 재료 단서다.
- 장터는 특정 음식 하나만 사도록 고정하지 않는다. 평소 수요도 계속 섞이고 진열·접근·계산이 필요하므로 판매를 보장하지 않는다.
- 자동 반응은 마우스 입력을 가로채거나 대화 창을 띄우지 않는다. 같은 말 표시 중에는 다른 손님의 말로 덮어쓰지 않는다. 표시 시간·너비는 Resource에서 조정한다.
- 진열대에 일부만 남은 경우 기존 부분 구매·미충족 수량 기록을 유지한다. 이번 품절 반응은 처음 검색 시 전혀 없는 경우에만 나온다.
- 종료 후 영업 기록은 해당 기간 전체 매장의 기록이다. 행사 때문에 발생한 매출만 따로 분리했다고 표현하지 않는다. 영업을 하지 않았거나 기록이 없으면 결과를 만들어 내지 않는다.
- 기존 행사는 전체 경과 일자 기준의 일회성 일정이다. 이번 변경이 매년 같은 계절에 반복되는 축제를 구현한 것은 아니다.

## 글과 코드

- `scenes/shop/events/default_store_event_story.tres`: 기존 event_id와 6개 장면의 연결·제조 단서·실제 적용 맥락. 밸런스 수치는 없음.
- `script/world/shop/events/store_event_story.gd`: 시점별 소문·메모·실제 수요에 맞는 반응.
- `script/ui/shop/store_event_remark.gd`: 플레이어 소유 비차단 표시. 손님이 퇴장해도 표시를 잠깐 유지하며 플레이어/장면 종료 시 제거.
- `data/shop/requests/requests_text.csv`: 기존 service_text 종류로 18행 추가, 전체 127행. 이는 이벤트 수가 아니라 글 장면 수다.
- 기존 소문 창, 일정 카드, 실제 손님 품절·결제 지점에 최소 연결. 큰 상태·시간·원정 파일은 수정하지 않았다.

## Gemini에게 넘길 장면

API는 호출하지 않았다. 기존 글 도구가 맥락을 읽으며 `{item}`이 들어간 반응은 실제 품목 이름 치환이므로 제거 시 검사 오류로 막는다. 정식 인물 기준 파일은 변경하지 않았다.

```bat
dev\gemini\run_request_text.bat draft service_text --ids store_raid_rumor,store_raid_ongoing,store_raid_closing,store_raid_finished,store_raid_bought,store_raid_missing
dev\gemini\run_request_text.bat draft service_text --ids store_market_rumor,store_market_ongoing,store_market_closing,store_market_finished,store_market_bought,store_market_missing
dev\gemini\run_request_text.bat draft service_text --ids store_trail_rumor,store_trail_ongoing,store_trail_closing,store_trail_finished,store_trail_bought,store_trail_missing
```

대사에 판매 배율·날짜 범위·보장된 판매·자동 제작·미학습 제조법 해금·새 물품 지급을 넣지 않는다. 준비 메모에는 진열과 실제 제조 재료 안내를 유지한다. 봄 장터 음식 범주를 빵 한 종류로 축소하지 않는다.

## 실행 검증

```bat
godot --headless --path . --import
godot --headless --path . --import
godot --headless --path . res://dev/scenes/check_store_event_story.tscn
godot --headless --path . res://dev/scenes/check_checkout_event.tscn
godot --headless --path . res://dev/scenes/check_request_text.tscn
godot --headless --path . res://tools/check_godot.tscn
godot --headless --path . res://dev/gemini/request_text.tscn -- --mode validate --file data/shop/requests/requests_text.csv
python tools/balance_baseline.py .
```

Godot 4.7.1 자동 검사: 매장 이야기 103개 실패 0, 기존 강제 첫 손님 결제와 글 도구 실패 0. 전체 531개 로드 실패 0. CSV 127행 오류·주의 0. 기존 누락 가구 아이콘·인증서 경고는 별개이며 새 스크립트 오류는 없다. 밸런스 계산 도구 종료 코드 0, 기존 수요 수치를 바꾸지 않았다.

같은 시드로 고객 1,000명의 실제 구매 요청을 생성한 비교에서는 행사 전/기간/종료 후 요청 수량 합이 포션 행사 여행자 1,000/2,377/1,000, 장터 주민 1,000/1,493/1,000, 길손 행사 여행자 1,000/1,360/1,000이었다. 이는 **모든 재고가 있는 실제 매출 측정이 아니라 요청 생성 검사**다. 실제 결제 검사는 진열 수량 감소·판매 수량·정상 금액 지급·중복 결제 방지를 별도로 확인한다.

사람이 하는 플레이와 3D 줄기 최신 내용의 병합 검증은 아직 하지 않았다. 사용자 확인 전이라 작업 브랜치에만 올리며 main에 자동 병합하지 않는다.
