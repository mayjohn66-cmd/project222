# 재고가 떨어지면 원정으로 이끄는 초반 흐름 (제안 초안)

## 최신 조정 — 강제 소진 대기 제거 (2026-10-13)

사용자가 초반 진행 순서·강제 조건이 생각한 콘텐츠와 다르다고 지적했고, 연결 중단 후 다시 진행을 요청했다. 우선 재고 0을 필수 완료 조건으로 삼는 부분을 완화한다. 아래 10월 12일 구현 기록의 `shop_days` 필수 단계는 현재 흐름에서 비활성이다.

- 현재 순서: `cleanup → setup → stock → checkout → barter → expedition → raw_sale`. 장비 교환 뒤 상인의 원정 부탁을 듣고 원정을 준비할 수 있다.
- 남은 식품으로 계속 장사할 수 있다. 원정 진입과 원재료 판매 후 주민 콘텐츠가 재고 소진을 기다리지 않는다.
- 시작 물품 수량·실제 판매 가격·교환 비용·장비 지급·원정 보상은 바꾸지 않는다. 기존 `shop_days` ID·저장 기록·원본 문구는 보존하고 단계만 비활성으로 둔다.
- 원정 대사·제작용 장면 설명에서 「이미 진열대가 텅 비었다」는 전제를 제거한다. Gemini는 새 원정 도입 문구를 다듬을 때 재고 소진을 다시 필수로 만들지 않는다.
- 청소 6곳·집기 직접 설치는 이번 묶음에서 자동화하지 않았다. 짧은 정리·자동 배치·선택 활동 중 어느 형태가 원하는 초반 경험인지 아직 확인 중이다. 안내 UI를 늘리던 별도 초안도 반영하지 않았다.

### 검증

Godot 4.7.1 격리 환경: 가져오기 2회 ERROR/SCRIPT ERROR0, 초기 단계112 항목 실패0. 실제 타이틀에서 새 게임→첫 거래→장비 교환→상인 부탁→원정1판 이동·공격·채집·귀환→상인 보고→원재료 실제 판매까지 `check_new_game_continuity --core-only` 41항목 실패0. 이 검사에서는 출발 전 부탁 읽기와 귀환 보고도 실제 NPC 상호작용으로 수행한다. 종료 때 빵11·물9가 남아 있었고 실제 판매 합계170G로 핵심 진행이 완료됐다. 돈·물품·날짜·완료 기록을 임의 fixture로 지급하거나 완료 처리하지 않았다. 가게 안 이동은 자동화했다.

전체 로드924개 실패0(임시 검사 파일 포함), 경제 기준선 손님27/일·평균객단가239·예상매출6451로 기존 값 유지. 후반 전체 플레이 완료나 Windows RC1 재빌드로 간주하지 않는다.

2026-10-12 사용자 제안. 상태: ✅ **구현됨(2026-10-12)** — 소진 기준은 **재고 0**, 퀘스트는 **타블렌**(사용자 결정). 대사는 **임시 문구**라 Gemini 글로 바꿔야 한다. ❓ 중 아직 정하지 않은 것은 7장 표시를 따른다.

## 1. 제안 한 줄

"교환 직후 곧장 원정"이 아니라, **가게와 함께 온 이세계(원래 세계) 상품을 넉넉히 두고 몇 번 영업하게 한 뒤, 재고가 떨어지는 것을 감지해 '이제 재료를 구하러 가야 한다'는 계기를 이야기로 만든다.** 원정이 떠밀려 가는 일이 아니라 장사를 하다 필요해서 가는 일이 된다.

## 2. 지금 흐름 (확인한 것)

- 튜토리얼 핵심 순서: `cleanup → setup → stock → checkout → barter → expedition → raw_sale`(`scenes/shop/tutorial/default_tutorial.tres`). `barter`가 끝나면 바로 `expedition` 단계가 이어진다.
- 시작 식품은 적다. 청소에서 빵 4·물 8을 건진다(`opening_cleanup.gd` `LOOT_TOTAL`). 설계 문서(`이세계_첫_거래와_원정.md`)에는 빵 8·물 6으로 적혀 있어 **문서와 코드 수치가 다르다**(어느 쪽이 현재 기준인지 확인 필요).
- 타블렌 교환(빵 2 + 물 1 → 낡은 검·가죽 갑옷)이 시작 재고의 일부를 가져가므로, 지금은 영업을 길게 할 재고가 없다.
- **재고 소진을 감지해 이야기를 여는 장치는 현재 없다.** 코드에서 찾은 것은 오프라인 정산의 "판매 실패(재고 부족)" 집계와 손님 수요 가중치 정도다.
- 이미 있는 글 중 이 제안과 맞는 말: `barter` 완료 대사 "물류가 끊겼으니 이걸 입고 직접 밖에서 캐오란 거다."

## 3. 제안하는 흐름

| 순서 | 일 | 플레이어에게 보이는 것 | 비고 |
|---|---|---|---|
| 1 | 청소·설치·진열 | 지금과 같음 | 시작 재고만 "넉넉하게" 늘린다(❓ 얼마나) |
| 2 | 첫 손님(델빈) | 지금과 같음 | |
| 3 | 타블렌 교환 | 지금과 같음. 검·갑옷을 얻되 **바로 원정을 요구하지 않는다** | 장비를 챙겨 두는 것만 |
| 4 | **영업 며칠** | 편의점 상품을 팔며 이웃·손님을 만난다 | 이 구간이 "넉넉한 재고"의 역할 |
| 5 | **재고 감소 징후** | 진열대가 비어 가는 것을 독백·타블렌의 한마디로 알린다 | 임계값 ❓ |
| 6 | **재고 소진** | "다 팔렸다. 이제 직접 구해야 한다" → **원정 퀘스트** 생성 | 감지 장치를 새로 만들어야 함 |
| 7 | 첫 원정 → 원재료 진열 | 지금의 `expedition`·`raw_sale` | 순서만 뒤로 이동 |

## 4. 이야기로 이어 붙일 지점 (Gemini에 요청할 글 후보)

새 글이 필요하다. 새 id가 생기므로 코드 연결이 따로 필요하다.

1. **넉넉한 재고의 설명**: 가게가 통째로 넘어와 창고가 그대로 있다는 한 줄(왜 처음에는 걱정이 없는지)
2. **재고 감소 징후**: 마지막 몇 개가 남았을 때의 독백("이 속도면 모레쯤 빈다")
3. **재고 소진의 순간**: 마지막 상품을 판 뒤 빈 진열대를 보는 장면
4. **원정 퀘스트의 계기**: 누가 무엇을 부탁하는가(타블렌이 숲 재료를 사 간다고 제안, 델빈이 숲 이야기를 하는 등 — ❓)
5. **퀘스트 수락·첫 원정 출발 독백**, **돌아온 뒤 첫 판매 후일담**(지금의 `expedition`·`raw_sale` 글 재사용 가능)

현재 글과의 충돌 가능성: `expedition` 단계 글이 "교환 직후 곧바로 나간다"는 톤이다. 순서를 뒤로 옮기면 이 글의 시점이 어긋난다.

## 5. 손대야 할 곳 (예상, 아직 안 바꿈)

- `scenes/shop/tutorial/default_tutorial.tres` — `expedition` 단계의 시작 조건을 "교환 직후"에서 "재고 소진"으로.
- `script/world/shop/tutorial/opening_cleanup.gd` — 건지는 식품 수량(데이터 쪽으로 빼는 편이 좋다).
- **새 감시 장치** — 판매 가능 재고(`ItemData`의 판매 상품 + 진열대 안 재고)를 합산해 임계값 아래로 내려가는 때를 알려 주는 것. 기존 큰 파일(`game_state.gd` 등)에 덧붙이지 않고 새 파일로 만든다.
- `tutorial_director.gd`의 단계 진행 규칙, 저장 호환(`tutorial_step:<id>:intro/done`은 유지).
- 새 글 CSV 행과 구조 파일.
- 테스트: `check_progressive_tutorial`, `check_opening_prologue`, `check_direct_expedition` 계열이 순서 변경에 영향을 받는다(실행해 확인하지는 않았다).

## 6. 위험과 확인할 것

- **재고가 너무 오래 가면** 원정이 늦어지고, 너무 빨리 떨어지면 지금과 같아진다. 하루 판매량과 손님 수를 재서 "며칠 영업"이 되도록 수량을 정해야 한다(측정 도구: `tools/balance/balance_baseline.py`로 먼저 가능한지 확인 필요, 아직 안 돌려 봄).
- **재고를 팔아 번 돈의 쓸 곳**이 있어야 한다. 이 구간에 돈을 쓸 곳이 없으면 퀘스트 전에 지루해진다.
- **원정으로 가야 한다는 걸 놓치는 플레이어**: 재고가 0이어도 퀘스트 안내가 눈에 띄어야 한다.
- 기존 저장: 이미 `expedition`을 끝낸 저장은 영향이 없어야 한다.
- 시작 자금(500,000)과 시작 재고(999개)는 작동 확인용 임의값이라 이 계산에서 무시한다(`CLAUDE.md` 4장).

## 7. 사용자가 정할 것 ❓

1. 시작 재고를 얼마나 늘릴지(종류와 수량), 이 구간을 며칠로 볼지
2. 소진 기준: **모두 0**이 될 때인지, **일정 수 이하**(예: 처음의 20%)에서 안내를 시작할지
3. 원정 퀘스트를 낼 사람: 타블렌 / 델빈 / 플레이어 독백만
4. 교환(`barter`)을 영업 며칠 뒤로 옮길지, 지금 위치(첫 손님 직후)에 둘지
5. 재고가 남아 있어도 원정을 미리 나갈 수 있게 둘지(자유 원정 허용)

## 8. 하루 판매량 측정과 시작 재고 (2026-10-12)

도구: `dev/spike3d/daily_sales_probe.tscn` (`godot --headless --path . res://dev/spike3d/daily_sales_probe.tscn -- 300 bread,water`). 오프라인 정산(`ShopOfflineSimulator`)과 같은 함수(시간대별 도착률 → 손님 유형 → 원하는 품목)로 300일을 돌린 **기대값**이다. 진열대·직원·캐릭터는 만들지 않았다.

| 항목 | 결과 |
|---|---|
| 하루 도착 손님 | 24시간 열면 약 27명, 낮(8~20시)만 열면 약 16명 |
| 빵 수요 | 24시간 5.8개/일 · 낮만 3.6개/일 (150G) |
| 물 수요 | 24시간 3.5개/일 · 낮만 2.2개/일 (100G) |
| 빵+물 수요 금액 | 하루 약 1,220G(24시간 기준) |
| 그 밖의 수요 | 포션 4.5개/일, 미네랄워터 1.2개/일 등 — 진열대에 없으면 놓치는 판매다 |

**시작 재고를 이렇게 정했다**(교환·첫 손님분을 빼고 약 3영업일분)
- 빵 4 → **14**: 교환 2 + 첫 손님 1 + 3일 × 3.6 ≈ 14
- 물 8 → **10**: 교환 1 + 3일 × 2.2 ≈ 8, 여유 2
- 바꾼 곳: `script/world/shop/tutorial/opening_cleanup.gd`의 `LOOT_TOTAL`(청소하며 건지는 합계). `GameConfig.STARTING_INVENTORY`(빵 8·물 6)는 튜토리얼 시작 때 비워지므로 이 길에서는 쓰이지 않는다.

**한계**
- 도착 손님은 시간대별 도착률의 기대값이라 실제 하루는 흔들린다. 플레이어가 가게를 여닫는 시간에 따라 위 두 열 사이 어디든 된다.
- 빵은 유통기한이 6(실온에서는 하루에 2씩 늙어 약 3일)이라 **재고를 더 늘리면 3일 뒤에는 폐기된다**. 3일분으로 잡은 것도 이 때문이다. 냉장고가 생기면 더 오래 간다.
- 시작 직후 일반 손님은 튜토리얼 동안 기다리므로(`이세계_첫_거래와_원정.md`), 실제로 며칠 영업하게 되는지는 이 구간 설계(3·4번)에 달렸다.
- 이 수치는 감시 장치와 퀘스트를 만들 때 소진 임계값을 정하는 기준으로 쓴다. 감시 장치는 아직 없다.
- 확인: 튜토리얼·청소 배치·프롤로그·진열 공간·마을 확장·식품 기한 테스트가 통과했다(`check_progressive_tutorial`은 수량 대신 `LOOT_TOTAL`을 읽도록 고쳤다). 게임을 직접 실행해 확인하지는 않았다.

## 9. 구현 (2026-10-12)

**결정(사용자)**: 소진 기준 = 판매 가능한 식품이 모두 0일 때 · 퀘스트 = 타블렌이 플레이어에게.

**새 흐름**: `… → checkout → barter → shop_days → expedition → raw_sale …`
- `shop_days`(새 단계, 플레이어 독백): 교환 뒤 개점해서 남은 식품을 판다. 완료 조건 `stock_depleted`. 시작 독백(넉넉한 재고)과 완료 독백(소진 장면)이 있다.
- `expedition`(기존 단계): 말하는 사람이 플레이어 독백에서 **타블렌**으로 바뀌었다. 가게에 찾아온 타블렌에게 [E]로 부탁을 듣고 원정 → 돌아오면 타블렌에게 보고(마무리 대사) → `raw_sale`.

**소진 판정** (`OpeningJourneyFlow.stock_depleted`): 교환을 마친 뒤, 창고·가방의 판매 상품과 진열대 재고가 모두 0. **판매 상품(`store_product`: 빵·물)만** 센다. 합판 같은 자재는 세지 않는다(청소로 얻는 합판 4개가 있어 세면 영영 0이 되지 않는다).

**손님**: 교환 뒤부터 일반 손님이 온다(`regular_customers_allowed`, `customer_spawner.gd`). 전에는 튜토리얼이 끝날 때까지 일반 손님이 나오지 않아 재고가 줄 수 없었다.

**저장 호환**: `shop_days`는 `skip_if_later_started`라서 원정을 이미 시작한 저장에서는 요구하지 않는다(`core_finished`가 이 규칙을 따르게 고쳤다). 유통기한은 튜토리얼 동안 늙지 않는다(`FoodShelfLife.learning`)라서 `shop_days` 구간에 빵이 상하지 않는다.

**바꾼 파일**: `scenes/shop/tutorial/default_tutorial.tres`, `script/world/shop/tutorial/tutorial_flow.gd`·`opening_journey_flow.gd`, `script/actor/customer_spawner.gd`, 글 `requests_text.csv`(`shop_days` 새 행, `expedition` 문구 교체), 테스트 `check_progressive_tutorial`(흐름과 단계 수 10).

**임시 문구(Gemini가 새로 쓸 것)**: `tutorial_step:shop_days`(시작·소진 독백), `tutorial_step:expedition`(타블렌 부탁 4줄·보고 2줄). 줄 수는 지금 형식(독백 3·3줄, 부탁 4·보고 2줄)을 기준으로 두면 코드 변경이 필요 없다.

**확인하지 못한 것**
- 게임을 직접 실행해 흐름(영업 → 재고 0 → 타블렌 등장)을 눈으로 보지 못했다. 테스트는 소진 상태를 인위적으로 만들어 확인했다.
- 실제로 빵·물 24개를 파는 데 걸리는 영업일 수. 측정값(하루 약 9개, 낮만이면 약 6개)으로는 2~4일이지만, 수요가 놓친 품목(포션 등)으로 흩어지는 것은 반영하지 않았다.
- 7장 ❓의 4번(교환 위치)과 5번(재고가 남았을 때 미리 원정을 나가는 것)은 정하지 않았다. 지금은 재고가 0이 되기 전에는 원정 안내가 나오지 않는다. **소진 전에 원정 출발점을 쓸 수 있는지는 확인하지 않았다.**
