# 계산대의 상품 조회

2026-10-05 · 사용자 요청: 계산하지 않을 때 진열된 상품 정보를 계산대에서 확인. 작업은 main.

## 이용 흐름

- 손님이 없는 계산대 안쪽에서 **E / 상품 조회 [E]**를 누르면 **계산대** 창이 열린다. 기본 탭은 **상품 조회**, 두 번째 탭은 **마감 정리**다.
- 손님이 기다리면 기존 결제 경로가 우선이다. 직원 예약/첫 결제 안내를 그대로 따른다. 문을 닫은 뒤에도 상품 조회와 마감 정리를 사용할 수 있다.
- 창이 열린 동안 월드는 멈춘다. 돌아가기·창 닫기·숨기기·매장 제거 시 이전 일시정지 상태를 복원한다.

## 화면에 표시하는 정보

| 항목 | 표시 기준 |
|---|---|
| 상품 | 현재 매장 진열대에 등록된 이름. 같은 상품은 한 행으로 합산 |
| 진열 | 현재 진열 수량 / 해당 상품에 배정한 총 슬롯 용량 |
| 판매가 | 실제 결제에 쓰는 현재 단가. 날짜가 다른 재고는 최저~최고 가격 |
| 상태 | 품절·진열 필요, 판매 가능, 가장 빠른 기한과 할인 수량 |
| 선택한 상품 | 이름·진열 수량/용량·판매가·상태·기존 상품 설명 |

- 식품 외 원정 재료/일반 상품도 조회한다. 기한이 없는 상품에 식품 날짜를 붙이지 않는다.
- 진열 수량 0이어도 상품이 슬롯에 배정되어 있으면 품절로 남긴다. 아무 상품도 등록하지 않은 가게에는 진열대 등록 안내를 보여 준다.
- 공용 재고/냉장·냉동 보관량을 진열 수량으로 합치지 않는다. 다른 매장·건축 미리보기·삭제 예정 객체를 제외한다.
- 예: 같은 현지식 빵이 마지막 날 3개와 신선한 1개라면 진열 4개, 판매가 **70~100G**, 가장 빠른 기한 1일·할인 3개다. 할인 OFF라면 100G로 표시한다. 고정 가격을 새로 만들지 않는다.
- 상품 조회는 정보 화면이다. 오래된 재고 우선 판매/자동 할인/날짜 보존/만료품 분리 방식은 기존 구현을 쓴다. 기한과 경제 수치는 바꾸지 않았다.

## 마감 정리와 튜토리얼

기존 요약·자동 할인 토글·만료품 폐기/퇴비 재활용은 **마감 정리** 탭에 있다. 상품 조회만 보고 닫았다고 선택 식품 안내를 끝내지 않는다. 마감 정리를 한 번 확인하고 돌아가기/창 닫기한 뒤 기존 플레이어 독백을 마치면 완료된다. 확인 기록이 있는 저장은 그대로 인정한다.

food_care의 UI 안내·초안 문맥과 아침 안내를 **상품 조회 → 마감 정리**에 맞췄다. 신규 대사 종류/보상/주민 기능/API 호출은 없다.
