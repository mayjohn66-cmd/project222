# 이세계 첫 거래와 원정

2026-10-04 사용자 요청: 가게와 플레이어가 함께 이세계에 떨어졌다. 상황을 정리한 뒤 현지 손님의 실제 구매로 화폐를 받고, 떠돌이 상인과 식품을 장비로 바꾼다. 극초반 운영은 원정 재료를 그대로 판매하는 흐름이다.

## 실제 진행

| 순서 | 이야기 | 플레이어 행동 / 완료 조건 |
|---|---|---|
| 1 | 가게 밖이 낯선 숲. 계산대와 식품은 함께 옮겨 왔다 | 플레이어 독백 완독, 기존 문·계산대·진열대 확인 |
| 2 | 남아 있던 식품을 정리한다 | 진열대 E로 가게 식품을 진열 |
| 3 | 델빈이 유리문·불빛·포장에 놀라며 처음 구매한다 | 개점 시 확정 방문, 표시된 계산 위치에서 플레이어가 실제 식품 하나 결제 |
| 4 | 떠돌이 행상인 타블렌은 낯선 식품에 관심을 보인다 | 타블렌 E → 교환창 → 실제 식품과 현지 검·갑옷 교환 → 결과 대화 완독 |
| 5 | 장비를 얻고 숲에서 가져올 물건을 찾아본다 | 출발 지점 E, 검·갑옷 장착, 이동·기본 공격·채집·귀환 |
| 6 | 숲의 원재료를 그대로 내놓아 본다 | 판매 가능한 원재료를 진열하고 개점, 다시 온 델빈에게 실제 결제, 플레이어 독백 완독 |
| 이후 | 주민 부탁과 인연, 첫 노점 정착 | 기존 주민 콘텐츠 조건으로 이어짐 |
| 선택 | 이웃이 된 타블렌이 현지 제작 도구를 가져온다 | 첫 노점 정착 후 제작 안내 가능. 주민 콘텐츠의 필수 조건은 아님 |

현지인은 현대의 계산대·매출 기록·게임 메뉴를 이해하는 안내자가 아니다. 현대 운영은 플레이어 독백과 목표 UI가 설명한다. 현지인은 화폐, 길, 숲의 재료, 자기에게 필요한 물건을 안다. 델빈은 첫 손님이고, 타블렌은 기존 `naru/peddler` 인물이다.

## 시작 물품과 실제 교환

- 가게와 함께 온 식품: 빵 8, 물 6. 시작 현지 화폐 0. 이전 시험용 포션·광석·수정·열매 지급은 제거했다.
- 문·계산대·진열대 하나는 새 게임의 비어 있는 매장에 미리 놓인다. 보유 가구를 각각 하나 소비하므로 소유량이 중복되지 않는다. 다른 보유 집기는 함께 온 가게 물품으로 유지한다.
- 처음부터 고용된 직원은 없다. 직원 데이터의 신규 시작 고용 여부만 바꿨고, 기존 저장의 고용 상태는 유지한다. 새 게임 시작 시 이전 게임의 고용 상태가 남던 문제는 `GameState.initialize_new_game()`에서 초기화한다.
- 첫 구매는 진열 식품 하나의 실제 판매가로 지급된다. 가짜 연습 재고·무료 식품·첫 결제 장비 보상은 없다.
- 타블렌 교환의 초기값: 창고 빵 2 + 물 1 → 낡은 검 1 + 가죽 갑옷 1. `default_tutorial.tres`가 수량을 관리하고 화면이 현재 재고를 표시한다. 진열품은 창고로 회수해서 건넨다. 부족하면 아무것도 소비/지급하지 않으며 돈은 쓰지 않는다. 교환 확인 후 한 번만 소비·지급하고, 저장 후에도 반복 불가. 기존 보유 장비는 중복 지급하지 않는다.
- 원정 귀환만으로 재료 판매가 완료되지 않는다. 판매 가능 `material` 상품의 실제 구매·대금 지급이 필요하다. 재료가 없으면 다시 원정을 다녀올 수 있다. 제작 상품이나 가게 식품은 이 조건을 대신하지 않는다.
- 확정 손님의 미결제 상품은 중도 폐점 시 반환된다. 다시 개점하면 거래를 재개한다. 도입부 동안 일반 무작위 손님 생성은 기다리므로 교환용 식품이 먼저 팔리지 않는다.
- 제작 소개는 `settle_naru` 완료 후 가능하다. 현지 화덕 1·현지식 빵 제조법 두루마리 1·밀 4를 소개 완독 시 한 번 준다. 기존 생산 구역 문은 가게가 소유한 물품이다. 만든 현지식 빵을 실제로 수령해야 제작 안내 완료. 추가 수치 보상은 없다. 이후 간식→생활용품→음식→처음의 빵·생수 재현으로 이어지는 세부 내용은 `docs/콘텐츠/2막/교류로_발전하는_상품.md`에 있다. 아래 검증 수치는 첫 도입부 구현 당시 기록이며 최신 검증은 그 문서를 본다.

## 진행과 저장 호환

- 기존 `tutorial_step:<id>:intro/done` 구조를 유지하고 `barter`, `raw_sale` 단계만 추가했다. 핵심 단계 6개 + 선택 제작 1개다.
- `tutorial_event:arrival_v2`, `arrival_barter`, `raw_material_sale`은 기존 진행 저장 Dictionary에 기록한다. 새 저장 형식은 없다.
- 새 기본 배치는 1일차의 빈 매장, 기존 플레이어 저장/배치/튜토리얼 기록이 없는 경우만 적용한다. 이전 매장을 덮어쓰지 않는다.
- 이전판에서 제작 소개에 도달했거나 제작을 완료한 저장은 새 도입부를 반복하지 않는다. 진행 중 제작은 이어서 할 수 있다. 이전판의 더 이른 부분 진행은 완료한 기존 단계는 유지하고 새 교환·재료 판매로 이어진다.
- 소개/완료 대화는 끝까지 읽은 뒤에만 진행을 기록한다. 실제 결제·교환이 이미 성립했다면 거래 기록과 물품은 유지하여 다시 돈을 받거나 식품을 소비하지 않는다.
- 제작 완료를 주민 부탁의 공통 선행에서 제거했다. 재료 판매가 끝나면 주민·마을 콘텐츠가 열린다. 선택 제작을 기다려도 이 콘텐츠는 잠기지 않는다.
- 후속 타블렌 소개는 기존 교환 기록이 있으면 재방문 대사를 사용한다. 주민 부탁 완료 수에 따른 후속 손님 해금과 정착 조건은 그대로다.

## 글과 Gemini 인수인계

정식 인물 이름표·말투 파일은 그대로 사용한다. 이 장면의 화자는 `content_voices.csv`에 기록하며 플레이어 독백이 이전 델빈 말투를 덮어쓴다. 세계관에는 이번 사용자 결정을 추가했다. API는 호출하지 않았다.

`requests_text.csv` 변경: 기존 튜토리얼 5단계·첫 구매 3장면 수정, 새 교환/재료 판매 2단계·재료 재구매 3장면·타블렌 재방문 1장면 추가. 전체 215행. 종류를 새로 만들지 않고 `tutorial_step`, `tutorial_dialogue`, `service_text`를 사용한다.

글 도구는 7개 단계의 `npc/stage`를 읽어 화자·시점·실제 행동을 전달한다. 첫 구매/재료 구매의 차이와 타블렌 재방문도 별도 맥락으로 전달한다.

장면별 생성 명령:

```bat
dev\gemini\run_request_text.bat draft tutorial_step --ids setup,stock,checkout,barter,expedition,raw_sale,production
dev\gemini\run_request_text.bat draft tutorial_dialogue --ids checkout_intro,checkout_checkout,checkout_finished,raw_checkout_intro,raw_checkout_checkout,raw_checkout_finished
dev\gemini\run_request_text.bat draft service_text --ids arrival_peddler_return
```

`summary`의 조작 UI 안내는 유지한다. 등장인물의 대사에 키·메뉴·매출 통계를 넣지 않는다. 첫 지급을 현대 식품으로 바꾸거나, 실제 교환을 무료 선물로 바꾸거나, 제작을 다시 극초반 필수 목표로 쓰지 않는다. 수량은 설정/교환창이 보여 주므로 대사에 넣지 않는다. 초안과 게임 CSV 반영은 별도다.
