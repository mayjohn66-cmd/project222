# 콘텐츠 다듬기 1차 — 초기 부탁과 일회 도움

2026-10-05 · 사용자가 콘텐츠 추가 이후 다듬기로 전환하도록 요청했다. 중간점검의 초반 재고/제작 해금/반복 지원 문제부터 수정했다. 새로운 부탁이나 후반 이야기를 늘리지 않았다.

## 1. 초반 요구 물품

| 기존 ID 유지 | 이전 | 현재 |
|---|---|---|
| neighbor_bread — 오렐의 첫 부탁 | 빵2 | 야생 열매2 |
| traveler_water — 라슈의 다음 부탁 | 생수2 | 채집한 물2 |
| naru_provisions — 타블렌의 여행 식량 | 빵3 | 야생 열매3 |
| doyun_water — 코르빈의 작업용 물 | 생수3 | 채집한 물3 |
| naru_neighbor_basket — 타블렌의 이웃 간식 | 야생 열매3 + 빵2 | 야생 열매3 + 마른 가지2 |

열매와 채집한 물은 숲의 기존 원정 규칙에서 구할 수 있다. 마른 가지도 기존 숲 재료다. 채집한 물은 NPC가 받아 끓여 쓸 물로 설명한다. 물을 생수로 가공했다거나 새 조리 행동을 완료했다고 간주하지 않는다.

첫 장사/교환용 빵과 물은 기존 시작 식품 그대로다. 현대 빵/생수의 제작은 기존 제품 성장 4단계 해금을 유지한다. 시작 상품을 모두 팔았거나 빵의 기한이 지난 뒤에도 초기 부탁은 현지 재료로 준비할 수 있다. 준비가 부족하면 재료나 돈을 소비하지 않고 다시 원정을 갈 수 있다.

보상·필요 수량·안부/선행 날짜·손님 해금 임계치는 그대로다. 첫 기본 부탁2개는 여전히 타블렌 손님을 해금하고, 개인 부탁은 기본 부탁 완료 수를 올리지 않는다. 표의 품목만 변경했다.

## 2. 나눔과 답례 표시

위5개 항목에 `payment_kind: gift`를 명시했다. 주민 목표 패널과 개인 부탁 게시판에 **나눔 부탁 · 물품 대금은 별도로 받지 않습니다 / 답례: 평판·소액 현금**을 보여 준다. 상품을 판매하는 주문과 혼동하지 않도록 기존 금액이 사례라는 사실을 표시한다.

다른 부탁·주문의 지급 금액과 표시는 이번에 일괄 변경하지 않았다. 후속 상품 주문의 가격 합계/사례금과 전체 경제 검토는 기존 인수인계21번에 남아 있다.

## 3. 기존 NPC 도움4개

`data/story/story_beats.csv`는 실제 `StoryDirector`가 사용하는 파일이다. 삭제하지 않고 기존4개 ID와 등장 조건을 유지했다. `repeat_days`는 모두0(저장당1회)으로 바꿨다.

| ID | 이전 도움 | 현재 도움 |
|---|---|---|
| welcome_oven | 화덕1 지급 | 선물 없이 타블렌에게 현지 제작 도구를 물어보라는 힌트 |
| help_no_stock | 빵4·생수4, 3일마다 | 야생 열매3, 한 번 |
| help_no_ore | 철광석8·수정2, 4일마다 | 광산 철광맥 안내(대사만, 선물 없음), 한 번 — 2026-10-06 경제 검토 반영 |
| help_broke | 500G, 5일마다 | 마른 가지2·야생 열매2, 한 번 |

금전/광석/현대 식품/제작 설비를 반복 제공하지 않는다. 수리비나 수리 재료가 바로 생기는 지원도 아니다. 도움이 필요한 상황에서 소량의 현지 재료를 받아 장사를 이어 가는 관계는 남겼다. 지급 시점은 기존 StoryDirector 방식(대화 시작 때 기록/지급)이며 이번에 대화 완독 방식으로 바꾸지는 않았다.

기본 튜토리얼·주민/정착 안내 중에는 이 도움 NPC가 차단되는 기존 규칙을 유지한다. 첫 부탁의 진행을 이 무료 지원에 의존시키지 않았다. 같은 도움을 이미 받은 저장은 기존 ID 기록 때문에 새 선물을 다시 받지 않는다.

## 4. 기존 저장

부탁 ID, 수락·완료 날짜, 평판·손님 해금·주민 기억 키를 유지하고 저장 형식을 바꾸지 않았다. 새 게임을 시작할 필요는 없다.

**이미 맡았지만 전달하지 않은 위5개 부탁도 새 요구 품목으로 표시된다.** 부탁을 받을 때 물품을 소비하지 않으므로 이전에 준비한 빵/물은 가져가지 않고 소유한 곳에 남는다. 해당 부탁은 기존 수락 기록으로 이어서 전달한다. 완료한 부탁은 다시 열리지 않고 기존 보상을 중복 지급하지 않는다. 기존 수첩에 표시하는 이5개 부탁의 제목/완료 문구는 현재 CSV 문구로 갱신된다.

NPC 지원도 이전 기록을 지우지 않는다. 이전판에서 받은 지원은 마지막 지급 날짜가 오래됐더라도 `repeat_days=0`으로 다시 지급하지 않는다.

## 5. 대사 보강

운영 `requests_text.csv`의 기존5행만 품목·사정·행동 안내에 맞춰 수정했다. 별도 `content_voices.csv`의 타블렌/코르빈3행도 현지 재료와 소액 답례로 맥락을 맞췄다. 고유 이름·정식 `character_names.md`/`character_voices.csv`는 변경하지 않았다. Gemini API는 호출하지 않았다.

기존 원본 설정에 등록되어 있으므로 새로운 kind/id 등록은 없다. 아래는 사용자가 글 보강을 요청할 때의 명령이다. 수량·금액·평판은 UI, 창고/주민 또는 게시판 전달 안내는 기존 글 검사 규칙에 따른다.

```bat
dev\gemini\run_request_text.bat draft resident_request --ids neighbor_bread,traveler_water
dev\gemini\run_request_text.bat draft personal_request --ids naru_provisions,doyun_water,naru_neighbor_basket
```

`story_beats.csv`의4개 지원 대사도 현지 재료/한 번 도움에 맞춰 짧게 수정했다. 구형 스토리 형식의 글이므로 위 부탁 CSV의 같은 kind에 섞지 않는다.

## 6. 실행 검증

Godot4.7.1 import2회 종료0. 새 `check_early_content_polish`64건 실패0: 새 게임에서 시작 식품을 없애고 현대 제조법이 잠긴 상황, 실제 주민 E로 수락/전달, 재료 부족 시 무소비, 정확한 소비/답례, 두 부탁 뒤 타블렌 해금, 개인 부탁의 창고 전달, 기존 수락/완료 저장 왕복, 중복 지급 방지, 실제 StoryDirector의 일회 재료 도움과 100일 뒤 저장 복원 비반복을 검사했다.

기존 주민 부탁/개인 부탁/글 도구/글 런타임/단계별 튜토리얼85/마석 수리38/제품 성장123/식품117/main통합88 검사도 통과했다. 전체 스크립트·씬649개 로드 실패0. 대사401행 오류0·주의0. `validate_story.py`의 구형4장면도 오류0·주의0으로 기존500G 경제 주의가 해소됐다. 중간 검사에서 발견한 전달 안내 누락/반복 표현과 기존 검사의 빵 고정 입력을 수정한 뒤 해당 검사를 다시 통과시켰다.

`balance_baseline.py` 종료0, 평균 객단가276/충분 재고 가정 하루매출약7,448 기준선은 동일하다. 이 도구는 부탁·무료 지원을 직접 모델링하지 않으므로 아래 기회비용을 별도로 기록했다(상품 가격을 바꿨다는 뜻이 아님).

- 첫 주민 부탁: 빵2의 판매가300→열매2의40, 생수2의200→채집한 물2의40. 답례는각30G 그대로.
- 초기 개인 부탁: 빵3의450→열매3의60, 생수3의300→채집한 물3의60. 답례는각30G 그대로.
- 이웃 간식: 열매3+빵2의360→열매3+가지2의100. 답례30G 그대로.
- 새 일회 지원 재료의 판매가 합계는180G(열매3=60/약초2=40/가지2+열매2=80), 현금은0G. 실제로 받아 모두 판매해야 실현되는 값이다.

위 검사는 재료 준비 상황을 설정해 실제 전달 경로를 확인한다. 초반 원정을 손으로 플레이한 사용자의 이해도·채집 체감·장기 경제를 대신하지 않는다. 기존 아이콘/건축 경고와 환경 인증서 메시지는 남아 있으며 이번에 이미지나 원정 동작을 변경하지 않았다.
