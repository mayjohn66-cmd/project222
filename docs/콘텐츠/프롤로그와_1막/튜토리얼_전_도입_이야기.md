# 튜토리얼 전 도입 이야기

2026-10-05 · main 콘텐츠 추가

플레이어와 편의점이 함께 이세계에 떨어진 직후, 조작 안내보다 먼저 플레이어의 혼란과 작은 결심을 보여 준다. 새 게임에서 세 장면의 짧은 독백을 마치면 기존 가게 확인·진열·현지인의 첫 구매로 이어진다.

## 세 장면

| 순서 | 장면 | 플레이어가 알아내는 것 |
|---|---|---|
| 1 | 평소와 다른 적막 | 가게 일을 하던 익숙한 일상이 떠오르지만 도로 소리가 사라졌다. |
| 2 | 유리문 너머의 풀 | 바깥 풍경이 달라졌고 계산대의 흠집·진열대·창고 식품은 그대로다. 가게 전체가 옮겨 온 것 같다고 추측한다. |
| 3 | 내가 아는 일부터 | 낯선 곳으로 무작정 나서기 전에 익숙한 가게부터 정리하기로 결정한다. |

첫 장면 예시:

> 진열대 끝을 맞추고 나면 유리문 밖을 보곤 했다.
> 차가 지나가고 누군가 횡단보도를 건너던 자리.
> 방금 전까지만 해도 분명 그랬는데.
> …왜 이렇게 조용하지?

현실의 일상은 짧은 기억으로 표현한다. 화면에는 현재의 가게와 이세계 풍경이 보인다. 현실 지도·전이 영상·효과음을 새로 추가하지 않았다. 전이가 일어난 이유나 신·마법사·사고·플레이어 이름은 확정하지 않는다. 장면 당시 플레이어는 현지 화폐나 상인, 검과 갑옷, 원정 및 제조법을 아직 알지 못한다.

## 튜토리얼과 연결

도입 독백 → 함께 온 가게 확인 → 남아 있던 식품 진열 → 델빈이 실제 첫 손님으로 구매 → 낯선 동전 → 타블렌과 식품/장비 물물교환 → 첫 원정 → 원재료 판매의 기존 흐름을 유지한다.

기존 `setup` 독백도 도입부와 중복되지 않게 집기 상태를 살피는 문장으로 다듬었다. 플레이어가 가게를 먼저 이해하고 현지인은 자기 필요에 따라 물품을 산다. 현지인이 현대 계산대 조작이나 게임 수치를 가르치는 장면은 없다.

대사 동안 튜토리얼 목표 패널을 숨기고 기존 대화창을 사용한다. [E] 또는 클릭으로 읽으며 이동·가게 시간을 멈춘다. 기존 정지 상태는 종료 시 그대로 복원한다. 소개 장면을 읽는 행동으로 진열·개점·구매를 자동 완료하지 않는다. 추가 돈·물품·평판·배치 변경도 없다.

## 저장과 기존 게임

- 실제 새 게임의 기존 집기 초기화 때만 `tutorial_event:opening_prologue_v1`을 등록한다. 저장 구조·버전을 바꾸지 않는다.
- 장면 완독 때 `opening_prologue:<장면ID>`를 기록한다. 읽다 만 장면은 완료 처리하지 않으며 다음에 같은 장면부터 이어진다.
- 중간 저장 후 다시 불러오면 이미 읽은 장면을 반복하지 않는다. 새 게임은 기록을 초기화한다.
- 표식 없는 이전 저장 파일과 이미 튜토리얼을 진행한 저장은 도입부를 강제 재생하지 않는다. 기존 저장에 새 돈/식품/배치를 지급하지 않는다.
- 확인할 때는 main을 업데이트한 뒤 **새 게임**으로 시작한다. 실제 사용자 저장 파일은 변경하지 않았다.

## Gemini 보강

추가 3장면은 기존 `service_text`다. 전체 대사 CSV는 **292행**이며 퀘스트 개수를 뜻하지 않는다. `default_opening_prologue.tres`의 `moments`를 글 원본에 등록하고 `content_voices.csv`에 화자·시점·아직 모르는 정보를 남겼다. 기존 정식 이름/말투 기준과 세계관 고유 설정은 그대로 둔다. API 호출은 하지 않았다.

```bat
dev\gemini\run_request_text.bat draft service_text --ids prologue_last_shift,prologue_unfamiliar_window,prologue_keep_the_light
```

제미나이는 전이 원인을 새로 확정하기보다 각 장면의 혼란·관찰·결심을 다듬는다. 첫 장면의 익숙한 도로는 과거 기억이고, 현재 화면에 도로가 그대로 있다는 뜻으로 쓰지 않는다. 새 인물·선물·마법 지식·실제 구현되지 않은 사건 영상을 약속하지 않는다.

## 자연스러운 진행 점검 10: 저장과 중간 재개 (2026-10-10)

구현·푸시: `main @ a3b570a`. 저장·불러오기 뒤 실제 화면을 다시 열어 도입/튜토리얼·부탁·원정 진행을 확인했다.

- 저장 목록이 요일/보유금만 보여 주던 부분을 `SaveSlotSummary`로 보강했다. **파일에 들어 있는** 게임 계절·날짜, 점장 이름, 보유금, 가게 06시 정비/원정 체크포인트, 파일 저장 일시를 표시한다. 현재 플레이 상태를 파일 미리보기에 섞거나 불러오지 않는다. `total_day`/이름이 없는 이전 저장은 기존 날짜 복원 기준과 기본 호칭을 사용한다.
- 시작 화면과 공통 저장 메뉴에 같은 표시를 연결했다. 사용 불가 파일은 불러오기에서 선택하지 못하며, 저장 화면에서는 기존 덮어쓰기 확인을 거쳐 교체할 수 있음을 표시한다. `SaveSlotSummary.ENABLED`를 끄면 기존 슬롯 표시로 돌아간다.
- 기존 검사가 `progress` 루트 형식을 확인하지 않아 사전이 아닌 진행 기록도 통과할 수 있었다. `SaveProgressGuard`에서 이 경우를 적용 전에 거부하도록 하고 `GameState.is_save_data_valid`에 호출 한 줄을 연결했다. 필드가 없는 이전 저장과 정상 사전 형식은 허용한다. 이 보강은 진행 기록 루트 형식 검사이며 모든 손상 유형을 새로 검증했다는 뜻은 아니다.
- UI 문구 5행만 추가했다. 슬롯 2개/자동 저장, 저장 버전·필드, 기존 저장 가능 시점, 내용 조건·보상·가격·식품 기한·대사 ID·이미지는 바꾸지 않았다.

### 실제 확인한 범위

- `check_save_resume` 신규39개 헤드리스 및 GPU 1152×648·593×523 각각 실패0. 실제 메뉴 클릭 → 슬롯 기록 → 덮어쓰기 취소/파일 바이트 유지 → 시작 화면 복귀 → 이어하기/슬롯 클릭 → 실제 씬 교체로 검사했다. 정상·손상 저장 목록과 닫기 버튼을 두 화면 크기로 캡처해 확인했다.
- 튜토리얼 `setup` 소개를 이미 읽은 저장에서 청소·프롤로그를 다시 시작하지 않고 가게 06시의 멈춘 정비 상태로 이어진다. 이름/선택 외형·날짜·돈·식품 수량 복원을 확인하고 새 시작 식품을 중복 지급하지 않는지 비교했다.
- 수락한 주민 부탁과 준비 물품을 실제 체크포인트 파일에 저장한 뒤 장면을 다시 만들었다. NPC E로 전달 → 대화 E로 완독 → 정확한 기존 보상 → 완료 후 다시 저장/불러오기까지 확인했으며, 반복 전달/다시 불러오기로 보상이 중복되지 않았다.
- `progress`·누적 날짜·보존·직원 기록·원정 필드가 없는 이전 저장 준비값은 기존 검사를 통과하고 날짜/호칭 기본값을 유지한다. 진행 기록을 문자열로 바꾼 파일은 슬롯 읽기 때 거부되고 현재 플레이 상태를 바꾸지 않는다.
- 원정 준비 저장을 실제 시작 화면에서 불러와 PREP로 돌아가는 것을 확인했다. 실제 출발 후 안전한 경로 선택 화면에서 RUN 체크포인트를 저장하고 다시 불러와 지도/현재 노드·저장된 계절/날씨·가방·HP가 동일하고 전투가 재생되지 않는 것을 비교했다. 이번 원정 가방은 빈 준비값이며, 전리품을 가진 중간 전투 전체 재현을 새로 추가한 검사는 아니다.
