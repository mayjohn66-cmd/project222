# 매장 인물 그림 연결과 여백 보정 (2026-10-08)

## 요청과 적용 범위

사용자가 업로드된 초상화·걷기 그림을 확인한 뒤 재조정을 요청했다. 이번 적용은 매장 직원 3명과 손님 대분류 8개의 제공된 8방향 정지/걷기 그림을 실제 매장 3D 표시 층에 연결하는 작업이다.

- 배경·칸·이동·충돌·계산·고용·저장 규칙은 기존 코드가 맡는다.
- 초상화·대사와 원정 인물 렌더러는 이번에 변경하지 않았다.
- 주인공과 이름 있는 NPC는 이번 묶음에 전용 그림이 없으므로 기존 모델을 사용한다. 별도 시험용 player_chibi를 남녀 선택형 주인공 대신 자동 적용하지 않았다.
- 앉는 연출과 제공 그림이 없는 인물, 현대 도시의 명시적 복장(look_key 메타)은 기존 모델을 사용한다.
- StoreView3D.use_pixel_actors 기본 true. false로 설정하면 기존 인물 렌더러로 복귀한다.

## 제공 파일과 실행 경로

원본: docs/그림_작업/받은그림/캐릭터_등각/.
실행용: art/actors/<키>/rotations/, art/actors/<키>/animations/walk/<방향>/.

docs 및 그림_작업의 .gdignore 때문에 원본 경로는 Godot에서 가져오지 않는다. 원본 정지 88장과 걷기 704장(총 792 PNG)을 새 실행용 경로로 복사했다. 이미지 생성·픽셀 수정·기존 이미지 덮어쓰기는 없다. 792개 전부 원본과 SHA-256 일치. 실행용 정지 파일의 대각 방향 이름만 south_east.png처럼 밑줄로 표기하여 에셋 검증기 파일명 규칙을 따른다. 원본 이름과 걷기 방향 폴더는 유지한다.

직원: worker_001/002/003 (employee_id).
손님: normal/traveler/adventurer/miner/herbalist/child/collector/marsh_local (소분류와 4막 source를 대분류로 해석). 새 타입별 능력/수요/저장 필드는 없다.

## 보정과 표시

- 정지는 64×64, 걷기는 방향에 따라 84/88/92px. 걷기 캔버스의 가운데 여백을 빼고 정지 그림의 발 중앙에 대응시킨다.
- 발 기준은 방향별 정지 그림의 하단 불투명 픽셀에서 얻고, 걷기 중 같은 기준을 쓴다. 한 묶음 전체의 최대 높이에 따른 배율을 고정한다. 프레임별 내용 경계는 UV와 표시 판을 자를 때만 쓴다.
- 기존 30도 카메라의 화면상 키에 맞춰 인물 높이를 정한다. child 계열의 기존 total 값을 유지한다.
- world X/Z 이동 방향을 카메라 yaw 기준 화면 8방향으로 변환한다. +X는 화면 오른쪽 아래, +Z는 왼쪽 아래다.
- 걷기 위상은 이동 속도와 주기당 거리(0.8칸)로 갱신한다. 정지하면 정지 그림으로 돌아간다.
- 제공된 등각 그림을 다시 기울이지 않고 카메라를 향하는 판에 최근접 필터로 그린다.
- 투명 여백은 색/번호 판에서 같은 UV와 알파 기준으로 버린다. 기존 정렬 순번으로 가구 앞뒤 가림을 적용한다.
- 그림 내부 음영을 보존하고 기존 환경광 색, 계절·밤 색감과 가까운 매장 조명을 별도 색조로 반영한다.
- 숨김·퇴장 시 그림과 번호 판을 함께 숨기거나 해제한다.

새 코드: actor_sprite_frames.gd, pixel_actor_figure.gd, store_actor_visuals.gd, actor_sprite(.gdshader)/actor_sprite_id(.gdshader).
기존 store_view_3d.gd에는 선택·생성·색조 호출만 연결했다.

## 검증

Godot 4.7.1, 사용자 실제 저장을 불러오지 않은 새 게임 검사.

- 최종 import 2회: 두 번째 SCRIPT/파싱 오류 없음.
- 전체 gd/tscn 로드 741개: 실패 0, 오류 로그 없음.
- check_pixel_actors: 최종 헤드리스 1,255개 실패 0.
- 화면 렌더링: 1,253개 실패 0, 색/번호 셰이더 및 런타임 오류 없음. 이후 현대인 메타 우선·손님 소분류 대응 2개를 추가하여 헤드리스 1,255개로 재검사했다.
- 실제 매장 화면의 정지, 걷기 0/2/4/6, 낮/밤, 계산대 뒤·앞 표시를 캡처해 확인했다.
- check_main_content_integration: 최종 88개 실패 0.
- validate_assets.py: FAIL 0, 누락 아이콘 0. 기존 WARN 28 및 LEGACY 42 유지. 새 art/actors는 일반 검사 unclassified로 분류되며, 방향/프레임 완전성·여백/표시 배율은 별도 검사에서 확인했다.
- 생성된 기존 .import/.translation 변경은 되돌리고 커밋에서 제외했다.

이전부터 ItemData의 낚시 아이콘 경고와 BuildObjectData 빈 행 경고가 실행 로그에 있으며 이번 변경으로 새로 추가된 경고가 아니다. 원정/마을 NPC 전용 걷기와 전체 NPC 표정 후보 반영은 이번 적용에 포함되지 않는다.

## Claude에게 전달

현재 매장은 제공된 직원·손님에서만 스프라이트 판을 사용하고, 그림이 없는 인물·앉는 연출에는 기존 상자 모델을 사용한다. 기존 3D 규격서의 상자 인물 규정과 실제 제공 그림 연결이 함께 설명되도록 문서 갱신을 검토한다. 이후 사용자 요청으로 그림을 만들 때 각 방향의 발 위치, 64px 원래 격자/가운데 걷기 여백과 머리·모자·의상을 유지하면 연결할 수 있다. 이번 전달은 추가 이미지 생성 요청이 아니다.
