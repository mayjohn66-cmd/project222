## 2. 발견한 오류와 수정

### 재료가 늘어나면 저장을 불러오지 못함

첫 검사에서 실제 원정 5회를 다녀온 뒤 일반 소지품이 12칸을 넘겼다. 저장 원본인 수량 사전은 정상이었지만, `GameState.rebuild_inventory_slots_from_counts()`가 옛 호환 표시를 12칸으로만 재구성하면서 실패했다. 불러오기 중 일부 상태를 적용한 뒤 실패하는 문제였다.

`InventoryCountSlots.build()`를 별도 파일로 추가했다. 실제 수량을 99개씩 나누어 모두 표현하고 빈 상태는 기존 최소 12칸을 유지한다. `game_state.gd`는 이 함수 호출로 연결했다. 일반 소지품 UI는 이미 동적 수량 사전을 사용하므로, 이번 변경은 수량을 잃지 않는 호환 표시를 만드는 수정이다. 원정 가방의 칸·무게·배치 제한과 저장 필드는 그대로다.

수정 뒤 실제 15종 재료가 남은 저장이 다시 적용되고 시작 화면에서도 복원된다. 별도 순수 함수 검사로 빈 사전의 12칸과 205개를 99/99/7로 나누는 경우도 확인했다. 이 205개는 플레이 진행에 지급하지 않았다.

### 문 밖으로 퇴장 중인 손님에게 내부 길찾기를 다시 요청함

상인이 가게 밖 보도로 이동 중일 때 문 닫기·원정 출발의 퇴장 요청이 겹쳤다. 내부 10×8 격자에 없는 `(-1, 4)`에서 AStar 경로를 요청해 오류가 났다.

`customer.gd`에서 퇴장 연출 중이거나 삭제 대기 중인 손님은 추가 퇴장 요청을 무시한다. 내부 길찾기 함수도 시작점이 가게 밖이면 빈 경로를 반환한다. 기존 미결제 상품 반환·방문 기록·보도 퇴장 연출은 유지한다.

## 4. 자동화와 실제 조작의 경계

- 사용자 저장과 분리한 프로젝트를 사용했다. `config/use_custom_user_dir=true`, 이름은 `project222_foodbag_checks_newgame_20261010`이다. 일반 사용자 경로에서는 신규 검사 실행을 거부한다.
- 검사 시작 시 자동 저장·슬롯 1·슬롯 2의 기존 바이트를 보관하고 정상 종료 시 원상 복구한다. 없던 파일은 검사에서 만든 경우만 제거한다. 실제 사용자 저장은 열거나 바꾸지 않았다.
- 가게에서는 상호작용 근처로 플레이어 위치를 옮겼다. 배치는 실제 배치 가능 검사와 보유 집기 소비를 사용했다. **가게의 모든 보행 동선·출입 충돌을 수동 검증한 것은 아니다.**
- 가게 시간·손님 생성 타이머를 중간에 멈추고 행동을 순서대로 실행했다. 재방문은 기존 손님 생성 콜백과 실제 보도 이동으로 진행했고, 해당 이동 대기만 가속했다. 실제 영업 시간의 손님 빈도는 이번 범위가 아니다.
- 원정은 기존 `ExpeditionRoomTestDriver`의 충돌을 고려한 이동·기본 공격·채집·출구 경로를 사용했다. 접근 가능한 지도 분기 중 채집 방을 우선 선택했다. 적 HP나 보상은 검사에서 바꾸지 않았다.
- 전리품은 기존 드래그 배치 콜백으로 정리하고 가방에 들어가지 않는 나머지는 기존 확인창으로 버렸다. 모든 전리품을 보유한 결과가 아니다.
- UI는 버튼 신호·상호작용 함수·대화 넘김 콜백으로 조작했다. 화덕 완성 대기와 계산 진행은 해당 기능의 경과 시간 처리로 진행했다. OS 마우스·키보드의 전 구간 수동 조작 검사는 아니다.
- 프롤로그 대사는 읽었지만 영상은 `--no-cutscene`으로 건너뛰었다. 소리·연출 체감은 별도 확인이 필요하다.
- 112일 장기 진행, 사계절 전체, 동시 행사·후반 부탁, 모든 지역·무기 조합, 성능 장시간 측정은 포함하지 않았다.

## 5. 재실행

프로젝트와 같은 리소스를 연결한 **별도 격리 프로젝트**에서 실행한다. 실제 프로젝트의 사용자 저장 경로를 바꾸어 테스트하지 않는다. 개발 일괄 검사도 격리 프로젝트를 대상으로 실행해야 한다.

```text
godot --headless --path <격리 프로젝트> res://dev/scenes/check_new_game_continuity.tscn -- --no-cutscene --seed=8123 --report=<절대 경로>/campaign.json
godot --path <격리 프로젝트> --resolution 593x523 res://dev/scenes/check_new_game_continuity.tscn -- --no-cutscene --seed=8123 --snap=<절대 경로>/campaign
```

성공 출력은 `CHECK_NEW_GAME_CONTINUITY checks=132 failures=0 runs=5`다. 다른 seed는 원정 횟수에 따라 검사 수가 달라진다. 결과 JSON에는 구간별 실제 돈·물품·공간 단계를 남긴다. `--snap`은 실제 화면 실행에서만 사용하며 생산 창·생산실·창고·재개 화면을 저장한다.

이 세션의 원본 실행 로그·결과 JSON·스크린샷은 작업 공간 `clade/output/campaign-*`에 남겼다. 저장소에 실행 부산물이나 받은 그림 변경은 포함하지 않았다.
