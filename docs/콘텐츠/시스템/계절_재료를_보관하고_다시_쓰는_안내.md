# 계절 재료를 보관하고 다시 쓰는 안내

2026-10-08 콘텐츠 보강. 기존 냉장함·냉동함에서 보존과 출고의 다음 행동을 안내한다.

## 플레이 흐름

1. 원정의 새순·물박하·서리 얼음이나 식품·생선을 얻는다.
2. 가게에 배치한 냉장함 또는 냉동함에 다가가 E로 기존 보관 창을 연다.
3. 물품의 소지·보관량과 상온 변형 시점을 살핀 뒤 필요한 만큼 넣는다.
4. 맡은 보존 체험은 소개를 들은 뒤 입고하고, 다음 날 이후 시료를 꺼낸다.
5. 보존 체험 안내에 표시되는 실제 주민에게 E로 직접 전달한다. 일반 상품은 꺼내서 사용하거나 진열한다.

안내만 읽어도 체험·부탁을 완료하거나 보상을 받지는 않는다. 입출고·실습 기록·전달·보상은 기존 시스템이 처리한다.

## 목록 공개

- 현재 소지하거나 냉장·냉동함에 넣어 둔 물품을 표시한다.
- 배운 제조법의 완성품과 이미 잡아 본 생선은 재고가 없어도 표시한다.
- 기존 보존 체험의 발견 기록이 있는 원재료도 표시한다.
- 이전 저장의 물품은 발견 기록 없이도 실제 소지·보관량이 있으면 표시한다.
- 알아본 적도 없고 소지·보관하지도 않은 미래 생선·상품·계절 재료는 목록에서 숨긴다.
- 공개 여부는 기존 기록으로 계산한다. 새 도감·발견 저장 필드는 없다. 별도 기록이 없는 일반 식품은 모두 소진하면 다시 숨겨질 수 있다.
- 설비가 원래 받지 않는 물품은 입출고 목록에 넣지 않는다. 냉장함을 보는 중 알고 있는 서리 얼음은 냉동함이 필요하다고 안내한다.
- 표기상의 ‘창고’를 실제 전송 재고인 ‘소지’로 바로잡았다. 물리적인 창고 선반 재고와 합산하지 않는다.

## 재료·식품 안내

| 대상 | 보강한 안내 |
|---|---|
| 봄 새순·여름 물박하 | 수확 계절이 지난 아침에 실제 변형 결과를 표시. 계절 마지막 날이나 계절 밖에는 다음 아침이라고 안내 |
| 서리 얼음 | 상온에서는 다음 아침에 채집한 물로 변함. 냉동함에 보관한 양은 별도로 표시 |
| 보관 중인 계절 재료 | 이 설비에 있는 재료가 보존 중임을 표시. 소지 재료까지 보존한다고 표시하지 않음 |
| 배운 보존 가공 | 기존 제조법의 실제 설비와 말린 완성품을 표시. 자동 가공·수령이나 새 제조법 학습 없음 |
| 식품 | 실제 배치 중 가장 먼저 기한이 끝나는 재고의 남은 기한을 소지/보관 각각 표시 |
| 냉장 식품 | 상온보다 천천히 줄어드는 기존 설정과 남은 기한을 안내 |
| 냉동 식품 | 기한 진행이 멈추는 기존 설정과 남은 기한을 안내 |
| 열매 주스·약초 음료 | 기존 냉동 불가 조건을 표시. 냉동함 목록에는 나타나지 않음 |

식품 기한의 숫자는 기존 `FoodShelfLife.days_left()`가 계산하는 **상온 환산 일수**다. 보관품은 ‘출고 뒤 상온 기준’으로 명시해 냉장 상태의 남은 달력 일수로 오해하지 않도록 했다. 입고·출고로 기한을 새로 채우지 않는다.

새순을 꺼낼 때 얼음을 사용하라는 잘못된 안내도 실제 재료 변형 안내로 바꿨다. 모든 부탁을 게시판으로 가져가라는 기존 일반 문장은 이웃 또는 게시판의 해당 안내를 따르도록 고쳤다.

## 보존 체험의 다음 행동

기존 세 보존 체험에서 수락했고 완료하지 않은 원재료에만 표시한다.

| 실제 상태 | 다음 행동 |
|---|---|
| 소개 완독, 입고 전 | 소개 뒤 넣고 다음 날 이후 꺼낸 시료를 해당 주민에게 전달 |
| 오늘 입고 | 다음 날 이후 꺼내기 |
| 이전 날 입고, 보관 중 | 전달할 날 필요한 만큼 꺼내기 |
| 실제 실습 기록과 소지 시료 준비 | 해당 주민에게 직접 전달 [E] |
| 실습 기록은 있으나 소지 시료 없음 | 전달할 시료를 소지품에 준비 |

같은 날 넣었다 꺼낸 것, 보관품 자체, 안내 조회는 하룻밤 실습을 만들어 내지 않는다. 기존 말리기 실습으로 시료가 준비된 경우도 기존 `ready_path()` 결과를 따른다. 신규 이야기·대사 ID·답례는 없다.

## 화면·연결

- 기존 보관 창의 각 물품 행 아래 짧은 안내를 붙인다. 긴 목록은 기존 스크롤을 사용하고 돌아가기 버튼은 바깥에 남긴다.
- 창을 연 동안 실제 날짜·재고·기한·관련 기록이 바뀌면 표시를 갱신한다. 다른 일상 대화만으로 입출고 버튼을 다시 만들지는 않는다.
- 갱신 때 스크롤 위치를 이어 가고, 마우스를 누른 동안 자동 재작성을 미룬다.
- 가구 현장/관리 메뉴의 기존 시간 정지·소유권 정책은 유지한다.
- 조회는 기존 보존·유통기한 정산과 이전 저장 배치 보완을 수행할 수 있다. 기한이 지난 물품을 사용 가능 재고로 계속 표시하지 않는다.
- `preservation_guide.gd`: 기존 데이터·재고·실습 기록 기반 안내.
- `preservation_guide_view.gd`: 열린 창의 갱신.
- `preservation_panel.gd`: 목록 필터·안내·갱신 연결. 대형 시스템 파일은 수정하지 않았다.
- 복귀: `PreservationGuide.ENABLED = false` 뒤 재실행하면 새 필터·물품별 안내·자동 갱신을 끈다. 소지 표기와 잘못된 일반 전달 문장의 수정은 남는다.

용량·가격·입출고 수량·변형 규칙·식품 기한·보상·계절·CSV·저장 형식·원정·이미지는 변경하지 않았다.

## 검증

독립 새 게임 `res://dev/scenes/check_preservation_guide.tscn`에서 실제 가구 E, 마우스 넣기/꺼내기, 같은 날과 다음 날 실습, 계절 경계의 상온 변형/보존, 기존 저장 데이터 메모리 복원, 식품 기한 유지, 생선 발견/이전 보관 재고, 작은 창의 목록·돌아가기를 확인했다. 사용자 저장 슬롯을 읽거나 쓰지 않았다.
