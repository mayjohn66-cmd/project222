## 3. 생산 탭: 무엇을 준비할지 결정하는 화면

### 3.1 화면 구성 제안

탭 이름을 **상품 준비**로 바꾸는 안을 제안한다. 이름은 미확정이다.

| 화면 | 보여 줄 정보 | 플레이어가 할 결정 |
|---|---|---|
| 오늘의 준비(기본 화면) | 배운 상품 중 만들 수 있는 것, 부족한 재료, 실제로 들은 매장 행사 소문·맡은 부탁과 연결되는 상품 | 지금 준비할 상품 선택 |
| 배운 상품 | 제조법, 재료와 부족분, 필요한 설비, 실제 산출량, 기존 이야기와 연결되는 배움의 출처 | 다음 준비 목표 확인 |
| 설비 현황 | 실제 설치 여부·위치·작동 상태·수령할 완료품 | 현장에 가서 사용할 설비 확인 |

- 아직 배우지 않은 상품과 미래 시설을 전체 목록으로 미리 공개하지 않는다.
- 행사 준비는 이미 들은 소문과 현재 기록에서 힌트를 준다. 정확한 미래 판매량·수익·날짜를 예언하는 문구를 쓰지 않는다.
- 계절 재료의 보관·가공 안내는 이미 배운 보존 방법과 실제 보관 상태를 사용한다.
- 일반 소지 재고와 창고 선반의 물품은 실제 이용 규칙대로 구분한다. 선반에 둔 재료를 원격으로 사용할 수 있다고 표시하지 않는다.
- **실제 생산 시작과 완료품 수령은 현장 설비 상호작용을 유지한다.** 책의 재구성으로 원격 제작·수령·자동 대기열 기능을 추가하지 않는다.

### 3.2 설비 설명 보강

화덕에서 처리하는 모든 상품에 같은 「반죽 → 굽기 → 완성」을 붙이면 실제 제조법과 어긋날 수 있다. 상품별 실제 재료·결과·사용 설비를 설명하고, 구현하지 않은 조작 과정이나 미니게임을 약속하지 않는다.

초반 원재료 판매 → 현지인의 제조법을 배운 상품 → 교류로 늘어나는 상품 → 처음 가져온 편의점 상품 재현의 기존 발전 방향을 유지한다. 제조가 시작부터 모든 매출의 필수 조건이 되어서는 안 된다. 새 기계 종류는 기존 설비로 표현하기 어려운 실제 제작 경험이 생길 때 검토한다.

## 4. 직원 탭: 만남부터 함께 일하기까지

### 4.1 공개 순서 제안

1. **핵심 거래 튜토리얼 중:** 직원 탭 숨김(구현됨).
2. **튜토리얼 이후 첫 만남:** 기존 직원 중 한 명이 지원자로 방문한다. 기존 첫 소개 이야기를 사용하고 만남 기록을 저장한다. 타블렌이 소개하는 연출은 후보안이며 확정 설정이 아니다.
3. **고용 전:** 만난 지원자만 보여 준다. 성격·선호 시간대와 함께 고용비·급여·근무 조건을 계약 전에 반드시 확인한다. 「나중에」를 선택해도 다시 기회가 있다.
4. **첫 고용:** 근무표에서 한 근무 시간을 지정하고 실제 출근을 기다리는 안내를 한다. 고용 확정은 기존 오전 6시 준비 시간 규칙을 유지한다. 다른 시간의 만남은 다음 준비 시간에 계약하도록 안내할 수 있다.
5. **실제 첫 근무:** 실제 근무 기록을 바탕으로 직원 이야기·급여 정보를 보여 준다. 근무표 선택만으로 출근했다고 기록하지 않는다.
6. **교육:** 첫 근무를 경험한 뒤 별도 선택으로 소개한다. 다른 후보도 각자의 만남 이후 공개한다.

첫 만남·실제 근무 조건의 세부 배치는 후속 설계 검토 대상이다. 고용비·급여·채용 가능 시간 등 기존 경제 규칙을 새 이야기로 우회하지 않는다.

### 4.2 화면 구성 제안

- **함께 일하는 직원:** 고용 직원의 근무표·현재 업무·누적 급여·실제로 경험한 이야기. 해고는 해당 직원 상세에서 조건 확인 후 진행한다.
- **만난 지원자:** 한 줄 성격·현재 상태·선호 시간대. 선택한 상세에 능력과 계약 조건을 표시한다. 고용 화면과 정보 화면에 같은 긴 소개를 반복하지 않는다.
- **교육:** 조건을 충족한 고용 직원만 표시한다. 아직 대상이 없을 때 빈 탭과 긴 사용법을 먼저 노출하지 않는다.

현재 직원 이름은 **직원 1/2/3**을 유지한다. 새 이름·인물 관계·능력·급여 감면·선물·해고 평판 불이익은 정하지 않았다. 기존 18장면을 재사용하고, 만남과 실제 첫 출근을 서로 다른 기록으로 다룬다.

고용하지 않은 사람의 미지급 급여를 보여 주지 않는다. 반대로 계약 비용을 숨기거나, 빈 근무표이면 급여가 없는 것처럼 설명해서도 안 된다. 기존 누적 급여·교육·재고용·계절 말 정산 규칙을 보존한다.

## 5. 생산 설비·치장·건축의 성장 방향

### 5.1 공간별 용도

| 분류 | 설명에서 먼저 답할 내용 | 공개 기준 |
|---|---|---|
| 편의점 집기 | 어떤 상품을 진열하거나 거래하는가, 실제 크기·용량은 얼마인가 | 초반 이용 가능한 기존 종류 |
| 생산 설비 | 어떤 배운 상품에 사용하는가, 어디에 놓고 어떻게 이용하는가 | 제작 안내·생산실 마련과 실제 이용 단계 |
| 창고 집기 | 무엇을 얼마나 담는가, 어떻게 넣고 꺼내는가 | 창고 마련 단계 |
| 치장 | 어디에 배치하며 어떤 외형인가, 실제 효과가 있는가 | 현재 구현된 첫 상품 수령 이후 공개 순서 |
| 공간 확장 | 지금보다 얼마나 커지는가, 비용·가능 시간은 무엇인가 | 실제 창고 입고 경험 이후 |

용량·비용·효과는 현재 데이터에서 읽으며 설명에 임의 수치를 넣지 않는다. 일반 선반을 냉장·냉동 보존 설비처럼 설명하지 않는다. 외형용 치장에 매출·친밀도 효과가 있는 것처럼 쓰지 않는다.

### 5.2 후속 콘텐츠 보강 제안

- 기존 **나무 → 보강 나무 → 현대 편의점 집기**의 제작·제품 이야기 조건을 유지하며, 재료·외형·실제 용량 차이를 설명한다. 이미 추가된 집기 10종을 새 작업에서 추가할 종류로 다시 집계하지 않는다.
- 생산 설비는 배운 상품과 실제 이용 목적을 먼저 보강한다. 기능이 같은 기계를 이름만 달리해 늘리지 않는다.
- 치장은 기존 오브젝트의 배치 용도부터 정리한다. 주민과 만든 물건·행사 기억을 담은 치장 같은 후속 후보는 제공 조건·이미지·효과를 별도로 검토한 뒤 추가한다.
- 공간을 만든 직후에는 다음 행동 하나를 안내한다. 설비 설치·첫 생산·첫 입고를 배우기 전에 장기 확장 계획 전체를 설명하지 않는다.

## 6. 구현 시 지킬 조건

- 메뉴·설계도·가방·퀵슬롯·실제 제작·배치·출입의 조건을 함께 검사한다. 버튼만 숨긴 것으로 진행 제한이 완료된 것은 아니다.
- 미리보기·실패·수량 0·대화 중단을 실제 완료로 기록하지 않는다. 방문한 지원자·실제 근무·생산 수령 등 필요한 기록은 저장·재개 시 유지한다.
- 이미 공간을 사용하거나 직원을 고용한 이전 저장은 기능을 소급 잠그지 않는다. 소유 집기·제조법·교육·급여·재고를 초기화하지 않는다. 이전 고용 직원은 신규 만남 조건 때문에 사라지지 않아야 한다.
- 미래 정보는 숨기되 현재 계약의 비용·급여, 실행에 필요한 재료·조건은 확인 가능해야 한다.
- 새 시스템 코드는 작은 별도 파일로 추가한다. 실제 구현 때 관련 흐름의 회귀 검사와 화면 확인을 수행하고, 이 설계 문서의 제안을 구현 완료로 표시하지 않는다.

Gemini 초안은 기존 작성 가이드와 검수 경로를 따른다. 아직 구현하지 않은 자동 생산·원격 수령·새 보상·직원 능력을 대사에 약속하지 않는다.
