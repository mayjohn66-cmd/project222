# 집기를 고르는 사용 안내

2026-10-08 · 사용자 「다음 콘텐츠 보강」 승인에 따라 기존 집기의 설명과 활용을 관리 책에 연결했다. 이미 있는 28종과 발전 카탈로그 12종을 사용한다. 새 집기·이미지·제조법·가격을 추가하지 않는다.

## 무엇을 보고 고르는가

| 집기 | 먼저 보여 주는 요약 | 상세에서 설명하는 사용법 |
|---|---|---|
| 진열대 | 한 층 총 수량·칸 수·최대 층 | 칸마다 담을 수량, 설치 크기, 같은 종류 1개를 더 사용해 적층, 현재 준비 가능한 다른 진열대 |
| 창고 선반 | 총 보관량·보관 칸 | 창고에 설치하여 넣기·꺼내기, 일반 보관과 냉장·냉동의 차이 |
| 냉장·냉동함 | 동종 설비가 공유하는 총용량 | 현장 [E] 입출고, 현재 보존 설명, 같은 종류 여러 대가 용량을 늘리지 않는 규칙 |
| 생산 설비 | 현장 가공·수령 | 생산실 배치, 배운 상품 예시만 표시, 가공 후 같은 설비에서 수령 |
| 계산대·문 | 거래 방식 또는 실제 연결 용도 | 손님이 걸을 통로와 대기 자리, 직접·직원 계산, 생산실/창고 문 연결과 출입 |
| 치장 | 실제 효과의 뜻 | 해당 손님의 방문 비중·추가 구매·배치 평판, 중첩 시 추가 효율 감소, 실제 매장 배치 조건 |

설계도에서는 이름 아래에 핵심 규격을 먼저 표시한다. 모델 미리보기와 긴 설명을 스크롤하지 않아도 한 층 수량·보관량을 읽을 수 있다. 다른 집기를 선택하면 상세 스크롤을 처음으로 돌린다. 제작 버튼은 기존처럼 설명 스크롤 밖에 둔다.

인벤토리에서도 같은 요약과 사용 안내를 표시하고, 오른쪽 상세 전체에 스크롤을 넣었다. 일반 아이템의 아이콘·가격·원래 설명은 유지한다. 제조법이 없는 기존 보유 집기를 「설계도에서 제작」한다고 잘못 안내하지 않는다.

## 실제 규격과 비교

진열대 수치는 `ShelfData`, 크기와 설치 위치는 `BuildObjectData`, 발전 재질은 `FurnitureObjectCatalog`에서 읽는다. 창고 선반은 실제 설치 씬의 기본값과 카탈로그 적용 후 값을 읽는다. 냉장·냉동함은 `PreservationService` 설정의 용량과 보존 설명을 사용한다. 수치를 안내 문구에 따로 고정 저장하지 않는다.

같은 기능 중 **현재 제작할 수 있거나 이미 보유/배치한 집기**를 비교하며 같은 크기를 우선한다. 아직 공간이 열리지 않은 집기와 미습득 현대 제작 단계는 비교 목록으로 새로 소개하지 않는다. 현대 집기를 이미 가진 이전 저장에서는 해당 종류를 비교할 수 있지만 새 제작 조건을 완료한 것으로 기록하지 않는다.

한 층 용량과 최대 층은 구분한다. 최대 3층이라고 집기 1개로 3층을 받는 것이 아니다. 한 층을 추가할 때 같은 종류 집기 1개가 더 필요하고, 방향이 있는 진열대는 같은 방향으로 놓아야 하는 기존 배치 규칙을 이용한다. 현재 철제 진열대는 3칸×8개로 한 층 24개·최대 3층이다. 기존 CSV 설명의 「두 층」 문장은 수치 변경 뒤 남은 이전 문장이라 첫 외형 문장만 재사용하고 현재 규격을 별도로 표시한다. CSV 원문 교정은 Claude 검토 대상으로 남긴다.

예를 들어 넓은 나무 진열대는 같은 2×1칸에서 한 층 12개·최대 1층이고, 철제 진열대는 한 층 24개·최대 3층이다. 이미 가진 기존 2×1 진열대는 한 층 21개·최대 3층으로 비교한다. 현대 표준 진열대는 기존 발전·제품 이야기 조건을 완료한 뒤 한 층 40개·최대 3층으로 표시한다. 실제 용량·적층·해금·재료 소비는 기존 값을 유지한다.

## 공개와 실제 실행

편의점 → 생산실 → 창고 → 확장의 공간 진행을 유지한다. 안내를 읽어 공간·층수·보존 설비·제조법·이야기를 완료하지 않는다. 소지품을 자동으로 진열하거나 창고에서 원격 제작하지 않는다. 일반 창고가 식품을 냉장·냉동 보존한다고 설명하지 않는다.

치장 설명은 기존 효과 종류를 사용한다. 화분은 일반 손님의 방문 비중, 포스터는 추가 구매 가능성, 등불은 배치 평판 기여를 안내한다. 상점 수익·관계 보상·고정 방문 인원을 보장하지 않는다. 냉장·냉동함에는 치장 보너스가 있는 것처럼 표시하지 않는다.

새 저장 필드나 대사/글 종류를 추가하지 않는다. `FurnitureGuide.ENABLED`를 false로 바꾸면 기존 설명으로 돌아갈 수 있다. 새 안내의 소스는 `script/ui/management/furniture_guide.gd`이고 설계도·인벤토리에 작은 연결을 추가한다. 새 종류·가격·이미지가 필요한 후보는 별도 검토 후 추가하며 이 사용 안내 구현을 새 집기 추가로 집계하지 않는다.

## 검증

`dev/scenes/check_furniture_guide.tscn`에서 실제 메인 씬과 책을 열어 단계별 공개·현재 용량·같은 크기 비교·알지 못한 현대 집기 제외·이미 보유한 종류·치장 효과·냉장냉동 공유 용량·실제 창고 씬의 규격·긴 상세 스크롤·일반 아이템 표시·저장 복원을 확인한다. 안내를 읽는 동안 돈·재료·집기 수량·진행·보존 설치 상태가 변하지 않는지도 검사한다. 실제 사용자 저장을 불러오거나 덮어쓰지 않는다.
