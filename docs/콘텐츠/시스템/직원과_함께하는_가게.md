# 직원과 함께하는 가게

2026-10-06 · 사용자가 요청한 고용·해고 기능과 직원 이야기 보완.

## 1. 확인 방법

핵심 튜토리얼을 마치면 기존 직원이 **지원자로 가게 앞에 걸어온다**. 가까이서 [E]로 소개를 끝까지 들으면 직원 관리의 **고용·해고** 목록에 나타난다. 「나중에 · Esc」로 중단하면 다시 인사할 수 있다. 고용 버튼은 기존 조건 확인창을 열며 계약은 아침 6시 오픈 준비 중에 결정한다.

고용 전에는 만난 후보와 계약 조건만 보여 준다. 첫 고용 뒤 **근무표·정보** 탭이 열리고 근무 시간을 직접 지정한다. 가게를 열어 직원이 실제 출근한 뒤 **교육** 탭이 열린다. 교육은 기존처럼 다음 아침 6시 오픈 준비 중에 진행한다. 소개·기억 버튼은 고용·해고에 모으고 정보에는 근무·능력·급여를 보여 주며 교육 버튼을 중복 배치하지 않는다.

직원 1→2→3 순서로 방문한다. 한 사람의 소개를 마친 **다음 날부터** 다음 지원자를 만날 수 있다. 계약하지 않아도 다음 만남과 핵심 이야기는 진행할 수 있으며 기한·재방문 벌점·새 보상이 없다. 길이 막혀 있으면 실제 연결된 빈 바닥 길을 찾을 때까지 방문을 재시도한다. 소개를 마친 방문자는 다음 갱신에서 화면을 떠난다. 이미 만난 후보는 이후 책에서 계약할 수 있다.

기존 직원 3명을 사용한다. 새 인물 이름·이미지·전용 능력은 만들지 않았다. 직원 성격은 기존 선호 시간에 맞춘 콘텐츠 초안이다.

| 직원 | 이야기 방향 | 기존 고용 비용 | 기존 28일 기준 급여 |
|---|---|---:|---:|
| 직원 1 (`worker_001`) | 아침에 물건 놓일 자리를 살피고 차분하게 확인한다 | 0 G | 1000 G |
| 직원 2 (`worker_002`) | 조용한 밤, 손님을 기다리는 가게에 관심을 보인다 | 0 G | 1200 G |
| 직원 3 (`worker_003`) | 저녁 정리와 동료끼리 일을 나누는 것을 좋아한다 | 100 G | 1400 G |

수치의 기준은 `data/shop/employees/employees.csv`다. 이번 작업으로 비용·급여·교육·출근·정산 수치를 바꾸지 않았다.

## 2. 직원별 이야기 6개

직원마다 아래 장면이 있어 총 **18개 장면**이다. 퀘스트 18개를 추가한 것이 아니다.

| 장면 접미사 | 실제로 열리는 조건 |
|---|---|
| `intro` | 지원자 방문의 소개를 완독한다. 이후 책에서 기억을 다시 읽을 수 있다 |
| `hired` | 첫 고용이 성공했다 |
| `first_shift` | 직원이 실제로 출근하여 화면에 나타나 근무 중이다 |
| `trained` | 기존 유료 교육이 성공했다 |
| `dismissed` | 실제 해고가 성공했다 |
| `rehired` | 이전에 고용했던 같은 직원을 다시 고용했다 |

아직 읽지 않은 장면을 소개→첫 고용→첫 출근→교육→작별→재회 순으로 읽는다. 조건이 충족되지 않은 장면은 건너뛴다. 화면을 닫거나 Esc로 중단하면 완독 기록을 남기지 않는다. 마지막까지 읽은 장면은 직원 카드에 제목과 기억 문장으로 남고 다시 읽을 수 있다. 이야기는 추가 돈·아이템·평판·능력치를 지급하지 않는다.

기존 저장에서 이미 고용·교육·소개·근속 기록이 있는 직원은 만난 후보로 유지한다. 고용·교육·근속 기록이 있는 직원의 교육 접근은 별도 호환 키로 유지하며, 실제 첫 출근 장면을 가짜로 완료하지 않는다. 이미 고용된 직원은 새로운 채용으로 처리하지 않는다. 첫 채용 대사를 소급하여 열거나 비용을 다시 차감하지 않으며, 실제 출근·교육·작별·재고용부터 기록할 수 있다. 이야기 기록은 기존 `PlayerProgress.story_beat_days` 저장 경로를 사용하고 새 게임에서 초기화된다.

## 3. 고용·해고 안내 보완

- 고용 조건 확인창에 비용, 28일 기준 급여, 선호 시간, 소지금, 전체 미지급 급여를 표시한다. 확정 전에 시간·영업 상태·자금·이미 고용된 상태를 다시 검사한다.
- 고용 뒤 근무표는 직접 지정한다. 이어진 최대 2타임이라는 기존 규칙을 안내한다. 근무표가 비어 있어도 고용 중인 날은 기존 급여가 누적되므로 카드에서도 이를 알린다.
- 해고 확인창에 현재 직원의 누적 급여를 표시한다. 해고하면 근무표는 비워지고 교육 단계와 이미 발생한 급여는 유지된다. 급여는 즉시 정산하는 새 기능 없이 기존 계절 말 정산에 포함된다.
- 재고용은 기존 비용만 사용한다. 교육 단계는 유지하지만 근무표는 다시 지정한다. 해고·재고용을 반복해도 별도 선물이나 보상이 생기지 않는다.
- 취소·자금 부족·영업 중 변경 실패는 이야기 조건을 열지 않는다. 직원 관리 책을 닫으면 대화와 고용·해고 확인창도 닫고 게임의 기존 시간 진행을 재개한다.
- 고용·해고 확인창 본문, 제목, 버튼 글자색을 각각 배경에 맞춰 지정했다. 정보 탭의 내부 직원 ID 표시는 제거하고, 실제 구현된 손님 추천 행동에 맞춰 교육 안내를 수정했다.

새 글 종류는 추가하지 않았다. 직원 소개의 기계용 `employee_id`는 글 항목으로 내보내지 않는다. 아래 명령은 초안 작성용이며 이번 작업에서는 Gemini API를 호출하지 않았다.

```bat
dev\gemini\run_request_text.bat webprompt service_text --ids worker_001_intro,worker_001_hired,worker_001_first_shift,worker_001_trained,worker_001_dismissed,worker_001_rehired --chunk 6
dev\gemini\run_request_text.bat webprompt service_text --ids worker_002_intro,worker_002_hired,worker_002_first_shift,worker_002_trained,worker_002_dismissed,worker_002_rehired --chunk 6
dev\gemini\run_request_text.bat webprompt service_text --ids worker_003_intro,worker_003_hired,worker_003_first_shift,worker_003_trained,worker_003_dismissed,worker_003_rehired --chunk 6
```

글을 다듬을 때 기존 이름, 실제 행동 조건, 교육 기록과 급여의 유지, 별도 답례가 없다는 점을 지킨다. 새 가족·직업·세력·전이 원인·평판 불이익을 확정하지 않는다. 최종 인물 이름과 개인 사연 확장은 이후 세계관 검토 대상으로 남긴다.

## 5. 검증

Godot 4.7.1, 실제 사용자 저장과 분리된 테스트 데이터로 확인했다.

- `check_employee_content`: 실제 관리 화면의 채용 버튼·취소·확정 재검사·첫 출근·교육·작별·재회·전체 저장 복원·계절 말 급여·화면 닫기·18개 글 등록 등 54개 검사, 실패 0.
- `check_request_text`, `check_request_text_runtime`: 글 형식·반복 문장·기계 장면 ID·실행 중 대사 연결 검사 통과.
- 기존 튜토리얼 85개, 수동 결제, main 콘텐츠·3D 통합 88개 검사 통과.
- 가져오기 2회와 전체 스크립트·씬 673개 로드 검사 통과. 로컬 인증서 경고는 기능 오류와 구분했다.
- 화면이 있는 실행에서도 54개 검사를 수행하고 직원 대화·고용 조건·해고 확인창을 캡처해 확인했다.
- `tools/balance_baseline.py`: 종료 코드 0. 기존 직원 경제 값은 유지했다.

원정 진행 경로·큰 시스템 파일·메인 씬·이미지는 이번 작업에서 수정하지 않았다.
