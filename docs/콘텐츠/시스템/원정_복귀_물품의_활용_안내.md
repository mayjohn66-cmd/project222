# 원정 복귀 물품의 활용 안내

2026-10-09 · 구현 완료 · `main` @ b5ef682.

## 1. 가방에서 가게로 이어지는 선택

원정 결과에서 **물품 활용 안내 보기**를 누르면 가방 물품을 어떻게 판매·가공·전달·보존할지 확인한다. 자동으로 열리지 않으며, 원래 종료 사유와 물품 수량은 같은 스크롤에 유지한다. **편의점으로 복귀** 버튼은 본문 밖에 고정되어 안내를 펼친 상태에서도 누를 수 있다.

결과 가방에는 출발 때 가져온 물품도 들어 있으므로 모두 새로 얻은 전리품으로 표현하지 않는다. 확인 전의 가방 수량만 합산하며, 기존 소지품·진열·창고 재고를 섞지 않는다. 안내를 읽거나 접는 것으로 물품 이동·제작·학습·부탁 완료·답례 지급이 발생하지 않는다.

## 2. 실제 물품별 안내

| 내용 | 공개·판정 기준 |
|---|---|
| 정산 후 위치 | 기존 `ItemData.should_deposit_after_expedition`. 자동 정산 재료는 소지품으로 이동하고 장비·두루마리는 기존처럼 가방 유지 |
| 직접 판매 | `is_sellable`과 `is_shelf_allowed`를 모두 충족. 복귀 후 진열대 [E]로 보충하고 실제 계산을 마쳐야 판매됨 |
| 가공 | 기존 `InventoryItemGuide.learned_outputs` 재사용. 제작 소개를 들었고 지금 배운 제조법에 들어가는 물품만 완성품 예시 표시. 설비·나머지 재료·실제 수령도 필요 |
| 맡은 부탁 | 기존 `RequestPreparationData.entries`의 현재 요구만 연결. 수락 후 미완료 부탁과 현재 단계, 동일 물품 또는 대체 그룹의 이 물품만 표시 |
| 부탁 수량 | 기존 요구 수량을 표시하고 수첩 [N]의 전달 장소·다른 조건 확인을 안내. 가방 수량만으로 전체 부탁이 준비/완료됐다고 판정하지 않음 |
| 계절 변형 | 실제 `PreservationGuide.material`·`ambient_hint` 규칙으로 다음 아침/계절 이후 변형과 변형 결과 표시. 맞는 보존 설비에 직접 넣어야 함 |
| 식품 | 실제 `FoodShelfLife.tracked` 대상만 상태 확인과 적정 진열 안내. 가방에 없는 배치별 남은 기한을 만들어 표시하지 않음 |
| 두루마리 | 기존 해금 연결과 학습 기록으로 미학습/기학습 구분. 조회만으로 배우거나 사용할 수 있다고 처리하지 않음 |
| 오류/빈 가방 | null·잘못된 물품/수량/UID·중복 UID는 안내 확인 불가. 빈 가방은 정상 복귀 안내. 기존 정산 오류 메시지는 덮어쓰지 않음 |

**자동 보관은 정산 때 소지품으로 옮기는 처리**다. 물리 창고 선반이나 냉장·냉동 설비 입고와 구분한다. 결과 화면은 복귀 정산 이전이므로, 날짜가 바뀌는 경우의 변형·식품 상태·부탁 조건은 가게에서 다시 확인하게 한다. 새로운 보존 설비를 설치했다고 가정하지 않는다.

아직 받지 않은 부탁·미학습 제조법·다른 대체 후보를 공개하지 않는다. 새 원정 보상·주민·대사 ID·가격·수요·계절/시간 정책을 추가하지 않았다.

## 3. 화면과 입력

- 본문은 기존 결과창의 스크롤에 추가하고, 안내 보기/접기와 복귀 버튼은 고정한다.
- 펼치면 활용 안내 시작 위치로 이동하고 접으면 기존 결과 맨 위로 돌아간다. 다시 결과창을 열면 접힌 상태로 시작한다.
- Esc는 안내만 접는다. 열린 동안 Tab은 안내 버튼과 복귀 버튼을 오간다.
- 열린 동안 R 등 게임 단축키와 F5가 결과창 뒤의 가방 회전·저장에 전달되지 않는다. 원래 확인/복귀 동작은 그대로 사용한다.
- 실제 원정 결과 화면에만 진입 버튼이 나타난다. 준비 화면에서는 숨겨지고 결과창 단독 배치 검사에서도 안전하게 숨겨진다.
- 별도 레이어나 새 저장 필드를 만들지 않는다. 씬 종료 시 안내도 함께 정리된다.
- `ExpeditionReturnGuideData.ENABLED = false`로 안내 연결만 끌 수 있다.

## 5. 식품 기한 연결 보강

후속 `main` @ `f51e657`에서 원정 가방·전리품 이동과 복귀 정산에 기존 `food_batches`를 전달하도록 보강했다. 이전 기한이 새로 시작되지 않으며 가방은 기존 상온 보관 규칙을 적용한다. 옛 누락 기록은 현재부터 채택하고 잘못된 기록은 거부한다. 실제 재고와 저장 가방·체크포인트 사본의 폐기 중복도 차단했다. 결과 안내에 기한 유지·상온 설명을 추가했지만 배치별 정확한 남은 날짜는 표시하지 않는다.

상세와 격리 검사 실행법은 [원정 가방에서도 이어지는 식품 기한](원정_가방에서도_이어지는_식품_기한.md)에 있다. 신규112 헤드리스/GPU·기존 복귀178 실패0. 기존 인수인계44의 식품 배치 미전달 문제는 구현으로 해결했으며, Claude의 규칙 정합성 검토는 같은 항목에 유지했다.
