# 초반 주민과 도구의 연결 점검

현행 구현: `main` @ `591b0bb` (2026-10-09, 푸시 완료). 콘텐츠 점검 순서의 2번: 첫 장사 뒤 주민 부탁 → 도구 판매 NPC → 채집 → 전달 연결을 보강했다.

## 1. 찾은 문제와 보강

엘미의 부탁 뒤에는 타블렌의 재방문·노점 자리·첫 안부·도구 구매가 이어져야 한다. 이 구간에서 현재 주민 부탁이 비어 있으면 수첩이 “지금까지의 주민 부탁을 마쳤습니다”라고 표시했다. 관리 책의 별도 도구 카드와 다음 부탁 카드가 서로 다른 상황처럼 보이던 부분을 실제 진행 상태로 맞췄다.

| 현재 상태 | 안내와 목적지 |
|---|---|
| 오렐·엘미 완료, 타블렌 미방문 | 가게를 열고 판매할 물품을 진열해 방문 기다리기 · 실제 출입문 |
| 타블렌 방문, 인사 전 | 재회 인사 [E] · 기존 소개 NPC |
| 노점 자리 부탁 진행 중 | 기존 부탁/준비 안내 · 기존 부탁 NPC |
| 노점 마련, 첫 안부 전 | 타블렌에게 안부 [E] · 정착한 타블렌 |
| 안부 뒤, 물병 미보유 | 노점 [E] · 현재 판매가/보유금/부족금 표시 · 실제 노점 |
| 물병 구매, 아직 가방에 없음 | 이미 보유한 도구를 보유 장비에서 원정 가방에 넣기, 재구매 불필요 |
| 저장 가방에 물병 있음 | 가방에 준비되어 있음을 안내, 출발할 때 그대로 챙기기 |
| 라슈 부탁 완료 | 이 초반 도구 안내 종료, 기존 후속 주민 흐름 유지 |

마을 수첩은 기존처럼 **관리 책 → 일정**에서 본다. 새 팝업·화면 왼쪽 안내·탭 숨김을 추가하지 않았다. 기존 목적지 표시 버튼을 사용하고, 책을 닫은 뒤 직접 이동한다. NPC와 거래·전달은 기존 [E] 동작이다.

도구가 부족하면 무료로 지급하거나 자동으로 구매하지 않는다. 돈이 부족할 때는 부탁에 필요한 물품을 남기고 남는 판매 가능 재료를 진열하라는 다음 행동을 안내한다. 현재 부탁·소개 NPC가 없는데 이전 NPC가 아직 장면에 남아 있는 경우에도 그 NPC를 목적지로 삼지 않는다.

3D 표시를 위해 2D 마을 컨테이너가 숨겨져 있어도, 개별 시설이 실제로 해금되어 있고 보이는 상태이면 목적지로 사용할 수 있다. 실제로 숨겨진 시설·건축 미리보기·삭제 대기 노드는 제외한다.

## 2. 돈과 도구가 이어지는지

현재 데이터에서 오렐30 G + 엘미40 G + 노점 자리40 G = **110 G**. 물병은 기존 **80 G**이므로 이 세 답례만으로 살 수 있고 **30 G**가 남는다. 처음 장사 수익을 추가하지 않은 0 G 시작 검사에서도 연결된다. 다른 곳에 돈을 쓰면 판매로 마련해야 하며 소지금 부족 구매는 차단된다.

오렐의 열매와 엘미의 약초, 노점 자리의 가지는 도구가 필수인 물 채집과 분리돼 있다. 실제 숲 전리품·복귀 정산으로 이 물품을 구해 NPC에게 전달할 수 있었다. 구매한 물병은 보유 장비에 생기므로 반드시 원정 가방에 넣는다. 기존 물 채집 서비스로 얻은 `raw_water` 2개를 라슈에게 전달하면 기존 답례30 G를 받는다. 초기 생수 `water`와 혼동하지 않는다.

물품·수량·가격·답례·평판·해금·방문률·시간 규칙은 변경하지 않았다. 이미 수락/완료한 부탁·장비 개별 ID·기존 저장과 후속 이야기 순서도 유지한다. 강제로 무료 손님이나 추가 도구/돈을 만드는 보강이 아니다.

## 3. 구현

- [EarlyProgressionGuide](../../../script/world/shop/requests/early_progression_guide.gd): 초반 대기 상태·도구 보유/가방 상태·목적지 조회. `ENABLED = false`로 새 상태 안내를 끌 수 있다.
- [VillageJournalFlow](../../../script/world/shop/requests/village_journal_flow.gd): 빈 부탁의 실제 다음 행동과 목적지 연결.
- [관리 책의 마을 수첩](../../../script/ui/management/village_journal_book_view.gd): 기존 도구 준비 카드도 같은 상태 조회 사용.
- [채집 도구 안내](../../../script/ui/expedition/prep/expedition_gathering_tool_guide.gd): 미보유/보유/가방 준비 구분. 수첩 물품 준비에서도 같은 문구 사용.

조회는 재고 이동·돈 지급·방문 기록·부탁 수락/완료·저장을 실행하지 않는다. 새 루트 저장 필드·CSV·대사 ID·이미지를 추가하지 않았다. 세계관 대사 보강은 기존 인수인계41의 Gemini 검토 범위에 남겨 둔다.

## 4. 실행 검증과 범위

[연속 검사 씬](../../../dev/scenes/check_early_supply_route.tscn) **52개 헤드리스/GPU 실패0**. 완료한 도입부·가게 배치가 시작 fixture이며, 이후 재료와 돈을 임의 지급하지 않고 실제 전리품/채집 → 복귀 정산 → 주민 NPC 전달 → 실제 보도 경로로 타블렌 방문 → 재회 → 자리 마련 → 첫 안부 → 관리 책의 실제 목적지 버튼 → 노점 구매 → 실제 준비 가방 이동 → 물 채집 → 라슈 전달을 확인했다. 부족금 검사는 이미 번 답례를 잠시 비웠다가 같은 금액만 복원해 검사하며 구매 경로에 추가 자금을 주지 않는다.

첫 청소·가게 설치·실제 첫 결제·물물교환·원재료 결제는 기존 도입 검사 **101개**로 별도 확인했다. 연속 검사에서 원정 방을 사람이 직접 조작한 것은 아니며, 채집/전리품·가방·정산 서비스를 사용했다. 전체 방 진행은 별도 원정16판 검사로 확인했다.

기존 도구43·부탁 준비50·주민 부탁·수첩·메인88 실패0. 최종 import2회 종료0·전체813 로드실패0·SCRIPT ERROR0, 원정16/16 완료(104단계, stuck0). 1152×648·768×432 관리 책 캡처와 실제 클릭/목적지 표시·닫기를 확인했다. 3D 책의 열기/닫기 연출 완료를 기다리고 SubViewport 입력 좌표를 적용해 실제 표시 경로로 검사했다.

검사는 앞선 식품 검사와 같은 `foodbag_checks` 별도 사용자 저장 프로젝트에서 실행한다. 새 연속 검사는 격리 경로가 아니면 진행 전에 중단한다. [격리 프로젝트 설정](원정_가방에서도_이어지는_식품_기한.md)을 적용한 뒤 `godot --headless --path <테스트 프로젝트> res://dev/scenes/check_early_supply_route.tscn`으로 실행한다. 실제 사용자 저장 파일은 사용하지 않았다. 로그·캡처는 저장소 밖 `output/early-route-*.log`·`output/early-route-gpu-journal-*.png`에 있다.

푸시 전 받은 그림 후보와 건축 CSV 빈 줄 경고 처리 `0173a2c`를 보존했다. 해당 빈 줄 처리는 데이터 끝의 경고를 줄이는 변경이며 재고/구매 규칙 변경은 아니다. 통합 뒤 신규52/메인88 실패0·SCRIPT ERROR0을 다시 확인했다.

다음 점검은 3번: **편의점 → 생산실 → 창고 → 확장**과 아직 사용할 수 없는 관리 기능의 다음 행동이다. 현재 `UNLOCK_ALL_TABS` 정책을 그대로 두고 공간/설비의 실제 선행 조건과 안내를 대조한다.
