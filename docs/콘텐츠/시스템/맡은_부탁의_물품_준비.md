# 맡은 부탁의 물품 준비

2026-10-08 · 사용자 「남은 콘텐츠 보강 계속」 요청에 따라 공간의 첫 사용 다음으로, 이미 맡은 부탁을 실제 준비 행동과 연결했다.

## 플레이에서 확인하기

핵심 거래 안내가 끝난 뒤 **마을 수첩 [N] → 물품 준비**를 연다. 준비할 물품이 있는 부탁을 아직 맡지 않았거나 모두 전달했다면 빈 소탭을 먼저 보여 주지 않는다. 기존 이웃 기록과 목적지 표시는 그대로 이용한다.

물품 준비에는 부탁 제목, 물품별 전달 가능한 재고·필요량·부족분, 별도 보관 재고, 부족한 물품의 확보 경로와 돌아갈 곳이 나온다. 이 화면은 새로운 부탁이나 보상 추가가 아니라 기존 부탁을 수행하는 방법의 보강이다.

## 알려진 부탁만

- 주민·정착·공동·개인 부탁: 수락 후 미완료 물품을 표시한다.
- 첫 장터: 맡은 뒤 준비 물품을 이미 전달했다면 제외한다.
- 계절 마을/생활 부탁: 맡은 미완료 이야기의 실제 요구 물품을 표시한다. 관찰·안부만 필요한 사건은 새 물품을 만들어 넣지 않는다.
- 시제품: 실제 제작·수령 경험도 필요하다는 안내를 유지한다. 물품 수량만 있다고 완료된 것처럼 표시하지 않는다.
- 낚시: 맡은 물품 요구와 첫 낚싯대의 실제 재료를 표시한다. 선택 그룹은 **후보 중 한 종류**이며, 후보 전부를 요구하거나 서로 다른 종류의 재고를 합치지 않는다. 잡아 본 물고기·보유한 물품·배운 상품만 후보 이름을 공개한다.
- 마을 확장과 4막: 현재 단계의 요구만 표시한다. 소개 다음에 요구할 물품을 미리 펼치지 않는다. 반복 사건의 이전 완료 기록이 있어도 새 회차의 현재 요구는 표시한다. 실제 제작·채집 경험과 가구 보관함 조건을 유지한다.

시간·관찰·안부만 필요한 장면, 미수락·완료 이야기, 미래 단계는 준비 물품 목록에서 제외한다. 모든 이야기를 새 사건으로 재집계하지 않는다.

## 재고와 확보 경로

| 항목 | 표시 기준 |
|---|---|
| 전달 가능 | 기존 GameState 일반 물품 재고. 현재 기한·변형 정산 규칙을 적용한 실제 수량 |
| 창고 선반 | 이 월드의 실제 선반 재고. 건축 미리보기·다른 월드 제외, 현장 출고 필요 |
| 냉장·냉동 | 설치된 보존 설비의 실제 재고. 현장 출고 필요, 일반 재고에 합산하지 않음 |
| 가구 | 가구 보관함 수량. 이미 배치한 집기는 전달 재고에 포함하지 않음 |
| 배운 제조법 | 실제 산출량으로 부족분을 채울 횟수를 올림 계산하고 그 횟수의 실제 재료를 표시. 현장 설비에서 시작·수령 |
| 원정 | 실제 이벤트→전리품 표(전투는 몬스터의 전리품 표)를 조회하고 입장 가능한 지역에서 얻을 수 있는 경로만 표시. 계절·날씨·난이도 조건과 채집·보물·전투 경로와 무작위 탐험 특성 안내 |
| 낚시 | 현재 이용 가능한 물가와 해당 어종의 계절·시간·날씨를 표시. 실제 포획 후보에 없으면 조건을 기다리도록 안내 |

모르는 제조법·닫힌 물가·입장 물품이 없는 지역은 경로로 공개하지 않는다. 채집·낚시 성공이나 원하는 물품의 지급을 보장하지 않는다. 제조법과 원정 경로는 각각 최대 세 개를 예로 보여 주므로 모든 획득 경로를 정리한 도감은 아니다.

식품은 날짜가 지난 물품을 전달할 수 없다고 설명한다. 재고 조회는 기존 보존·변형 정산을 사용하며 새로운 기한, 할인, 냉장 효과를 추가하지 않는다. 같은 물품을 쓰는 여러 부탁은 재고를 예약하지 않는다. 한 부탁에 실제 전달하면 다른 부탁의 표시 수량도 줄어든다.

## 화면·저장·역할

두 소탭은 같은 수첩 모달 안에 있어 기존 시간 정지·닫기 [E/Esc]·[N] 처리가 유지된다. 물품 준비 목록은 세로로 스크롤하며 닫기 버튼을 덮지 않는다. 수량과 진행이 바뀌면 목록을 갱신하고 읽던 스크롤 위치를 유지한다. 요구 물품이 모두 사라지면 이웃 기록으로 돌아간다.

새 저장 필드·대사 ID·수치 CSV·이미지·인물 설정은 추가하지 않았다. 기존 글 제목과 실제 요구 데이터를 재사용한다. 수첩에서 수락·전달·제작·원격 출고·보상 지급을 하지 않는다. 기존 저장의 수락·완료 기록으로 준비 화면을 다시 구성한다.

코드는 새 파일 `request_preparation_data.gd`, `request_item_sources.gd`, `request_preparation_view.gd`에 두고 기존 `village_journal_panel.gd`에 연결만 추가했다. `RequestPreparationData.ENABLED = false`이면 기존 이웃 기록 화면만 표시한다.

Gemini가 기존 부탁의 글을 다듬을 때는 실제 장소·물품 전달·대체 후보 한 종류·제작/채집 경험의 추가 조건을 유지한다. 이번 보강은 새 글 등록이나 API 호출을 요구하지 않는다. Claude는 실제 요구 데이터와 준비 안내가 일치하는지 검토한다.

## 검증

새 `dev/scenes/check_request_preparation.tscn`에서 실제 월드를 사용해 수락/완료, 실제 선반 입출고와 주민 전달, 시제품 재료 횟수, 낚시 대체 그룹과 냉동 입고, 계절 대기, 닫힌 물가 제외, 반복 회차, 기존 진행 저장 왕복, 식품 만료, 목록의 닫기 버튼과 모달 해제를 검사한다. 사용자 실제 저장은 불러오거나 덮어쓰지 않는다.
