# 원정과 분리된 낚시

2026-10-08 사용자 결정: **낚시는 원정과 별도로 물고기를 얻는 생활 채집 활동으로 만든다.** 이 문서는 설계 결정과 후속안을 기록하며 낚시 기능·어종·아이템은 아직 구현하지 않았다.

## 1. 확정된 방향

- ✅ 원정의 몬스터 처치·채집과 낚시의 획득 경로를 분리한다.
- ✅ 원정에 입장해야 낚시를 할 수 있는 구조로 만들지 않는다.
- 이전 대화의 「마을 낚시로 시작한 뒤 원정 물가에도 연결」은 권장안이었다. 이번 결정에 따라 첫 낚시 설계는 별도 생활 활동을 기준으로 한다. 원정 낚시를 확정된 확장 계획으로 남기지 않는다.

## 2. 첫 구현 제안

아래는 🟡 제안이며 장소·조작·규모의 확정은 아니다.

| 항목 | 제안 |
|---|---|
| 장소 | 가게 근처에서 접근할 수 있는 작은 물가 1곳 |
| 도입 | 첫 원정·원재료 판매 이후 기존 주민과 대화하여 낚시를 알게 됨 |
| 기본 흐름 | 물가 접근 → 낚싯대 사용 → 입질 기다림 → 버튼으로 건지기 → 획득 결과 확인 |
| 조작 난도 | 복잡한 게이지·연타 없이 짧은 조작으로 시작 |
| 첫 콘텐츠 규모 | 어종3종·소개 사건1개·요리법1개·주민 부탁1개 |
| 진행 관계 | 선택 활동으로 두고 주요 이야기·생산실·창고·확장을 낚시 완료로 막지 않음 |

새 인물 이름·낚싯대 무료 지급·가격·확률·잡는 시간·보상은 정하지 않았다. 소개를 읽은 것과 실제 낚시 성공은 다른 기록으로 다룬다.

## 3. 기존 경영과 연결할 후보

- 판매: 잡은 생선을 상품으로 진열해 판매하는 경로.
- 제작: 교류로 생선구이·말린 생선 등의 제조법을 배우는 경로.
- 보존: 기존 냉장·냉동·가공 구조와 연결. 생선별 보존 방법과 변형 조건은 추후 검토.
- 부탁: 주민의 식사 준비나 계절 음식과 연결하는 생활 부탁.
- 계절·날씨: 기존 환경 상태를 참고하여 어종 차이를 주는 확장안.

모두 🟡 후속 후보다. 현재 데이터에 생선·요리법·낚시 부탁을 등록한 것으로 보지 않는다. 수치는 기존 경제와 함께 검토하며 낚시가 원정 재료 판매를 대신하는 필수 수입원이 되지 않도록 확인한다.

상품 신선도 안내는 기존 진열 상품 조회·관리 구조에 연결하는 방향으로 검토한다. 낚시 전용 인벤토리나 생선마다 반복해야 하는 별도 관리 화면을 먼저 늘리지 않는다.

## 4. 구현 전에 정할 항목

1. 낚시터 위치·접근 경로와 첫 소개 조건.
2. 낚싯대 확보 경로·장착 방식·미끼 사용 여부.
3. 입질·성공·실패 조작, 낚시 중 기존 시간 진행 규칙과의 관계.
4. 어종 ID·계절/날씨 조건·확률·판매가·가공/보존 규칙.
5. 첫 소개를 맡을 기존 주민과 실제 장면·부탁 조건.

직원 없는 상태에서도 별도 활동을 소개할 수 있어야 한다. 낚시가 손님을 대신 계산하거나 가게 시간을 자동으로 정지시키는 새 규칙을 암묵적으로 추가하지 않는다.
