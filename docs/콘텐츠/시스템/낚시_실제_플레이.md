# 낚시 실제 플레이와 연결 데이터

2026-10-08. 사용자의 “게임 기능을 마저 구현” 요청으로 전체 초안을 실제 게임에 연결했다. 가격·시간·가중치는 플레이가 가능한 초기값이며 Claude의 경제 검토 대상이다. 이미지 20종은 미제작으로 이름 표시를 사용한다.

## 1. 시작하는 순서

1. 기존 핵심 튜토리얼과 원정 재료의 실제 첫 판매를 마치고 엘미의 기존 부탁을 맡거나 완료한다.
2. 가게 밖에 표시되는 **가게 옆 개울 [E]**로 걸어간다. 수첩에도 물가와 다음 행동이 기록된다.
3. 엘미의 물가 소개를 끝까지 듣고 `물가 살펴보기`로 관찰한다. 다시 이야기해 첫 단계를 마친다.
4. 타블렌에게 낚싯대 소개를 듣고 나뭇가지 2개·수액 1개로 엮는다. 무료 시작 지급은 없다. 해당 NPC가 물가로 걸어오면 가까이서 E로 이야기한다.
5. 첫 포획 소개 → 실제 E 낚시 → 생선 진열·실제 계산 → 첫 판매 이야기를 진행한다. 버튼만 누르거나 물품 보유만으로 포획·판매 단계를 완료하지 않는다.
6. 보관 소개 뒤 냉장·냉동함에 실제 입고하거나 생산실에서 말린 생선을 만들어 수령한다. 생산실·창고의 기존 건설 순서는 유지된다.

개울에는 기본 3어종이 모두 있어 특정 계절·희귀 물고기를 기다리지 않아도 다음 물가로 진행할 수 있다. 갈대 못은 오렐의 생선 부탁과 2종 포획, 숲 연못은 첫 판매 단계 완료와 3종 포획 뒤 공개된다.

## 2. 조작과 시간

- 물가에서 E → `낚싯대 드리우기` → 입질 후 E 또는 건지기 버튼. 성공 시 물고기 1마리를 받는다. 연타·게이지·미끼·내구도·스킬 레벨은 없다.
- 낚는 동안 이동만 멈추고 세계의 시간·손님·직원은 진행한다. 초기 입질 대기는 현실 20~28초다.
- 소개·전달·기록 메뉴는 기존 대화처럼 잠깐 시간을 멈추며 닫을 때 이전 상태를 복원한다. 06시 정비/정산이나 다른 정지가 발생하면 낚시를 거두고 물품을 지급하지 않는다.
- **문 닫기의 현재 시간 정책을 바꾸지 않았다.** 닫힌 문 자체는 시간을 정지시키지 않는 현재 코드를 따른다.
- Esc/돌아가기로 취소하면 포획·답례 기록이 생기지 않는다. 소지 공간이 가득 차면 건지지 못하며 놓아줄 수 있다. 물품을 버리도록 강요하지 않는다. 가공품도 가방이 가득 차면 설비의 완성품 상태로 남는다.
- 낚시가 계산을 대신하지 않는다. 직원이 없으면 손님 응대 시간과 낚시 시간을 플레이어가 나누어야 한다.

첫 포획은 기본 어종 중 하나다. 이후 계절·시간대·날씨·물가를 모두 만족하는 어종에서 가중 추첨한다. 기본 어종 가중치 32, 계절·희귀 어종 12/2는 임시 경제값이다. `all`은 제한 없음, `night`/`evening`은 기존 직원·달력의 시간 구분을 공유한다.

생선 기한은 기본 2일, 냉장은 기존 규칙의 2배, 냉동은 남은 기간을 유지한다. 냉동함/냉장함의 기존 12개 용량·운영비를 유지했다. 생선과 가공품 18개를 기존 보존 품목에 등록했다. 봄/겨울 어종 ID를 유지해 냉동한 겨울 생선을 다음 여름에 실제 전달할 수 있다. 일반 말린 생선으로 이 부탁을 대체할 수 없다. 날짜가 지난 식품은 기존 할인·폐기 체계를 따른다.

## 4. 실제 가공과 부탁

생선구이·말린 생선·맑은 수프·생선 빵·도시락·겨울 스튜의 **6가지 제조법**을 기존 주민에게 배운다. 실제 생산실 화덕에서 재료를 넣고 기다려 수령한다. 관리 책에서 원격 지급하지 않는다. 생산실이 아직 없으면 안내를 서두르지 않는다.

어떤 생선을 소비하는지 명시하기 위해 기존 제작 CSV에는 **51개 선택별 레시피**가 있다(구이/건조/수프/빵 각각 12, 도시락 1, 겨울 스튜 2). 서로 다른 51개 요리나 해금이 아니다. 기본 제조법 하나를 배워 해당 선택지를 사용한다. 제작 화면에 사용할 어종 이름을 함께 표시한다. 일반 가공 45초, 건조 30초는 초기값이다.

| 부탁 | 전달 물품 | 답례 초기값 |
|---|---|---|
| 오늘 저녁의 작은 생선 | fish_any_fresh ×2 | 195 G · 평판 1 |
| 작업 뒤의 따뜻한 한 접시 | fish_grilled ×1 | 103 G · 평판 1 |
| 길 위에서 먹는 생선 | fish_dried ×2 | 150 G · 평판 1 |
| 함께 나눌 저녁 | fish_grilled ×2 | 207 G · 평판 1 |
| 비 오는 날의 수프 | fish_soup ×1 | 144 G · 평판 1 |

| 겨울을 남겨 둔 여름 식탁 | fish_winter_kept ×1 | 126 G · 평판 1 |

생선 그룹은 전달 창에서 플레이어가 어종을 고른다. 필요한 수량·식품 기한을 최종 대화 완독 시 다시 검사하고 한 번만 소비·답례 처리한다. 소개만 듣거나 대화 중 Esc로 닫으면 지급하지 않는다. 계절/비/저녁 조건은 소개 때만 적용하며 맡은 부탁은 환경이 바뀌어도 계속할 수 있다. 전달 재료가 부족하면 부분 소비하지 않는다.

입문 5단계, 주민 부탁 10개, 물가 생활 사건 8개, 매장 행사 4개가 각각 구현되어 있다. 계절·비의 관찰 사건은 실제 살펴보기가 필요하다. 달무늬 잉어는 챙기기/놓아주기 선택을 저장하며 놓아주기만 1마리를 소비한다. 물가 식탁은 오렐·코르빈·피니아의 실제 현장 만남과 생선구이 2개 나눔이 필요하다. 생활 사건은 현금·평판 답례를 주지 않으며 기록을 남긴다. 마지막 기억은 일부 계절 어종을 만나면 열리며 12종 전체 수집을 강요하지 않는다.

## 5. 계절 매장 행사

봄 구이, 여름 생선 빵/도시락, 가을 말린 생선, 겨울 수프/스튜를 실제 진열·판매한다. 초기 일정은 계절 17~20일 소문, 21~25일 수요다. 매년 반복하지만 배우지 않은 상품은 고객 요구와 준비 단서에서 제외한다. 신규 게임 초반에는 아직 만나지 않은 어종의 수요도 제외한다.

소문·진행·마감·종료·실제 구매·품절의 여섯 단계가 기존 매장 행사 체계와 연결되어 있다. 소문을 듣는 것만으로 매출·상품·보상을 만들지 않는다. 첫 구매 영수증 뒤 이웃의 감사 대화를 들을 수 있고 연도별 한 번 기록한다.

## 6. 저장·데이터·글 다듬기

- 실행: `script/world/shop/fishing/`의 별도 모듈, `DayManager`가 설치한다. 원정 입장·씬을 사용하지 않는다.
- 조건·물가·가중치·초기값: `data/fishing/fishing_content.json`. `settings.enabled=false`로 기능을 끌 수 있다.
- 아이템/기한/선택별 제작/행사: 기존 `data/core`, `data/production`, `data/shop` CSV에 등록.
- 모든 실제 글: `data/shop/requests/requests_text.csv`, 기존 `service_text` 종류를 사용한다. 새 장면 종류를 만들지 않았다. 글 도구는 실제 기계 조건을 원본 JSON에서 함께 읽으며 구매/품절 글의 `{item}`을 필수로 검사한다.
- 52개 물가 장면 등록: `data/fishing/fishing_scenes.json`; 매장 24장면은 `default_store_event_story.tres`에서 등록. **합계 76장면**이다. 원래 60장면 초안에 행사 진행/마감/종료/품절 16개를 보강한 수다.
- Gemini 참고: `docs/drafts/story/content_voices.csv`에 같은 76개 문맥을 추가했다. 기존 인물 이름/말투 기준 파일은 그대로 사용한다. API를 호출하지 않았다.
- 예: `dev\gemini\run_request_text.bat webprompt service_text --ids fishing_intro_intro,fishing_intro_finish --chunk 2`. 기존 `webimport`·검사·승인 흐름으로 글만 다듬는다.
- 저장은 기존 `PlayerProgress.story_beat_days`의 `fishing:` 정수 기록과 기존 제조법/식품 배치 데이터를 사용한다. 포획·실제 판매·입고·완성품 수령·선택·연례 반응을 복원한다. 낚시 진행 중 찌 상태는 저장하지 않으며 불러온 뒤 물품을 재지급하지 않는다.
- 원본 `docs/drafts/fishing/`와 60장면 초안은 설계 기록이며 런타임에서 읽지 않는다. 현재 실행값과 혼동하지 않는다.
