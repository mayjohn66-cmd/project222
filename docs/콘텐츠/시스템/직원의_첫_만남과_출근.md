# 직원의 첫 만남과 출근

2026-10-08 · 사용자 「1번부터 콘텐츠 보강」 승인에 따른 직원 도입 구현. 기존 직원 3명과 18장면을 사용한다.

## 실제 진행

| 경험 | 다음에 공개하는 내용 |
|---|---|
| 핵심 튜토리얼 완료 | 첫 지원자가 가게 앞의 연결된 빈 길로 걸어온다 |
| 가까이에서 [E] 소개 완독 | 그 사람만 고용 후보에 표시, 계약 조건 확인 가능 |
| 아침 6시 문 열기 전 계약 확정 | 근무표·직원 정보, 직접 시간대 선택 안내 |
| 근무 시간대를 직접 적용 | 첫 출근을 기다리도록 안내, 교육은 아직 숨김 |
| 가게를 열어 실제 출근 완료 | 첫 근무 장면과 교육 탭, 다음 아침 교육 안내 |
| 교육·해고·재고용 | 기존 비용·급여·기억·교육 유지 규칙 사용 |

직원 1 소개를 마친 다음 날부터 직원 2, 다시 그 다음 날부터 직원 3이 방문한다. 고용은 다음 방문의 필수 조건이 아니다. 처음 인사를 미루거나 소개 중간에 「나중에 · Esc」로 닫아도 비용·관계 손실은 없으며, 지원자와 다시 [E]로 이야기할 수 있다. 가게 문에서 떨어진 장소를 골라 지원자가 플레이어에게 너무 붙어 나타나지 않도록 하고, 막힌 길은 방문을 소비하지 않고 재시도한다.

지원자는 별도 이야기 인물로 표시한다. 실제 직원 그룹이나 구매 손님 그룹에 넣지 않아 임금·결제·재고·판매 통계에 포함하지 않는다. 기존 직원 스프라이트와 3D 직원 외형을 재사용하며 이미지 파일을 추가하지 않는다.

## 계약과 관리 화면

- 고용하지 않아도 직접 계산하며 모든 핵심 이야기를 진행할 수 있다. 생산실·창고를 직원의 선행 조건으로 묶지 않는다.
- 고용 후보에는 소개를 마친 사람과 이전 고용 기록이 있는 사람만 표시한다. 직접 고용 함수도 만남 조건을 검사한다.
- 후보 카드와 함께 일하는 직원 카드에 구분 문구를 표시한다. 고용·해고에서 이야기·계약을 살피고, 정보에서 근무·능력·급여를 확인한다.
- 대상이 없는 근무표·정보·교육 탭은 숨긴다. 미지급 급여가 남아 있으면 정보의 전체 급여 확인은 유지한다.
- 실제 첫 출근 뒤에만 해당 직원의 교육을 허용한다. 메뉴 버튼, 정보 탭, 직접 교육 함수로 이 순서를 건너뛸 수 없다.
- 고용비 0/0/100 G, 28일 급여 1000/1200/1400 G, 교육 단계·비용, 이어진 최대 2타임, 빈 근무표에도 급여 누적, 해고 후 교육·누적 급여 유지, 계절 말 정산은 그대로다.

## 저장과 끄기

`PlayerProgress.story_beat_days`에 `employee_recruitment:v1`, `employee_recruitment:met:<직원 ID>`, 이전 저장 호환용 `employee_recruitment:legacy_access:<직원 ID>`를 기록한다. 새 게임은 이 기록을 초기화한다. 방문자의 화면 위치는 저장하지 않고 재시작 시 아직 만나지 않은 다음 지원자를 다시 방문시킨다.

처음 이 기능을 적용할 때 기존 고용·교육·소개·이전 계약·근속 기록을 확인한다. 해당 후보는 다시 인사를 강요하지 않는다. 기존 고용·교육·근속 기록의 교육 접근은 별도 호환 키로 보존하고 실제 첫 출근 장면을 소급 완료하지 않는다. 돈·교육 수준·근무표·급여 기록을 초기화하지 않는다. 이후 저장부터는 새로 계약했다고 교육을 바로 열지 않는다.

`EmployeeStorySettings.recruitment_enabled`를 false로 바꾸면 방문을 끄고 만남·첫 근무에 따른 제한을 해제한다. 방문 간격·재시도 시간·문에서의 거리·상호작용 거리는 같은 설정 리소스에 있다. 현재는 하루 간격, [E] 거리 70이다.

## 글 다듬기 전달

기존 `service_text`의 `worker_001/002/003_intro`, `hired`, `first_shift` 장면을 우선 다듬는다. 새 이름·능력·답례·무료 교육을 약속하지 않는다. 소개는 가게 앞에 찾아와 일할 의사를 전하는 장면, 계약은 비용과 급여를 확인한 선택, 첫 근무는 실제 출근 이후의 경험이다. 설정 리소스의 intro 조건을 이 진행에 맞춰 갱신했다. 새 대사 ID·글 종류·가격을 추가하지 않는다.

기존 자료: [직원 기능과 18장면](직원과_함께하는_가게.md), [관리 책 전체 설계](관리_책의_단계별_설계_방향.md).

## 검증

Godot 4.7.1의 분리된 새 게임 데이터로 검사한다. `dev/scenes/check_employee_recruitment.tscn`은 실제 방문 이동·공통 [E]·미루기/재개·계약·직원별 공개·실제 출근·다음 날 방문·저장 복원·기존 저장 호환을, `check_employee_content.tscn`은 계약 재검사·교육 비용·해고/재고용·급여·18장면 등록을 확인한다. 실제 사용자 저장은 사용하거나 덮어쓰지 않는다.

2026-10-08 결과: 지원자 실제 흐름 50개·직원 고용/해고/급여 57개·튜토리얼 101개·main 통합 88개·글 검사 2종 실패 0. Godot import 2회 종료 0·전체 718개 로드 실패 0. 화면 실행도 지원자 50개 실패 0, 소개·후보·첫 계약 화면을 캡처 확인했고 첫 지원자의 고용 버튼은 스크롤 없이 전부 보이는지 검사했다. 검증 캡처·로그는 저장소 밖에 두었다.

원격 표정 작업과 통합한 `main @ 74e24b5`에서 import 2회·전체 720개 로드·지원자 50개·기존 NPC 표정 연결 13개 검사도 실패 0이다. 인수인계 28·30의 검토 상태를 유지하고 34에 기존 9장면의 진행 맥락 교정을 요청한다.

## 자연스러운 진행 점검 4 (2026-10-09)

직원 책의 다음 행동을 실제 진행 상태에 맞췄다. 바깥 관리 탭 전체 공개는 유지하며, 내부 근무표·교육·정보의 기존 순서를 적용한다.

| 현재 상태 | 화면에서 알려 주는 다음 행동 |
|---|---|
| 가게 튜토리얼 중 | 현재 안내를 따라 직접 계산·첫 원정·재료 판매를 마친다. 아직 없는 지원자를 가게 앞에 있다고 안내하지 않는다 |
| 도입 완료, 지원자 미도착 | 책을 닫고 가게를 돌보며 방문을 기다린다 |
| 지원자가 실제로 도착 | 지원자의 이름과 [E] 인사, 책을 닫아 이동·대화를 이어가는 방법을 표시한다 |
| 고용했지만 근무표가 비었음 | 시간대를 선택하고 근무표 적용을 누른다. 휴무에도 고용한 날의 급여가 누적됨을 안내한다 |
| 근무표 적용 | 실제 시간 범위와 문 열기·담당 시간대 기다리기·출근 중이라는 현재 행동을 구분한다 |
| 실제 첫 출근 후 | 교육 탭을 연다. 교육 실행은 퇴근·하루 정산 뒤 다음 아침 6시 문 열기 전이라는 기존 조건을 따른다 |
| 마지막 직원 해고 후 | 당기 누적 급여가 남으면 정보 탭과 해당 직원 급여 카드를 유지한다. 이전 기간 미지급 급여와 구분한다 |
| 재고용 | 교육을 유지하고 빈 근무표부터 다시 지정한다 |

근무표와 정보 카드의 시간은 `EmployeeData.get_period_at_hour()`에서 가져온다. 현재 아침 06~12시·낮 12~18시·저녁 18~24시·심야 00~06시이며 저녁과 심야도 이어진 조합이다. 변경 불가 시간에는 조회만 가능함과 다음 정비 시간을 표시한다. 급여 표기는 달 대신 실제 급여 기간과 `CalendarData.DAYS_PER_SEASON`을 사용한다.

`EmployeeNextStepGuide`는 안내와 조회만 담당한다. `ENABLED=false`로 기존 안내·정보 공개 조건으로 돌아갈 수 있다. 고용·근무표·교육·퇴근·급여 정산의 실제 조건과 비용, 이야기 18개, 기존 저장 형식은 변경하지 않았다. `worker.gd`, `day_manager.gd`, `game_state.gd`와 새 게임 데이터·이미지는 수정하지 않았다.

### 검증과 후속 문구 이전

`dev/scenes/check_employee_next_steps.tscn`을 사용자 저장과 분리한 foodbag_checks 프로젝트에서 실행했다. 튜토리얼 완료·시간 이동·교육 자금은 검사 시작 조건으로 마련했으며, 실제 지원자 인사·책 버튼·저녁/심야 근무표 적용·첫 출근·실제 퇴근·다음 날 교육·해고·급여 스크롤·전체 저장 복원·재고용을 실행했다. 실제 출근·퇴근 상태를 검사 코드로 강제 완료하지 않는다. 신규 63개 헤드리스/GPU, 지원자 50개·직원 57개·원정 전 가게 운영 136개·main 통합 88개 실패 0. 초기 전체 로드 818개 통과 뒤 최신 UiText 패치와 통합해 import 2회·전체 821개·UiText 5개·main 88개·신규 63개 헤드리스/GPU를 재검증했다. SCRIPT ERROR 0, UI 키 검사 종료 0. 화면에서 초반 안내·시간대·교육·해고 후 급여 금액까지 스크롤을 확인했고 로그·캡처는 저장소 밖에 두었다.

작업 도중 동기화된 `d7b5266`의 `UiText`와 관리 책 설명 7개 CSV 이전을 보존했다. 이번 직원 안내의 CSV 이전은 담당 Claude에게 기존 인수인계 28·30의 후속으로 전달한다. 안내 분기·실제 조건은 코드에 두고 문구·서식만 기존 `data/ui/ui_text.csv`/`UiText`로 옮긴다. 키 제안은 `management.employee.guide.*`(튜토리얼/대기/방문/빈 근무표/첫 근무/정비/정보), `management.employee.period`, `management.employee.salary.*`다. 원본은 `employee_next_step_guide.gd`와 `management_employee.gd`의 해당 안내·시간/급여 표기이며, 이름·시간·금액 서식을 보존한다. 새 CSV 키는 아직 사용하지 않으므로 누락 키 경고는 없다. 경제 수치·직원 이름·이야기 조건은 별도 검토를 유지한다.

다음 자연스러운 진행 점검은 원정 지역 선택→준비→이동·기본 공격→복귀 흐름이다.
