# 공간을 마련한 뒤의 첫 사용

2026-10-08 · 사용자 「다음 콘텐츠 보강」에 따라 관리 책의 건설 화면에서 실제 방 사용의 다음 행동을 안내한다. 기존 편의점 → 생산실 → 창고 → 확장의 진행과 제공 물품·제조법·재료·확장 비용을 사용한다.

## 생산실

문 설치 직후에는 먼저 문에서 [E]로 들어가도록 안내한다. 입장 후 화덕이 없다면 소지한 화덕을 건축 모드 [B]로 설치한다. 소지하지 않았다면 현재 화덕 제작 정보로 연결한다. 미리보기·철거 대기 노드·다른 방의 설비는 첫 생산실 설비로 세지 않는다.

실제 화덕이 있으면 배운 첫 제조법과 소지 재료를 확인한다. 부족분은 기존 제조법의 재료 수량을 사용하고, 보관 중인 재료를 꺼내야 한다고 안내한다. 첫 제조법이 없는 저장에는 배운 상품과 타블렌의 기존 안내를 확인하도록 한다. 다른 미습득 상품을 소개하지 않는다.

| 현재 상태 | 다음 행동 | 안내 버튼 |
|---|---|---|
| 화덕 미설치·보유 | 생산실에서 보유 화덕 배치 | 가구 보관함 |
| 화덕 미설치·미보유 | 현재 제조 재료와 조건 확인 | 화덕 제작 상세 |
| 화덕 설치·재료 부족 | 표시한 부족분 준비 | 오늘의 준비 |
| 화덕 설치·재료 준비 | 현장 화덕 [E]로 첫 상품 만들기 | 오늘의 준비 |
| 화덕 가공 중 | 책을 닫고 가공을 마침 | 설비 현황 |
| 완성품 수령 대기 | 같은 화덕 [E]로 실제 수령 | 설비 현황 |

화덕이 여러 대면 수령 대기인 완성품을 먼저 안내한다. 하나가 가공 중이어도 다른 화덕과 재료가 준비되어 있으면 제작을 안내한다. 가공 시작·완료와 실제 수령을 구분하며, 현지식 빵의 기존 실제 수령 신호가 발생해야 창고 준비로 넘어간다. 책을 연 동안 게임과 가공이 멈추는 현재 정책을 설명한다.

## 창고

문 설치 뒤 실제 입장을 먼저 안내한다. 선반이 없다면 현재 가진 종류를 우선한다. 옛 저장의 기존 선반도 사용하며, 없으면 현재 제작 가능한 나무 창고 선반으로 연결한다. 옛 제작법 없는 선반을 새로 만들라고 요구하지 않는다.

선반 설치 후에는 실제 설치 수와 보관량/전체 용량을 표시한다. 가득 찬 경우 먼저 물품을 꺼내 입고할 자리를 마련하도록 안내한다. 소지 물품이 없으면 거래·원정이나 기존 창고에서 꺼내기를 안내한다. 여유가 있으면 소지 물품을 하나 이상 실제 입고하도록 한다. 슬롯이 찼을 때 같은 물품 추가 입고나 기존 물품 꺼내기를 설명한다.

설치·빈 입고·꺼내기·안내 읽기를 첫 입고로 기록하지 않는다. 실제 창고의 성공한 입고가 기존 확장 조건을 만족한다. 일반 선반은 재고 정리용이며 냉장·냉동 보존과 구분한다. 사용 경험 이후에는 기존 확장 화면과 실제 가격·오전 준비 시간 제한으로 돌아간다.

## 화면·저장·담당

건설 화면의 기존 왼쪽 현재 상태 / 오른쪽 다음 행동·버튼을 재사용한다. 이번 안내 버튼은 설계도·가구 보관함·배운 상품·오늘의 준비·설비 현황을 연다. 현장 이동·배치·재료 소비·가공·수령·입고를 원격 실행하지 않는다. 클릭 시 현재 상태를 다시 읽는다.

안내는 실제 방 노드와 기존 진행 기록을 읽고 새 저장 필드나 대사 ID를 추가하지 않는다. 이전 저장에 새 공간 진행을 소급 적용하지 않는다. `RoomPreparationGuide.ENABLED`를 false로 설정하면 기존 고정 안내로 돌아간다. 가격·보상·신규 집기·이미지·NPC 설정은 추가하지 않는다.

구현: `script/ui/management/room_preparation_guide.gd`와 `shop_space_construction.gd`의 작은 연결. 검사: `dev/scenes/check_room_preparation.tscn`의 실제 문 설치·E 입장·화덕 설치·실제 생산과 수령·창고 선반 설치와 입출고·책 버튼·현재 저장 복원. 사용자 저장을 불러오거나 덮어쓰지 않는다.

관련: [공간 진행](편의점에서_공간을_넓히는_순서.md), [상품 준비](상품을_준비하는_관리_책.md), [집기 안내](집기를_고르는_사용_안내.md).

실제 화면 검사에서 빠른 탭 이동 중 기존 책 넘김 연출이 두 프레임 기다린 뒤 이미 교체/해제된 포스트잇 뷰포트를 사용하는 오류를 발견했다. `management_presentation.gd`의 넘김/끌기에서 캡처 소유 노드가 아직 현재 연출인지 확인하고 취소된 연출을 중단한다. 새 안내 링크의 빠른 이동과 책 닫기에도 기존 화면·시간·재고 동작을 유지한다.

## 2026-10-09: 실제 다음 행동과 제작 안내 점검

현재 `UNLOCK_ALL_TABS=true`로 탭은 초반부터 보인다. 실제 공간 사용은 **편의점 → 생산실 → 창고 → 확장** 순서이며, 탭을 읽는 것만으로 공간이나 제조법이 열리지 않는다.

- 첫 제작 안내 전에는 생산 책에 기본 건조 제조법의 재료 목록부터 보여 주던 부분을 현재 가게 진행 안내로 바꿨다. 핵심 안내 중에는 진열·직접 계산, 완료 후에는 이웃 부탁·타블렌 정착, 정착 뒤에는 실제 첫 제작 안내를 가리킨다.
- 타블렌이 준 현지식 빵 제조법은 두루마리다. 아직 배우지 않았다면 생산 책에서 인벤토리의 ‘배우기’를 안내한다. 화덕을 설치한 건설 화면에서도 ‘제조법 두루마리 보기’로 실제 물품 분류를 열 수 있다. 클릭은 자동 학습이 아니며 기존 확인창에서 두루마리 한 개를 소비한다.
- 미설치 설비에 바로 [E] 사용을 안내하던 문구를 생산실 마련 → 직접 입장 → 보유 설비 배치 또는 설계도 확인으로 나눴다. 가공 중에는 책을 닫고 기다리도록 안내한다. 책을 열어 둔 동안 가공도 멈추는 기존 동작을 설명한다.
- 주민 부탁의 ‘창고 기준/창고로 옮기기’는 ‘소지품 기준/소지품에 챙기기’로 맞췄다. 물리 창고 건설은 초반 물품 전달의 선행 조건이 아니다. 진열대나 보관 선반의 물건은 꺼내야 한다.

새 안내 모듈은 `script/ui/management/product_next_step_guidance.gd`이며 `ENABLED=false`로 앞선 생산 책 안내로 돌아간다. 단계별 화면 안내만 바꾸며 CSV의 가격·재료·보상, 실제 제조법 접근 조건, 지급량, 공간 해금 조건, 저장 필드와 기존 저장은 유지한다. NPC 알림에 덧붙이던 기존 기능 설명을 다듬었으며 새 글 종류·장면 ID는 추가하지 않았다.

검증: 공간40·첫 사용50·생산67·주민 부탁·초반 도구52·main88 헤드리스 통과. GPU 생산67·첫 사용95 통과. ‘제조법 두루마리 보기’를 실제 마우스 입력으로 눌러 올바른 인벤토리 분류로 이동했고, 기존 확인창에서 정확히 한 개를 소비하며 재확정은 추가 소비하지 않았다. 실제 문 설치/입장/화덕 설치/제작·수령/창고 입고/확장과 기존 저장을 확인했다. import2회 종료0·전체815 로드 실패0·원정16/16 완료(104단계, stuck0)·SCRIPT ERROR0. 기존 누락 아이콘·Collision 경고는 별개로 남는다.

실행은 [별도 사용자 저장 프로젝트](원정_가방에서도_이어지는_식품_기한.md)에서 했다. 화면과 로그는 저장소 밖 `output/natural-*`에 있다. 첫 가게 도입 전체를 사람이 연속 조작한 검사는 아니며, 각 실제 서비스·진행·UI와 자동 원정 검사를 사용했다. 코드 `main @ 7220dc5` 푸시 완료. 받은 `3fd56e4`는 문서용 마법 오븐 후보17장만 추가했고 실행 코드·데이터 변경은 없었다.

다음 점검은 직원 도입 → 고용 → 근무표 → 실제 근무 → 교육·해고의 설명과 조건이다.
