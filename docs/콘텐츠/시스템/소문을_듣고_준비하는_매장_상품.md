# 소문을 듣고 준비하는 매장 상품

2026-10-08 콘텐츠 보강. 관리 책의 **일정** 탭에서 들은 이야기와 실제 상품 준비를 함께 살핀다.

## 플레이 흐름

1. 손님 또는 기존 낚시 행사 인물에게 소문을 듣는다.
2. 일정 탭에서 기존 이야기와 그 소문에 나온 상품의 준비 메모를 읽는다.
3. 소지 상품은 진열대에 보충하고, 창고·냉장·냉동 상품은 해당 보관함에서 꺼낸 뒤 진열한다.
4. 배운 제조법의 상품은 메모의 **상품 준비 · 상품명** 버튼으로 생산 탭의 해당 제조법을 확인한다.
5. 설비에서 직접 가공·수령하고 진열한다. 손님은 기존 구매·결제 규칙을 따른다.

기간·배율·권장 준비 수량이나 예상 매출은 추가하지 않는다. 소문 본문과 준비 재료에 대한 기존 대사를 유지한다. 진열했다고 판매를 보장하지 않는다.

## 공개 조건

- 이미 들은 **현재 회차**의 소문이며, 그 회차의 소문 시작부터 행사 종료일까지 안내한다.
- 현재 장면의 `cue_items`가 없으면 기존 소문 장면의 상품을 사용한다.
- 상품은 기존 아이템 카탈로그에서 판매 가능한 항목만 사용한다.
- 작년·지난 주기의 소문은 다음 회차 준비 안내로 자동 전환하지 않는다. 기존 지난 이야기와 영업 기록은 남는다.
- 낚시 행사는 기존 선행·인물·배운 제조법 조건과 `StoreEventStory.moment()`의 상품 공개 조건을 그대로 따른다.
- 제조법 이동 버튼은 배운 해당 완성품 제조법과 생산 탭의 공개 조건을 만족할 때만 나온다. 원재료에 없는 제조법을 만들거나 미래 상품·제조법을 알려 주지 않는다.
- 기존 전체 탭 공개 스위치는 변경하지 않는다.

## 재고와 행동

| 표시 | 의미 | 다음 행동 |
|---|---|---|
| 진열 | 현재 월드의 실제 진열대 슬롯 재고 | 판매·손님 수령 뒤 실제 보충 |
| 소지 | 기존 GameState 소지 재고 | 진열대에 보충 |
| 창고 선반 | 현재 월드의 실제 창고 선반 재고 | 선반에서 출고한 뒤 진열 |
| 냉장·냉동 | 기존 설치된 보관함의 상품 재고 | 보관함에서 출고한 뒤 진열 |

- 보관량을 진열량이나 소지량에 더하지 않는다.
- 건설 미리보기, 삭제 대기 노드와 다른 월드의 진열대·창고 선반은 집계에서 제외한다.
- 손님이 이미 가져간 상품은 진열 재고에서 빠진다. 결제 전 물품을 판매 완료로 표시하지 않는다.
- 식품은 기존 유통기한 정산을 통해 기한이 지난 상품을 제외하고, 기한을 보며 조금씩 보충하라는 메모를 표시한다. 이 조회는 기존 정산·이전 저장의 배치 보완을 수행할 수 있다.
- 일정을 열어 둔 동안 준비 메모를 갱신한다. 관리 책의 기존 시간 정지 정책을 따른다.
- 안내 열기·제조법 이동은 상품 제작, 보관 출고, 판매, 부탁 완료, 보상 지급을 수행하지 않는다.
- 제조법 이동 시 이전의 '지금 만들 수 있는 상품만' 필터를 해제하고 배운 상품 화면에서 해당 제조법을 선택한다. 재료·설비 부족 여부는 그 화면의 기존 안내에서 확인한다.

## 화면과 연결

기존 소문 카드 다음에 별도의 준비 카드를 둔다. 현재 책의 두 쪽 배치·스크롤·ESC 닫기를 사용하므로 이야기에 긴 재고 설명을 덧붙이지 않는다. 여러 소문이 있으면 각 카드에 같은 이야기 제목을 붙여 구분한다.

- `script/ui/management/store_event_preparation.gd`: 상품 공개·실제 재고·배운 제조법 조회.
- `script/ui/management/store_event_preparation_view.gd`: 일정 준비 카드와 제조법 이동.
- `management_menu.gd`: 기존 일정 카드 작성 뒤 연결 한 줄.
- 되돌리기: `StoreEventPreparation.ENABLED = false`. 기존 일정 이야기와 영업 기록만 표시한다.

새 행사·상품·가격·수요·보상·대사 ID·CSV·저장 필드·이미지는 추가하지 않았다. 기존 19개 매장 행사와 지난 영업 기록을 사용한다.

독립 새 게임 검사 `res://dev/scenes/check_store_event_preparation.tscn`로 실제 소문 발견·제조법 버튼 입력·진열대 보충/수령·창고/냉장 입고·자동 표시 갱신·기한 경과·연례/공용 회차·낚시 공개 조건·기존 소문 저장 복원·ESC 닫기를 검사한다. 사용자 저장을 읽거나 덮어쓰지 않는다.

### 준비 안내의 빈틈 보강

기존 메모는 상품 재고와 배운 제조법이 없으면 「상품을 마련한 뒤 진열」만 표시했다. 이미 가진 두루마리를 써야 하는지도 알기 어려웠다. 새 `StoreEventNextStepGuide`가 **진열·소지·창고 선반·냉장·냉동 어디에도 해당 상품이 없는 경우에만** 다음 행동을 덧붙인다.

| 실제 상태 | 다음 행동 |
|---|---|
| 해당 완성품의 미학습 두루마리를 소지 | 실제 보유 두루마리 이름과 인벤토리의 ‘배우기’ 안내 |
| 배운 해당 상품 제조법이 없음 | 얻은 두루마리 사용/이웃 교류로 천천히 준비, 이번에는 다른 상품부터 진열해도 됨 |
| 배운 제조법이 있고 생산 도입이 아직 | 기존 가게·타블렌 제작 도입 안내 유지 |
| 배운 제조법이 있지만 생산실 미마련 | 생산실 마련 뒤 설비 가공 안내 |
| 배운 제조법과 도입 조건이 갖춰짐 | 생산 탭의 배운 상품에서 실제 재료/설비 확인, 책을 닫고 설비에서 가공·수령 |
| 원재료 등 완성품 제조법 자체가 없음 | 기존 상품 확보 안내 유지, 없는 제조법을 안내하지 않음 |

상품을 이미 보유/진열했으면 기존 보충 안내가 먼저다. 보관한 상품은 제조보다 현장 출고를 안내한다. 미래 제조법의 재료·시설·위치를 새로 공개하거나, 소문만 듣고 제조법/상품/생산실을 지급하지 않는다. 실제 보유 두루마리 이름만 추가로 확인한다.

UiText 문구4행 추가. 기존 행사19개·날짜·수요·가격·보상·대사 ID·이미지·저장 구조는 변경하지 않았다. `StoreEventNextStepGuide.ENABLED=false`면 기존 준비 메모를 유지하고 이번 다음 행동 안내만 끈다. 관리 책 전체 탭 공개와 편의점→생산실→창고→확장 순서도 그대로다.
