# 원정 가방에서도 이어지는 식품 기한

현행 구현: `main` @ `f51e657` (2026-10-09, 푸시 완료).

## 1. 플레이 규칙

식품은 다른 보관 장소로 옮겨도 원래 기한이 이어진다. 먼저 얻은 재고와 나중에 얻은 재고를 섞어도 각각의 취득일과 상태를 유지한다.

- 원정 가방은 기존 **상온 보관** 속도를 적용한다. 냉동고처럼 기한을 멈추는 공간이 아니다.
- 가방 → 임시 전리품 → 가방 이동, 격자 이동·회전, 복귀 정산, 저장·재개에서 기한을 새로 시작하지 않는다.
- 복귀 때 만료된 배치는 폐기하고 살아 있는 수량만 소지품으로 옮긴다. 다시 정산해도 물품이나 폐기량이 늘어나지 않는다.
- 냉동고에서 꺼낸 식품을 가방으로 옮기면 기존 나이를 가진 채 상온 변화가 다시 이어진다.
- 튜토리얼 유예와 상온·냉장·냉동 속도, 할인 시점·비율은 기존 식품 규칙을 사용한다.
- 시간은 기존 게임 날짜 정산을 따른다. 원정 실시간이나 플레이어 이동에 별도 기한 타이머를 붙이지 않는다.

결과창의 선택형 물품 활용 안내에는 기한 유지와 가방의 상온 보관을 짧게 알려 준다. 배치마다 관리 버튼을 만들거나 남은 날짜를 추정해 표시하지 않는다.

## 2. 실제 적용 범위

현행 원정 준비 화면의 소지품 ↔ 가방 이동은 **개별 장비**에 한정돼 있다. 이번 보강은 새 식품 포장·사용 UI를 추가한 작업이 아니다. 현재 식품 데이터 중 가방 크기와 수납 정책을 갖춘 대상은 생선 12종이며, 해당 데이터가 가방·전리품에 들어 있는 경로를 검증했다. 초기 빵과 물이 준비 화면에 새로 나타난다는 뜻은 아니다.

장비의 개별 ID·강화 단계, 광석의 대장장이 진행 기록, 기존 자동 보관/가방 유지 정책은 그대로다. 낚시를 원정으로 옮기거나 새 식품·보상·수요를 추가하지 않았다.

## 3. 이동·저장 정합성

| 경로 | 처리 |
|---|---|
| 가방 생성/복원 | 기존 `food_batches`를 검증하고 깊은 복사. 기록이 없는 옛 배치만 현재 날짜부터 채택 |
| 격자 간 이동 | 원본 메타데이터를 함께 전달. 목적지 배치 실패 시 원본 유지 |
| 가방 ↔ 임시 전리품 | 식품 배치와 장비/광석 메타데이터를 보존. 전리품으로 옮길 때 격자 UID·셀·회전만 제거 |
| 복귀 정산 | 먼저 전체 배치를 검증하고 기한 정산 후 남은 실제 수량을 `GameState.add_item`에 배치와 함께 전달 |
| 실제 원정 중 | 살아 있는 가방과 임시 전리품, 진행 중인 방의 대기 전리품이 재고의 주인 |
| 저장본·체크포인트 | 실제 재고의 복사본도 날짜를 갱신하되 폐기를 중복 집계하지 않음. 원정이 없으면 재개할 체크포인트 또는 저장 가방이 기준 |
| 잘못된 식품 기록 | 수량 불일치·음수 나이·미래 취득일·잘못된 자료형을 거부. 새 식품으로 조용히 대체하지 않음 |

기존 배치 형태 `{amount, age, day}`를 가방 placement에도 선택적으로 싣는다. 루트 저장 필드·저장 버전·체크포인트 형식은 바꾸지 않는다. 누락된 옛 기록은 현재부터 적용하므로 과거 일수를 추정해 소급 폐기하지 않는다.

새 기능은 [ExpeditionFoodBatches](../../../script/expedition/services/expedition_food_batches.gd)에 분리했다. 원정 본체에는 재고 소유 노드 등록 1줄, 기존 식품 서비스에는 정산·저장 검증 연결만 추가했다. `ExpeditionFoodBatches.ENABLED = false`로 새 연결을 끌 수 있다. 원래 문제였던 복귀 기한 초기화까지 복구되는 점을 고려해 되돌린다.

## 4. 검증

[검증 씬](../../../dev/scenes/check_expedition_food_batches.tscn)은 **112개 헤드리스/GPU 실패 0**. 다른 취득일을 가진 재고, 할인 가격, 만료·폐기, 이동 실패 원본 유지, 12종 식품 정산, 실제 전리품 왕복, 냉동 후 출고, 튜토리얼 유예, 이전 저장, 잘못된 기록의 원자적 거부, 실제 체크포인트 파일 저장·재개를 확인했다. 실제 결과창 1152×648 캡처에서 긴 안내와 고정 복귀 버튼도 확인했다.

기존 식품153·보존66·복귀 안내178·인벤토리53·메인88 실패0. 최종 import2회 종료0·SCRIPT ERROR0, 전체815 로드 실패0·원정16/16 완료(104단계, stuck0). 푸시 전 Claude의 함수 정리 `d107600`과 그림 후보를 보존하고 통합했다. 통합 뒤 import2회·전체810 로드 실패0·신규112/복귀178/인벤토리53/메인88·원정16/16 통과, SCRIPT ERROR0을 다시 확인했다. 전체 대상 감소는 upstream의 미사용 파일 삭제 때문이다. 기존 번역 Unicode NUL 메시지·생선 아이콘 경고는 이번 범위 밖이다.

### 검사를 다시 실행할 때

검사는 **별도 사용자 저장 폴더를 쓰는 테스트 프로젝트**에서 실행한다. 복사한 프로젝트의 `project.godot` `[application]` 아래에 다음 설정을 적용하고 기존 설정은 유지한다.

```ini
config/name="project222_foodbag_checks"
config/use_custom_user_dir=true
config/custom_user_dir_name="project222_foodbag_checks"
```

그 프로젝트에서 import 후 `godot --headless --path <테스트 프로젝트> res://dev/scenes/check_expedition_food_batches.tscn`을 실행한다. 새 검사는 사용자 경로에 `foodbag_checks`가 없으면 파일 검사 전에 중단한다. 일반 개발 프로젝트에서 기존 일괄 검사에 포함해 실행하면 이 보호 검사에 걸리므로 테스트 프로젝트를 사용한다. 실제 체크포인트 저장도 별도 테스트 파일에 기록한다.

이번 실행은 저장소 밖 `output/food-bag-runtime`에서 진행했고 사용자 실제 저장은 쓰지 않았다. 로그·캡처는 `output/food-bag-*.log`·`output/food-bag-gpu-return.png`에 있다. 식품 기록 없이 돌아오는 기존 정산 문제는 해결했으며 인수인계44에 기존 안내 검토와 함께 묶었다.
