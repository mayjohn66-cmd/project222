# 편의점에서 공간을 넓히는 순서

2026-10-07 사용자 결정: **편의점 → 생산실 → 창고 → 확장** 순으로 배우고 사용한다. 아직 마련하지 않은 공간의 확장 가격·크기부터 설명하지 않는다.

## 1. 실제 진행

| 단계 | 열리는 조건 | 지금 할 일 | 다음으로 넘어가는 실제 행동 |
|---|---|---|---|
| 편의점 | 새 게임 시작 | 가져온 식품 진열, 직접 계산, 첫 원정, 원재료 판매 | 기존 핵심 튜토리얼과 타블렌 노점 정착 |
| 생산실 준비 | 기존 타블렌의 선택 제작 안내 | 안내 완독 후 건설 메뉴에서 생산실 문 배치 | 가게 벽에 보유한 문을 실제 설치 |
| 생산실 사용 | 생산실 문 설치 성공 | 문에서 E로 입장, 화덕 설치, 현지식 빵 제작·수령 | 기존 생산 완료품 수령 신호 |
| 창고 준비 | 생산실을 마련하고 현지식 빵을 실제 수령 | 건설 메뉴에서 창고 문 배치 | 가게 벽에 보유한 문을 실제 설치 |
| 창고 사용 | 창고 문 설치 성공 | E로 입장, 창고 선반 설치, 남은 재료 보관 | 실제 창고 안 선반에 재료 입고 성공 |
| 확장 | 창고 사용 경험 기록 | 편의점·생산실·창고 크기 확장 선택 | 기존 오전 6시 준비 시간·자금 조건과 확장 비용 사용 |

타블렌 제작 안내는 첫 원재료 판매와 주민 정착 이후의 **선택 안내**를 유지한다. 생산실이나 창고를 마련하도록 핵심 첫 거래·첫 원정을 막지 않는다. 기존 소개에서 화덕·현지식 빵 제조법·밀을 받고, 직접 제작해 수령하는 행동이 필요하다. 시작 빵을 갖고 있거나 구매한 것만으로 다음 공간이 열리지 않는다.

## 2. 공간 마련과 확장 구분

- 초기에는 생산실·창고의 실제 씬을 숨기고 입장을 거절한다. 문을 설치하기 전에는 공간이 활성화되지 않는다.
- **생산실 문 배치 / 창고 문 배치** 버튼은 기존 건축 모드에서 보유한 해당 문의 미리보기를 선택한다. 책 닫기 연출이 끝난 뒤 건축 모드로 넘어가며, 기존 퀵슬롯은 덮어쓰지 않는다.
- 미리보기를 고르거나 취소한 것만으로 공간을 마련했다고 기록하지 않는다. 문 설치가 성공하여 기존 보유 수량이 차감된 후에만 기록한다. 미래 단계의 문 배치와 제작도 차단한다.
- 처음 함께 온 문의 보유 수량을 사용한다. 문을 사용해 버렸다면 기존 설계도의 재료 제작으로 확보한다. 새 방 설치 대금이나 무료 문 지급을 추가하지 않았다. 기본 방 크기는 기존 씬과 데이터를 사용한다.
- 생산 설비는 마련한 생산실에, 창고 선반은 마련한 창고에 설치한다. 새 게임에서 화덕을 편의점에 바로 설치하여 생산실 단계를 건너뛰지 않는다. 기존 저장의 설치 규칙은 소급 변경하지 않는다.
- 창고에 실제로 들어가 선반에 입고해야 확장을 소개한다. 실패한 입고·수량 0·미리보기·다른 곳의 선반은 조건을 충족하지 않는다.
- 일반 소지 재고는 창고 마련 전에도 진열·제작에 사용한다. 물리적인 창고 선반 보관은 별도이며, 선반의 재료는 꺼내서 사용한다.
- 공간 마련 단계에는 확장 단계·가격·다음 크기를 표시하지 않는다. 확장 공개 후에는 기존 UI와 경제 값을 사용한다. 확정 시 진행 조건과 준비 시간을 재검사한다.

## 3. 설비·치장·건축 설명과 노출

- 핵심 튜토리얼 중에는 생산·직원·건설 책갈피를 숨긴다. 직접 탭을 요청해도 잠긴 화면 대신 인벤토리로 돌아간다. 직원 탭은 핵심 안내 완료 후 열리며, 첫 지원자를 만나는 별도 사건은 이번 공간 작업에서 추가하지 않았다.
- 설계도는 초반에 편의점 집기 분류부터 시작한다. 타블렌 제작 안내 뒤 생산 설비와 공간용 문, 실제 첫 상품 수령 뒤 추가 설비와 치장, 창고 마련 뒤 보관 선반이 차례로 나타난다.
- 가구 인벤토리와 건축 가방·퀵슬롯에서도 아직 사용할 수 없는 집기를 숨긴다. 보유 수량은 삭제하지 않고 미래 단계에서 다시 보여 준다. 키보드 퀵슬롯 선택·제작·실제 배치도 같은 조건을 사용한다.
- 첫 제작에는 화덕을 먼저 보여 주고, 빵을 수령하면 음료 제조기를 포함한 다음 설비를 보여 준다. 생산 현황의 미설치 카드도 같은 조건을 사용한다.
- 설계도 설명에 설비는 어디서 가공하는지, 문은 어떤 공간을 연결하는지, 선반은 입출고를 어떻게 하는지, 치장은 어디에 배치하며 실제 효과를 어디서 확인하는지 안내한다.
- 이번 보완은 기존 종류의 용도와 공개 순서에 집중했다. 새 설비·치장 종류, 이미지, 수치 보너스, 건설 대금은 추가하지 않았다. 새로운 집기 종류는 이 진행 단계에 배정하여 확장하면 된다.

## 4. 저장 호환과 파일

새 게임의 기존 부트스트랩에서 `shop_space:v1`을 기록한다. 공간·입장·첫 입고는 `PlayerProgress.story_beat_days`의 `shop_space:*` 키로 기존 저장 경로에 함께 저장한다. 새 게임에서는 이전 기록이 초기화된다.

공간을 사용하지 않은 현재 도입 튜토리얼 저장도 관리 화면에서 새 순서를 적용한다. 이미 제작 안내를 받았거나, 문·부속 공간 배치가 있거나, 공간 크기를 확장한 이전 저장에는 새 잠금을 소급하지 않는다. 이전 저장의 수량·공간·급여·제조법·돈을 초기화하지 않는다.

주요 새 파일:

- `script/world/shop/progression/shop_space_progression.gd`: 조건, 저장 키, 준비 안내, 실제 공간·입고 기록.
- `script/ui/management/shop_space_menu.gd`: 현재 진행에 맞춘 메뉴·가방·설계도 갱신.
- `script/ui/management/shop_space_construction.gd`: 방 마련 안내와 기존 확장 화면 분리.
- `dev/scenes/check_shop_space_progression.tscn`: 실제 게임 씬·문 설치·출입·제작·입고·확장 검사.

기존 큰 파일 중 `build_manager.gd`에는 배치/퀵슬롯 조건 확인 2줄만 연결했다. `game_state.gd`·`worker.gd`·`day_manager.gd`와 메인 씬은 수정하지 않았다. 새 NPC 대사, CSV 경제 값, API 호출과 이미지 변경은 없다.

## 5. 검증

Godot 4.7.1, 사용자 저장과 분리된 환경:

- 새 진행 **40개 검사 실패 0**: 조기 탭 접근·문 제작/배치 차단, 실제 문 설치와 수량 차감, 실제 E 출입, 생산실 화덕 설치·밀 소비·빵 제작/수령, 창고 선반 입고, 중간/전체 저장 복원, 이전 저장 유지, 새 게임 초기화, 확정 시 시간 재검사, 기존 5000 G 확장 실제 적용.
- 화면이 있는 실행도 **40개 실패 0**. 초기 책갈피·생산실 준비·창고 준비·확장 화면을 각각 캡처하여 내용과 버튼 위치를 확인했다.
- 기존 핵심 튜토리얼 85개, 직원 54개, main 콘텐츠·3D 통합 88개 실패 0. 직원 검사는 핵심 안내를 마친 상태에서 기존 고용·해고 흐름을 검증한다.
- import 2회 종료 코드 0, 전체 681개 스크립트·씬 로드 실패 0. 기존 로컬 인증서·일부 문 Collision 경고와 기능 오류를 구분했고 최종 검사에 Script/Parse 오류는 없다.
