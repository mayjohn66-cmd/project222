# 이야기 원본 위치 지도

> 외부 작가(Gemini 등)에게 2·3막 이야기를 다시 쓰게 할 때 "어디를 주면 되는지" 한눈에 보기 위한 문서. 2026-10-12 기준.
> 위치는 파일 목록·키 이름·문서 언급을 기계적으로 훑어 만들었다. 각 파일이 이야기에서 정확히 무슨 역할인지는 하나씩 열어 검증하지 않았다.

## 1. 이야기는 세 층으로 나뉘어 있다

| 층 | 무엇이 들어 있나 | 어디에 |
|---|---|---|
| ① 글 | 제목·요약·대사·완료 문구. 한 행 = 한 항목, 대사는 `\|`로 줄 구분. 줄 앞 `*`(서술)·`{표정}`(초상화 표정) 표시가 있다 | `data/shop/requests/requests_text.csv` (556행) |
| ② 구조 | 어떤 이야기가 **언제**(계절·날씨·선행 이야기·평판·재료·보상) 나오는지, 단계 순서, 글을 부르는 키(`title_id` 등) | `scenes/**/default_*.tres` (아래 3장) |
| ③ 설계 문서 | 기획 의도·흐름·검토 기록 | `docs/콘텐츠/` (README의 표가 현행/구 기록을 구분) |

**글만 바꿀 때**는 ①만 고치면 된다. 이야기 **순서·조건·개수**를 바꾸거나 새 이야기를 넣을 때는 ②와 코드 연결(`*_flow.gd`)이 같이 바뀐다. 이전 합치기 규칙은 `docs/콘텐츠/README.md` 8장과 `tools/merge_story_csv.py`.

## 5. 외부 작가에게 넘길 묶음 (제안)

1. **필수**: `data/shop/requests/requests_text.csv` — 기존 글과 `*`, `{표정}` 표기법(설명: `docs/그림_작업/주인공_초상화.md` 6장, `script/data/story/dialogue_marks.gd` 머리말).
2. **필수**: 다시 쓸 막의 `docs/콘텐츠/<막>/` 문서 전체 — 이야기가 언제 나오는지와 의도.
3. **조건·순서까지 바꿀 때만**: 3장의 해당 `.tres`. 글만 바꾸게 한다면 줄 필요 없다.
4. **주의 전달**: 줄 수를 바꾸면 연출·테스트가 어긋날 수 있다(프롤로그가 대표). 새 id를 만들면 코드 연결이 따로 필요하다. 주인공 대사에만 `{표정}`을 쓰고 NPC 줄은 무시된다.

## 6. 결과를 되돌려 받을 때

탭으로 구분한 6열(`id, kind, title, summary, lines, completion`) 표로 받아서 `python tools/merge_story_csv.py 파일.tsv`로 먼저 점검한다.
