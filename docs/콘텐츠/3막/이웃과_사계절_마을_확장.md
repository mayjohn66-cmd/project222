# 이웃과 사계절 마을 확장

## 구현 범위

사용자 요청으로 제안했던 8개 분야를 모두 플레이 가능한 콘텐츠로 연결했다. 신규 이야기 **24개/대사 단계 69개**, 정착 주민 **2명**, 제작 상품 **2종**, 실제 매장 계절 수요 행사 **4개/소문·구매 반응 24장면**이다. 주민 안부 2행까지 포함해 대사 CSV는 298→**393행**이다. 기존 콘텐츠에 추가하며 main에서 진행한다.

정식 이름/말투 파일을 새로 만들거나 바꾸지 않았다. 새 이웃은 기존 야영 요리사·채집가의 직업 호칭과 기존 3D 외형을 사용한다. 대사는 Gemini가 다듬을 러프 초안이다.

## 실제 진행

첫 거래·원재료 판매와 기존 주민 정착 후 **기존 마을 게시판**에 카드가 나타난다. 잠긴 카드는 앞선 이야기, 제조법, 교류, 계절 조건을 표시한다. 수첩은 맡기 전 게시판, 맡은 뒤 실제 주민이나 모임 장소로 안내한다.

1. 게시판에서 이야기를 직접 맡는다. 수락만으로 재고나 보상을 바꾸지 않는다.
2. 해당 주민 가까이에서 E로 대화한다. 그날의 첫 안부를 아직 나누지 않았다면 기존 안부가 먼저 나온다.
3. 전달은 보통 창고의 설정 품목만 사용한다. 게시판에서 전달하는 기존 개인 부탁과 달리 새 연속 이야기는 지정 주민 E 대화의 **최종 완독**에서 전달한다.
4. 다음 날 단계는 앞선 단계의 실제 완료일부터 계산한다. 읽다 닫거나 준비 안내만 완독하면 진행하지 않는다.
5. 마지막 단계 완독 때만 최종 대금·답례·평판을 기록한다. 중간 전달은 미리 소비하고 최종 대금은 마무리에 받는다는 안내를 표시한다.

맡은 이야기는 계절·해가 바뀌어도 유지된다. 상품 시제품은 소개 후 실제 생산 설비의 제작·수령 기록과 창고 재고가 모두 필요하다. 재고만 넣거나 제조법만 배우는 것으로 건너뛰지 않는다. 원정 부탁은 소개 다음 단계에서 지정 지역/지정 재료의 **성공한 채집 경험**을 기록하고, 마을 창고 재료를 별도로 전달한다. 채집 경험은 회상 기록이며 가방 전리품을 복제하거나 소비하지 않는다. 이미 보관한 같은 재료도 창고 전달에 사용할 수 있다.

## 반복과 계절

- 사계절 모임과 생일은 매년 1회. 진행 중인 회차는 맡은 해를 보존하고 최종 완료 전에 새 회차로 덮어쓰지 않는다.
- 모임은 각 계절 **8~20일**, 다음 날 이후 **15~20시**(겨울 **18~20시**), 우물 벤치에서 세 주민이 실제 도착해야 대화가 완료된다. 기간이 지나면 준비 기록을 남겨 다음 같은 계절에 이어간다. 실패나 강제 재료 손실은 없다.
- 매장 수요 행사 역시 각 계절 8~20일이며 소문은 3~7일에 기존 손님을 통해 들을 수 있다. 모임 퀘스트와 판매 수요는 별도다. 퀘스트를 맡지 않아도 해당 기간 수요가 적용된다. 준비를 마쳤다고 판매나 손님 수를 보장하지 않는다.
- 생일 초기 설정은 봄 15일/가을 7일/여름 18일, 전후 2일에 부탁을 시작한다. 세계관 검토용 임시 값이며 `default_village_expansion.tres`에서 수정한다. 맡은 선물은 늦어도 전달할 수 있다.
- 가게 기념일은 달력의 새해가 아닌 **실제 첫 거래 완료일 +112일**부터 시작한다. 반복도 112일 간격으로 처리한다.
- 반복 주문은 완료 다음 **7일** 뒤 다시 받는다. 반복 회차도 창고 전달과 대금 기록은 각각 1회, 평판은 이야기별 첫 완료에만 지급한다.

제빵 이웃 정착은 `regular_cook_aroma`의 실제 구매와 최종 후일담, 약초 이웃은 `contact_forest_bundle`의 실제 가게 구매와 최종 후일담 뒤 열린다. 앞선 구매 기록을 새로 만들지 않는다. 제빵소·약초 노점은 새 이웃의 생활 장소이며 무료 생산 설비나 별도 상점 UI를 지급하지 않는다. 기존 daily 안부의 밀/약초 선물은 별개이며 하루 1회다.

삭제된 곡물창고를 복원하지 않는다. 첫 식탁의 표시 개방은 현재 편집된 맵에 남아 있는 기존 보급 수레 복제본 중 한 곳에 연결했다. 사용자가 맵에서 제거한 원본과 건물 배치를 존중한다. 마지막 성장 장면 이후에도 영업·원정·반복 콘텐츠를 계속 플레이할 수 있다.

계절 매장 수요는 모임별 두 실제 상품, normal 가중치45/traveler30, 구매 수량1~2로 설정했다. 총 매장 행사는 공용3+계절12=**15개**다. 신규 상품은 기존 food 수요와 실제 진열·수동 결제를 이용하고 아이콘은 기존 빵 이미지를 재사용한다. 이미지 생성/수정은 없다.

## 구성과 저장

- `VillageExpansionFlow`/`VillageExpansionDirector`/`VillageExpansionSettings`: 순서·재료·생산·발견·회차·대화·방문자 처리.
- `default_village_expansion.tres`: 24개 event, 주민2, 글 도구용 moments69. events는 기계 설정이고 대사 행으로 취급하지 않는다.
- 기존 게시판·수첩·주민 목록·동선·마을 개방·제조법·원정 채집 성공에 작은 연결만 추가했다.
- `village_expansion:<id>` 아래 active/회차별 accepted·step·advanced·made·discovered·done/last_done/count를 기존 PlayerProgress 저장에 기록한다. 평판은 기존 합산 키를 사용한다. 저장 버전은 변경하지 않고 이전 저장에 완료를 자동 이식하지 않는다.
- 대화 중 가게 시계와 플레이어 이동을 멈추고 이전 상태로 복원한다. 장면 이탈/재고 변경/같은 행동 재호출로 부분 소비나 중복 지급을 하지 않는다.

## Gemini 보강

`requests_text.csv`의 **service_text93행**(연속 단계69+매장 반응24), **resident_greeting2행**과 `content_voices.csv`의 같은 ID 문맥을 추가했다. 기존 종류·검수 규칙을 유지하고 SOURCE_FILES/프롬프트에 실제 단계와 지급 시점을 등록했다. API 호출은 하지 않았다.

```bat
dev\gemini\run_request_text.bat sync
dev\gemini\run_request_text.bat draft resident_greeting --ids baker_neighbor,herb_neighbor
```

새 대사는 `expansion_`/`store_fest_` 접두사로 골라 검수할 수 있다. 가게가 이세계로 온 뒤 현지 재료와 교류로 원래 상품을 재현한다는 시점, 같은 직군의 기존 구매자 재방문, 기념일 임시 날짜, 첫 평판/회차별 대금 구별을 유지한다. 전이 원인·새 고유 이름·무료 설비·자동 판매·음식 회복·실제 NPC 여행이나 음용 연출을 새로 확정하지 않는다. 상품·숫자·시간·조작 안내는 UI에 맡긴다.

## 확인 방법

`git pull` 후 Godot에서 실행 → 기존 튜토리얼·주민·제품 생활 부탁 완료 → 마을 게시판의 연속 이야기 맡기 → 수첩 안내를 따라 주민 E. 계절 모임에는 지정 시간에 우물 벤치에서 기다린다. 새 게임의 도입부를 반복해서 볼 필요는 없고, 이전 저장에서도 실제 선행 완료 조건을 충족하면 새 카드가 열린다.

자동 검증 결과는 아래에 기록한다. 사용자 화면에서 대사 호흡과 주민 외형 구별은 추가 플레이 확인 대상이다.

### 검증 범위

`check_village_expansion`은 24개 이야기의 실제 게시판 버튼 → 실제 NPC E → 부분 읽기/완독 → 정확한 창고 소비 → 다음 날/최종 보상 → 저장 복원을 확인한다. 모임 참가자는 건물 주변을 실제로 걸으며, 원정 채집은 실제 방 이동과 E를 사용하는 드라이버로 검사한다. 새 상품은 실제 설비 제작·수령 → 진열 → 수동 결제로 판매한다. 반복 회차/평판 최초 1회/생일 기한 없음/첫 거래부터 기념일/대화 중 재고 변경/정착 제안 미리 듣기/맵 삭제 존중도 포함한다. 채집 난수에 따라 검사 횟수는 달라진다.

- 최신 3D main `56b25bf` 포함 후 신규 **1189검사 실패0**, 전체 **609개 로드 실패0**, 통합88 실패0. import 재실행 종료0.
- 매장 소문·품절·구매 반응 486검사, 일정·실제 수요 497검사 실패0. 겹치는 계절 행사의 종료 경계는 해당 행사 ID의 수요로 구별하도록 검사 전제를 수정했다.
- 기존 제품 생활 부탁118/제품 발전120/단골281/원정 만남336/날씨177/계절 생활 부탁174/행사 후 부탁172/통합88/도입 독백34/튜토리얼80 실패0. 주민 생활·동선·수첩·게시판·개인 부탁·수동 결제·첫 거래·글 도구·런타임 대사 검사도 통과했다. 기존 주민 생활 검사에서 삭제된 2D sprite_frames를 찾던 전제만 3D 배우 등록 확인으로 수정했다.
- 원정 전체16판 완료/막힘0, 기본240프레임 종료0, SCRIPT/Parse 오류 없음. 기존 Windows 인증서 저장소·누락 아이콘 경고는 남아 있다.
- 대사 CSV393행 오류/주의0. 새 대사의 반복 어구와 수량 표현을 다듬었으며 검수 규칙은 완화하지 않았다.
