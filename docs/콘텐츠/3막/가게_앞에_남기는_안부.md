# 가게 앞에 남기는 안부 (2026-10-03)

생활 부탁을 도운 뒤 이웃들이 가게와 마을에 대해 남긴 말을 직접 듣는 사건이다. 재료를 전달하는 흐름에서 잠깐 벗어나 주민을 찾아가고, 돌아올 장소가 생겼다는 마음을 나눈다.

## 플레이 흐름

1. 길목 쉼터 첫 모임을 마치고, 생활 부탁 세 개를 전달한 뒤 **타블렌·코르빈·이세르의 후일담을 모두 끝까지 듣는다**.
2. 첫 모임·생활 부탁 전달·후일담 완독 중 가장 늦은 날의 **다음 날부터** 이야기가 열린다. 기존 튜토리얼과 세 주민 정착 조건도 필요하다.
3. 이세르에게 E로 **가게 앞에 남기는 안부** 제안을 끝까지 들으면 사건이 시작된다. 일부만 읽거나 대화를 닫으면 시작되지 않는다.
4. **타블렌·코르빈·이세르 모두**에게 E로 각자의 안부를 듣는다. 순서·시간대·기한 제한 없이 진행하고, 끝까지 읽은 주민만 기록한다. 이세르의 제안과 본인 이야기는 서로 다른 대화다.
5. 수첩에서 들은 주민과 남은 주민을 확인한다. 이세르의 이야기를 먼저 듣고 다시 찾아가면 남은 안부를 안내한다.
6. 모두 들은 뒤 이세르에게 돌아가 마지막 대화를 끝까지 읽는다. **밀 2개·숲 약초 2개를 창고에 받고 평판 1**을 한 번 얻는다. 돈이나 플레이어 물품을 소비하지 않는다.
7. 완료 날짜와 세 이웃의 안부, 마지막 공동 기억은 수첩에서 다시 읽는다. 완료 뒤 사건 대화가 기존 이세르 이야기 재읽기를 계속 가리지 않는다.

주민은 기존 자리와 이동 일정을 이용한다. 가게 앞이라는 이름은 주민들이 가게에 대해 나눈 안부를 뜻하며, 새 집합 장소나 실제 편지·상자·선물 오브젝트를 배치하지 않는다. 새 고객·건물·가방·장비·날씨 기능을 해금하지 않는다.

## 진행과 수치

- 새 `VillageGoodwillSettings`와 `default_village_goodwill.tres`에 제안자·참여자·앞선 부탁·대기일·선물·평판·장면을 모았다. 답례는 Claude가 조정할 수 있는 초기값이다.
- 새 `VillageGoodwillFlow`가 조건·소개·주민 완독·마무리를 처리한다. `VillageLifeDirector`에는 대화 선택과 완료 연결을 추가했다. 기존 개인 부탁 후일담이 우선하며, 새 사건 진행이 없으면 기존 이야기와 안부를 사용한다.
- 선행 상태가 열리기만 해서는 자동 시작·완료·지급하지 않는다. 대화 중단·건축 모드·다른 모달·장면 이탈은 기존 대화 차단과 시계·이동 복원 규칙을 사용한다. 최종 답례는 마지막 대화 완독 시 한 번 지급한다.
- 저장 키는 `village_goodwill:shop_neighbors:accepted`, `heard:<주민 id>`, `done`과 `resident_request:reputation:event/shop_neighbors`다. 기존 진행 정수 저장 형식을 사용한다.
- 수첩은 시작 전 이세르, 시작 후 아직 듣지 않은 주민, 모두 들으면 이세르를 가리킨다. 완료 뒤에는 반복 선물을 받으러 가도록 목적지를 표시하지 않는다.
- 일반 안부의 친밀도와 작은 선물은 기존 기능이다. 새 사건 중간 단계는 별도 지급이 없고, 최종 선물에만 이 설정값이 적용된다. 기존 개인 부탁 수와 새 손님 해금 기준을 변경하지 않는다.

## Gemini 보강용 장면

기존 `service_text` 종류로 6개를 등록했다. `requests_text.csv`에는 글만, 설정 파일에는 기계 조건·수치만 둔다. 정식 `character_names.md`·`character_voices.csv`를 유지하며 `content_voices.csv`에 사건 맥락을 추가했다. Gemini API는 호출하지 않았다.

| ID | 화자 | 사용처 |
|---|---|---|
| `goodwill_intro` | 이세르 | 제안 제목·소개 |
| `goodwill_naru` | 타블렌 | 가게가 돌아올 기준점이 된 이야기 |
| `goodwill_doyun` | 코르빈 | 일을 마친 뒤 보는 불빛과 인사 |
| `goodwill_sora` | 이세르 | 이름 옆에 길어지는 안부 기록 |
| `goodwill_wait` | 이세르 | 아직 듣지 않은 이웃을 수첩에서 확인 |
| `goodwill_finish` | 이세르 | 이웃이 모은 선물 전달·수첩 공동 기억 |

```bat
dev\gemini\run_request_text.bat draft service_text --ids goodwill_intro,goodwill_naru,goodwill_doyun,goodwill_sora,goodwill_wait,goodwill_finish
```

주민들의 말투와 실제 방문·완독 안내를 유지한다. 소개에서 이미 선물을 받았다고 쓰지 않는다. 특정 방문 순서나 시각을 강제하지 않고, 물품을 가져오거나 구매하라고 쓰지 않는다. 최종 밀·약초는 창고에 지급하며 수량·평판 숫자는 대사에 쓰지 않는다. 각 `completion`은 수첩에서 실제로 읽는 기억이다. 초안 생성과 게임 데이터 반영은 별도이며 검토 후 반영한다.

## 검증

- `check_village_goodwill` 79개 통과: 튜토리얼·정착·모임·개별 부탁·완독·다음 날 조건, 실제 NPC E 대화, 중단·재시도·안부 순서 자유·제안자 본인 이야기 분리·남은 주민 안내, 원래 시간/이동 상태 복원, 건축 중 차단, 잘못된 제안자 마무리 방지, 창고 선물 일회성 지급·돈 소비 없음·기존 고객 조건 유지, 저장·수첩 목적지·기억·장면 이탈·새 게임을 확인했다.
- 대사 CSV 92행 오류·주의 0. 새 항목 6개는 사건의 대화 장면이며 퀘스트 여섯 개를 뜻하지 않는다.
- Godot 4.7.1 가져오기 2회, 통합 main의 3D 자료를 포함한 전체 리소스 521개 로드 실패 0. 기존 이세르 이야기 70개·생활 부탁 98개·먹거리 후일담 97개·쉼터 51개·주민 일상·수첩·대사 도구 검사 통과. `tools/balance_baseline.py` 실행 성공이며 이 도구는 사건의 일회성 선물을 직접 계산하지 않는다.
- 최종 검사 로그에 `SCRIPT ERROR`는 없다. 기존 인증서 저장소·아이콘 누락·빈 데이터 경고는 남아 있다. 가져오기로 변경된 `.import` 파일은 콘텐츠 커밋에 포함하지 않는다. 사람이 처음부터 끝까지 직접 플레이한 확인은 아직 하지 않았다.
