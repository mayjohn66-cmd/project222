# 콘텐츠별 첫 이야기 점검표 (2026-10-12)

새 콘텐츠를 처음 만날 때 이야기가 있는지 보는 표. 콘텐츠마다 세 가지가 있어야 한다고 보았다.

1. **계기** — 왜 이 일을 하게 되는지(소문·부탁·사건·소개)
2. **첫 만남** — 처음 접했을 때의 대사(사람·도구·가구를 처음 마주침)
3. **첫 완료 후일담** — 처음 해냈을 때 한마디

> **읽는 법과 한계**
> - 근거는 `data/shop/requests/requests_text.csv`의 **id 이름**이다(`intro`·`first`·`meet`·`finish` 같은 말). 내용이 실제로 그 역할을 하는지는 읽어 확인하지 않았다.
> - **초반에 나오는지(게임 시간상 언제 열리는지)는 확인하지 않았다.** 이 표는 "글이 있는가"만 본다. 시점은 구조 파일(`원본_위치_지도.md` 3장)에서 따로 봐야 한다.
> - ✅ id 있음 · ⚠ 일부만/애매 · ❌ 못 찾음 · ❓ 이야기가 필요한지 사용자가 정할 것.
> - 글이 `data/` 밖(낚시 JSON, 원정 이벤트 CSV 등)에 있으면 못 봤을 수 있다.

## 2. 비어 있어서 새로 써야 할 곳 (Gemini에 요청할 목록)

우선순위는 "플레이어가 일찍 만나는 순"으로 제안한다. 정하는 것은 사용자다.

1. **가구 건축·공간 넓히기**의 계기와 첫 완료 후일담
2. **냉장·냉동 가구와 생산 설비**를 처음 놓았을 때의 첫 만남·후일담
3. **매장 행사**를 처음 열 때의 소개 글(소문 이전에 "행사가 뭔지" 알려 주는 한 줄)
4. **원정 지역 첫 방문**(`expedition_events.csv`에 있는지 먼저 확인)
5. **등불 길손·첫 장터·마을 확장**의 소개/마무리 구분
6. **계절 보존**의 마무리 글

새 글을 만들면 새 id가 생기므로 코드 연결이 따로 필요하다. 글만 바꿔서 끝나지 않는다.

## 3. 같이 정해야 할 것

- 이 표에 없는 콘텐츠가 더 있는가(예: 아직 구현 전 계획).
- 순수 시스템 화면(❓)은 이야기를 붙이지 않는다고 확정할 것인가.
- 세 가지(계기·첫 만남·후일담)를 모든 콘텐츠의 최소 기준으로 삼을 것인가.
