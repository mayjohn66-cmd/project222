# 계획 — 실제 매장에 3D 도트 방식 붙이기 (초안 v0.1)

작성일: 2026-10-02 · 상태: **계획만. 사용자 승인 전에는 기존 게임 파일을 바꾸지 않는다.**
근거: `그림_규격서_3D도트_초안.md`, `3D_도트_기법_참고.md`, `dev/spike3d/store_spike.tscn`(시험 장면), 아래 1장에서 읽은 실제 코드

## 0. 목표와 범위

- 목표: **실제 매장 안쪽**(바닥·벽·가구·사람)을 시험 장면과 같은 방식(낮은 해상도 3D + 정렬 깊이 + 윤곽선 + 법선 맵·시간대 빛)으로 그린다.
- 이번 범위: 매장 안쪽만. 바깥 도로·마을·생산실·창고·원정은 **2D 그대로**(나중에 같은 방식으로 확장 가능).
- 원칙: **게임 규칙·충돌·길찾기·건축은 지금의 2D 코드를 그대로 쓴다**(논리 층). 3D 는 그 상태를 읽어서 그리는 **보이는 층**을 새로 얹는다. 기존 큰 파일(`build_manager.gd`, `customer.gd`, `worker.gd`, `player.gd`, `day_manager.gd`)은 건드리지 않거나 한두 줄만 건드린다.
- 되돌리기: 설정 하나(`use_3d_view`)로 3D 층을 끄면 지금 화면 그대로 나온다.

## 1. 읽어서 확인한 현재 구조

### 1.1 화면·좌표
- 게임은 전부 2D 입니다. `main.tscn` 의 `World` 는 `Node2D`, 하위 `Floor`(위치 530,208), `Objects`(y_sort, 위치 0,7), `Actors`, `StoreExterior`, `ProductionRoom`(12000,8000), `WarehouseRoom`(18000,8000) 등.
- 칸→화면 변환(`isometric_grid.gd`): `화면 = ((x−y)×48, (x+y)×24)` (칸 96×48, 2:1).
- 카메라: 플레이어 아래 `Camera2D`(zoom 1). 마을 편집 모드는 zoom 0.30 으로 바꿈(`village_map_editor.gd`).
- 창: `stretch mode=canvas_items`, `aspect=expand`(창이 커지면 보이는 영역이 넓어지고 2D 그림이 같이 커짐).
- 매장 기본 칸 수 10×8, 확장·부지 종류에 따라 바뀜(`floor.gd`, `store_expansion_data.gd`, `store_lot_data.gd`).

### 1.3 사람
- `Player`, `Customer`(`customer.gd` 2065줄), `Worker`(`worker.gd` 2437줄)는 모두 2D 노드이고 그림은 자식 `AnimatedSprite2D`(`character_visual.gd`). 이동은 `global_position` 으로 판단, 방향은 8방향 이름(`down_right` 등).
- 방향·걷기는 `character_visual.gd` 가 위치 변화량으로 판단 → 3D 층도 **위치 변화량만 읽으면** 같은 정보를 얻는다(기존 코드 수정 불필요).

## 2. 접근: "거울 층" (논리 2D 그대로 + 3D 가 읽어서 그림)

새 파일(예: `script/world/view3d/`):
1. `store_view_3d.gd` — 3D 보이는 층의 뿌리. `SubViewportContainer` + `SubViewport`(낮은 해상도, 배경 투명) + 카메라 + 빛. `World` 아래에 1개 노드로 추가.
2. `floor_mirror.gd` — `Floor` 의 칸 수·부지에서 바닥 평면과 질감을 만든다.
3. `wall_mirror.gd` — `wood_walls` 와 같은 경계 선분에서 벽 상자를 만들고, 벽에 붙은 문·포스터 자리에 구멍·부착물을 만든다.
4. `furniture_mirror.gd` — `Objects` 의 자식(진열대·계산대 등)을 읽어 상자(발자국×회전×높이)로 만든다. 추가·삭제·이동·회전·진열대 층 변경을 감지한다.
5. `actor_mirror.gd` — `Player`/`Customer`/`Worker` 를 읽어 3D 상자 캐릭터(3등신, 시험 장면의 `BlockyActor`)를 대응시킨다. 위치·방향·걷기는 위치 변화량으로.
6. `time_light.gd` — `time_of_day.csv`/게임 시각에 맞춰 해·달·환경광·등(시험 장면의 `apply_time`).
7. 정렬·윤곽선·깊이 셰이더는 `dev/spike3d/` 의 것을 `script/world/view3d/shader/` 로 **복사해 정리**(시험 코드는 그대로 남김).

기존 파일 변경(최소):
- `scenes/shop/main.tscn`: `StoreView3D` 노드 1개 추가 + 설정 연결.
- 2D 그림 숨기기: 가구 `*_visual.gd`, `wood_walls.gd`, `floor.gd`, `character_visual.gd` 에 **`use_3d_view` 가 켜져 있으면 그리지 않는다**는 조건 한 줄씩(또는 부모에서 `visible=false` 로 처리해서 코드를 안 건드리는 방법 — 선택 ❓).
- 건드리지 않는 것: 충돌, 길찾기, 건축 배치 규칙, 손님·직원 행동, 저장.

## 3. 해결해야 할 문제와 제안

| # | 문제 | 제안 | 결정 필요 |
|---|---|---|---|
| 1 | **칸 크기 불일치**: 3D 는 낮은 해상도 36×18 → 3배 확대로 화면 108×54, 2D 칸은 96×48 | 3D 를 2D 카메라에 **맞추지 않고**, 2D 카메라 zoom 을 3D 칸 크기에 맞춘다(기준 창에서 zoom 1.125). 2D 로 그려지는 UI·건축 고스트·클릭 판정이 함께 커져서 맞는다 | ✅ 가능하면 승인 |
| 2 | **창 크기**: 기본 게임 화면 1152×648 만 기준으로 한다(낮은 해상도 384×216, 배율 3). 창 크기 조절은 나중에 **설정 화면**에서 다룰 예정(사용자 계획, 2026-10-02)이라 이번 범위 밖 | 이번에는 1152×648 에서만 맞춘다. 나중에 설정에서 크기를 고르게 할 때는 **정수 배율이 되는 크기만** 목록으로 제공하는 것을 권한다(1152×648=3배, 1920×1080=5배 등). 그러면 3D 도트가 번지지 않는다(상세는 아래 5장 메모) | 설정 화면 때 결정 |
| 3 | **카메라 이동**: 플레이어를 따라 2D 카메라가 움직임 | 3D 카메라가 2D 카메라 중심을 바닥 좌표로 바꿔서 따라가고, 화면 픽셀 격자로 스냅(시험 장면과 같음) | — |
| 4 | **건축 고스트·선택 표시·진열대 글자(`StockLabel`)·말풍선**은 2D 그림 | 그대로 2D 로 3D 위에 겹쳐 그린다. 한계: 3D 가구에 **가려지지 않고 위에 그려짐** | ❓ 어색하면 다음 단계에서 3D 화 |
| 5 | **진열대 쌓기(최대 3층)** | 층마다 높이가 늘어나는 상자(+상품 그림은 2D 그대로 위에 겹침) | — |
| 6 | **벽의 문·포스터** | 벽 상자를 문 폭만큼 나눠 구멍을 내고 문 틀을 상자로 추가. 포스터는 벽 면 위 얇은 판 | — |
| 7 | **가구 그림**: 지금은 한 장짜리 2D 그림(`art/world/cozy_v6` 등, 일부는 픽셀 아님) | 시험 단계에서는 **임시 질감**(코드로 만든 도트)을 쓴다. 실제 그림은 Pixel Lab 으로 면별 질감(규격서 3~4장)을 만들어 교체 | 이미지 제작은 사용자 |
| 8 | **시간대 빛** | `day_night_tint.gd`(CanvasModulate) 대신 3D 층에는 해·달·등을 쓰고, 2D 부분(UI 제외)은 기존 tint 유지. 3D 층에는 tint 를 이중 적용하지 않도록 분리 | 기존 tint 와의 관계 ❓ |

| 10 | **마을 편집 모드(zoom 0.30)·타이틀·연출** | 편집 모드 중에는 3D 층을 숨기고 2D 로 보이게 한다 | — |
| 11 | **성능** | 이 환경(소프트웨어 렌더링)에서만 시험했다. 실제 PC 확인 필요. 정렬은 상자 수십 개 규모에서 문제 없었으나 가구·손님이 많아지면 재계산 빈도를 줄인다(위치가 바뀐 것만) | PC 확인 |

## 4. 작업 순서 (각 단계마다 시험·검증 후 커밋)

1. **가구 표 확정**: 위 1.2 의 "코드값 없음 ❓" 가구의 높이·색을 정한다(임시값 제안 → 사용자 확인). 이 단계는 문서만.
2. **읽기 전용 거울 시험**: 실제 `main.tscn` 을 실행하면서 3D 층이 바닥·벽·가구·사람을 **그리기만** 한다(2D 도 그대로 켜 둔 채 겹쳐서 위치가 맞는지 확인). 기존 파일 변경 없음.
3. **2D 숨김 스위치**: `use_3d_view` 를 켜면 2D 매장 그림이 사라지고 3D 만 보이게. (여기서 기존 파일 한 줄 수정이 생김 — 목록을 보여 주고 승인)
4. **빛·법선 맵·시간대** 연결.
5. **건축 모드·진열대 쌓기·문/벽 꾸미기** 확인.
6. **정리**: 시험 코드 중복 제거, 규격서 갱신, 검증기 추가.

각 단계의 합격 기준: ① 2D 와 3D 위치 오차 0~1px(겹쳐 보기) ② 가구 추가·삭제·회전이 즉시 반영 ③ 손님 7명 이상에서 가림 순서 이상 없음 ④ `use_3d_view` 를 끄면 지금과 동일.

## 5. 위험과 미확인

- 시험은 **이 환경의 소프트웨어 렌더링**에서만. 실제 GPU 에서 깊이(DEPTH) 방향·줄무늬·윤곽선이 같은지 **미확인**(시험 장면 `store_spike.tscn` 을 PC 에서 먼저 봐 주세요).
- 기존 2D 그림 일부는 픽셀 규격이 아니고(`에셋_규격서_초안.md` 2장) 질감 면별 그림이 아직 없다 → 3D 가구는 임시 질감으로 시작.
- 줌·창 크기 처리(문제 1, 2)가 가장 영향이 큼. 2D UI 크기가 12% 커지므로 UI 배치를 확인해야 한다.
- 매장 확장·부지 종류(코너 부지 등)와 벽 구성이 다양하다(`wood_walls.gd`, `store_exterior.gd` 1328줄) → 처음에는 기본 부지·기본 크기에서 시작한다.
- 저장·불러오기에는 영향 없음(논리 층 불변)이어야 하나 **확인 전**.

메모(나중에 설정 화면에서 창 크기를 바꿀 때): 3D 도트는 낮은 해상도를 **정수 배**로 늘려야 선명하다. 배율 N = 창 높이 ÷ 216 이 정수인 크기(648, 864, 1080, 1296, 1512, 1728, 1944, 2160 …)를 선택지로 주고, 그 밖의 크기를 고르면 가장 가까운 정수 배율 크기로 맞추는 방식이 가장 단순하다. 지금은 구현하지 않는다.
