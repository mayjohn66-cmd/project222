# AI 협업 규칙 (초안 v0.2)

이 프로젝트는 사용자 1명과 AI 2개(Claude, ChatGPT)가 코드·데이터를 작업하고, 이미지는 전용 이미지 AI(예: Pixel Lab)가 만듭니다. 파일이 꼬이지 않도록 아래 규칙을 지켜 주세요.
규칙은 필요할 때마다 사용자와 상의해서 고칩니다.

## 1. 담당 구역

| 구역 | 담당 | 비고 |
|---|---|---|
| `data/` (CSV 밸런스 데이터) | Claude | 수치 변경은 여기서만 |
| `docs/` (규칙서, 규격서) | Claude가 작성, 모두 참조 | 구현 전에 반드시 읽기 |
| `tools/` (검증·계산 스크립트) | Claude | `validate_assets.py`, `balance_baseline.py` |
| 기존 코드 정리·리팩터링 | Claude | 큰 파일 분리는 기능 작업이 안정된 뒤에 |
| `art/` (이미지) | 사용자(이미지 전용 AI로 제작) | **Claude와 ChatGPT는 이미지를 생성하거나 덮어쓰지 않음.** 규격은 `docs/에셋_규격서_초안.md` |
| 새 기능 코드 (`script/`, `scenes/`) | ChatGPT | **새 파일로 추가**, 기존 큰 파일에 덧붙이지 않기 |

두 AI는 이미지 파일을 만들지 않습니다. 이미지가 없을 때는 임시 이미지(`ArtLoader`)로 게임이 죽지 않게만 하고, 필요한 이미지 목록은 사용자에게 전달합니다.

담당이 아닌 구역을 고쳐야 하면 먼저 사용자에게 알리고 허락을 받습니다.

## 2. 브랜치

- `main`: 사용자가 확인한 것만 들어갑니다. **직접 올리지 않습니다.**
- 작업 브랜치: `claude/<주제>`, `gpt/<주제>` (예: `claude/materials-24`, `gpt/expedition-prototype`)
- 합치는 것(병합)은 사용자가 내용을 확인한 뒤에 합니다.

## 3. 커밋 메시지

`[구역] 무엇을 왜 바꿨는지` 형식으로 씁니다.

- `[data] 재료 24종 추가, 지역 배율 공식 적용`
- `[code] 원정 방 이동 프로토타입`
- `[art] 숲 몬스터 스프라이트 추가` (사용자가 이미지 도구로 만든 것을 올릴 때)
- `[docs] 원정 규칙서 v0.3`
- `[tools] 에셋 검증기에 팔레트 검사 추가`

## 4. 같은 파일을 동시에 고치지 않기

- 작업을 시작하기 전에 **고칠 파일 목록**을 사용자에게 알립니다.
- 다른 쪽이 작업 중인 파일은 건드리지 않습니다.
- 아래 큰 파일은 기능 작업이 안정될 때까지 **수정 최소화**, 새 기능은 새 파일로 만듭니다: `expedition.gd`, `game_state.gd`, `build_manager.gd`, `worker.gd`, `day_manager.gd`
- 한 번에 많은 파일의 이름이나 폴더를 바꾸는 작업(대규모 이동)은 혼자 하고, 그동안 다른 쪽은 쉽니다.

## 5. 수치와 데이터

- 수치는 코드에 직접 쓰지 않고 `data/`의 CSV나 설정 상수로 뺍니다.
- 데이터를 바꾸면 `tools/balance_baseline.py`를 돌려 결과를 커밋 설명에 붙입니다.
- 이미지를 추가하면 `tools/validate_assets.py`를 돌려 **FAIL이 없는지** 확인하고 결과를 커밋 설명에 붙입니다. 검증 실패 목록은 Claude가 사용자에게 넘깁니다.
- 이미지 도구(API 키, 크레딧)의 키는 저장소에 넣지 않고 사용자 환경 설정으로만 관리합니다.

## 6. 하지 않는 것

- `.godot/` 폴더를 올리지 않습니다(`.gitignore`가 막아 줍니다).
- `main`에 직접 올리지 않습니다.
- 버전 이름이 붙은 폴더(`_v2`, `cozy_v11` 등)를 새로 만들지 않습니다. 버전은 git 이력으로 관리합니다.
- 검증 없이 이미지를 넣거나, 실행해 보지 않은 코드를 "동작한다"고 말하지 않습니다.

## 7. 채팅 방식으로 전달할 때

저장소에 직접 올릴 수 없는 환경에서는 **바뀐 파일만** 저장소와 같은 폴더 구조로 담아서(`patch/data/core/items.csv` 처럼) 사용자에게 전달합니다. 무엇을 왜 바꿨는지 짧게 적습니다.
