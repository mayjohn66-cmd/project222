# AI 협업 규칙 (초안 v0.6)

이 프로젝트는 사용자 1명과 AI 2개(Claude, ChatGPT)가 코드·데이터를 작업하고, 이미지는 전용 이미지 AI(예: Pixel Lab)가 만듭니다. 파일이 꼬이지 않도록 아래 규칙을 지켜 주세요.
규칙은 필요할 때마다 사용자와 상의해서 고칩니다.

## 1. 담당 구역

| 구역 | 담당 | 비고 |
|---|---|---|
| `data/` (CSV 밸런스 데이터) | Claude | 수치 변경은 여기서만 |
| `docs/` (규칙서, 규격서) | Claude가 작성, 모두 참조 | 구현 전에 반드시 읽기 |
| `tools/` (검증·계산 스크립트) | Claude | `validate_assets.py`, `balance_baseline.py` |
| 기존 코드 정리·리팩터링 | Claude | 큰 파일 분리는 기능 작업이 안정된 뒤에 |
| `art/` (이미지) | 사용자(이미지 전용 AI로 제작) | **Claude와 ChatGPT는 이미지를 생성하거나 덮어쓰지 않음.** 규격은 `docs/에셋_규격서_초안.md` |
| 새 기능 코드 (`script/`, `scenes/`) | ChatGPT | **새 파일로 추가**, 기존 큰 파일에 덧붙이지 않기 |

두 AI는 이미지 파일을 만들지 않습니다. 이미지가 없을 때는 임시 이미지(`ArtLoader`)로 게임이 죽지 않게만 하고, 필요한 이미지 목록은 사용자에게 전달합니다.

담당이 아닌 구역을 고쳐야 하면 먼저 사용자에게 알리고 허락을 받습니다.

## 2. 브랜치 (2026-10-03 변경: main + 작업 브랜치 최대 2개)

브랜치가 20개 넘게 늘어 확인이 불가능해져 단순화합니다. 기능 단위로 브랜치를 만들던 방식(2026-10-01)은 폐기합니다.

- `main`: **항상 Godot에서 실행되는 상태**만 둡니다. 사용자가 확인한 것만 들어갑니다.
  - 데이터·문서·도구처럼 작고 안전한 수정은 사용자 승인 후 `main`에 바로 합칠 수 있습니다.
- **작업 브랜치는 동시에 최대 2개**입니다. 이름은 큰 줄기 기준(`feature/<줄기>`, AI 이름 금지). 현재 계획: 3D 마을(`feature/iso-3d-store`)과 마을·스토리(`feature/village-life`).
  - 새 브랜치가 필요하면 먼저 `git branch -r`로 확인하고, 2개가 이미 있으면 기존 것에 이어서 작업하거나 하나를 먼저 `main`에 합칩니다.
  - 모든 AI는 같은 줄기면 같은 브랜치에 커밋합니다. 푸시 전에 `git fetch`로 상대 커밋을 먼저 받고 강제 푸시는 금지합니다.
- **짧게 유지**: 한 단계가 끝날 때마다(길어도 며칠 안에) `main`에 병합하고, 병합이 끝난 브랜치는 바로 삭제합니다(삭제는 사용자 PC/GitHub에서, 사용자 승인 후).
- 병합은 사용자가 내용을 확인한 뒤에 합니다. 큰 병합은 `merge/<이름>` 임시 브랜치에서 먼저 해 보고 `main`에 반영합니다.
- 큰 기능은 켜기/끄기 스위치(예: 3D의 `F10`, 기본 꺼짐)를 두어 완성 전에도 `main`에 합칠 수 있게 합니다.
- **`docs/handoff` 고아 브랜치는 체크아웃하지 않습니다**(작업 폴더의 파일이 모두 사라짐). 인수인계 문서는 `main`의 `docs/`로 옮기고 이 브랜치는 삭제합니다.
- 사용자 PC에서 확인할 때는 AI가 알려 주는 브랜치로 `git switch` 하고, 모르겠으면 `git branch --show-current`로 확인합니다.
- 기존 브랜치 정리와 병합 순서는 `docs/병합_계획서.md`를 따릅니다.

## 3. 커밋 메시지

`[구역] 무엇을 왜 바꿨는지` 형식으로 씁니다.

- `[data] 재료 24종 추가, 지역 배율 공식 적용`
- `[code] 원정 방 이동 프로토타입`
- `[art] 숲 몬스터 스프라이트 추가` (사용자가 이미지 도구로 만든 것을 올릴 때)
- `[docs] 원정 규칙서 v0.3`
- `[tools] 에셋 검증기에 팔레트 검사 추가`

## 4. 같은 파일을 동시에 고치지 않기

- 작업을 시작하기 전에 **고칠 파일 목록**을 사용자에게 알립니다.
- 다른 쪽이 작업 중인 파일은 건드리지 않습니다.
- 아래 큰 파일은 기능 작업이 안정될 때까지 **수정 최소화**, 새 기능은 새 파일로 만듭니다: `expedition.gd`, `game_state.gd`, `build_manager.gd`, `worker.gd`, `day_manager.gd`
- 한 번에 많은 파일의 이름이나 폴더를 바꾸는 작업(대규모 이동)은 혼자 하고, 그동안 다른 쪽은 쉽니다.

## 5. 수치와 데이터

- 수치는 코드에 직접 쓰지 않고 `data/`의 CSV나 설정 상수로 뺍니다.
- 데이터를 바꾸면 `tools/balance_baseline.py`를 돌려 결과를 커밋 설명에 붙입니다.
- 코드를 바꾸면 Godot 4.7.1로 실행 검증을 하고 결과를 커밋 설명에 붙입니다(Godot가 있는 환경에서만).
  - `godot --headless --path . --import`를 두 번 돌려 두 번째에 오류가 0인지 확인(첫 실행은 가져오기 순서 때문에 테마 관련 가짜 오류가 나옴)
  - `godot --headless --path . res://tools/check_godot.tscn`으로 모든 `.gd`와 `.tscn`이 로드되는지 확인
  - 원정 흐름을 바꿨다면 `godot --headless --path . res://tools/check_expedition_run.tscn`으로 원정 한 판을 끝까지 자동 진행(로드 검사로는 안 잡히는 실행 중 타입 오류용). 종료 코드가 0이고 로그에 `SCRIPT ERROR`가 없어야 함
  - 실행하면 `.translation`(CSV 번역 부산물)이 바뀌므로 커밋하지 않고 `git checkout`으로 되돌림
- 이미지를 추가하면 `tools/validate_assets.py`를 돌려 **FAIL이 없는지** 확인하고 결과를 커밋 설명에 붙입니다. 검증 실패 목록은 Claude가 사용자에게 넘깁니다.
- 이미지 도구(API 키, 크레딧)의 키는 저장소에 넣지 않고 사용자 환경 설정으로만 관리합니다.

## 6. 하지 않는 것

- `.godot/` 폴더를 올리지 않습니다(`.gitignore`가 막아 줍니다).
- `main`에 직접 올리지 않습니다.
- 버전 이름이 붙은 폴더(`_v2`, `cozy_v11` 등)를 새로 만들지 않습니다. 버전은 git 이력으로 관리합니다.
- 검증 없이 이미지를 넣거나, 실행해 보지 않은 코드를 "동작한다"고 말하지 않습니다.

## 7. 채팅 방식으로 전달할 때

저장소에 직접 올릴 수 없는 환경에서는 **바뀐 파일만** 저장소와 같은 폴더 구조로 담아서(`patch/data/core/items.csv` 처럼) 사용자에게 전달합니다. 무엇을 왜 바꿨는지 짧게 적습니다.

## 8. AI끼리 소통

- 두 AI는 서로 직접 대화하지 못하고, 채팅 AI(일반 Claude·ChatGPT 채팅)는 저장소를 읽지 못해 **옛 정보로 답할 수 있습니다.** 그래서 질문·결정·인수인계는 **`docs/AI_소통.md`**에 적습니다.
- 작업 전에 그 파일과 규칙서를 읽고, 작업 뒤에 자기 항목을 고칩니다. 설계 결정(❓)은 사용자가 정합니다.
- 기준 브랜치는 그 파일 3장에 적힌 브랜치입니다(`main`은 최신이 아닐 수 있음).
