# 성능 측정과 최적화 기록 (2026-10-09)

**원칙: 추측으로 고치지 않고 먼저 잰다.** 아래는 화면 없이(헤드리스) 돌린 CPU 쪽 측정이다. 그리는 비용(GPU)과 실제 PC 글꼴 환경은 포함하지 않으므로, **PC에서 같은 도구를 돌려 숫자를 비교**해야 한다.

## 1. 측정 도구(개발용, `dev/spike3d/`)
| 도구 | 하는 일 | 실행 |
|---|---|---|
| `frame_profile.tscn` | 한 프레임에 스크립트가 쓰는 CPU 시간, 스크립트별로 끄면 줄어드는 시간, StoreView3D 단계별 시간. 두 번째 인자 `load`는 손님 부하 시도(지금은 손님이 안 생겨 부하가 안 걸림) | `godot --headless --path . res://dev/spike3d/frame_profile.tscn -- 300` |
| `load_profile.tscn` | 게임 켜는 데 걸리는 시간, 관리 책을 열고 탭을 넘길 때 걸리는 시간, 탭별 새로고침 시간 | `godot --headless --path . res://dev/spike3d/load_profile.tscn` |
| `label_cost_probe.tscn` | 긴 글 Label 하나를 만들 때 비용 비교 | 같은 방식 |

주의: 헤드리스는 프레임을 144fps 근처로 맞추느라 기다리므로 **프레임 사이 시간을 재면 안 된다**(스크립트가 쓴 시간이 아니다). `frame_profile`은 한 프레임의 `_process` 구간만 감싸서 잰다.

## 2. 측정 결과(헤드리스 컨테이너, 최적화 전)
- 한가한 상태의 스크립트 비용은 **프레임당 약 1.2ms**로 작다(`StoreView3D` 0.27, `world_interactions` 0.19, `floor` 0.11 …). 3D 정렬·동기화 단계는 합쳐 1ms 안팎이다.
- 시작: `main.tscn` 읽기 약 1.5초, 트리에 넣고 첫 프레임까지 약 2.0초(합 약 3.5초). 이후 30프레임 합계 약 0.5초.
- 관리 책 탭을 넘길 때 한 번에 걸리는 시간(내용 새로고침이 거의 전부, 책 배치는 0ms):

| 탭 | 이전 | 비고 |
|---|---|---|
| 정보(기본 정보) | 약 81ms | **글 칸 하나가 약 65~80ms**: 한글 약 340자 Label. 영문은 같은 길이에 0.2ms |
| 설계도 | 약 45~50ms | 미조사 |
| 생산 | 약 42~55ms | 미조사 |
| 인벤토리 | 약 22~38ms | 미조사 |
| 일정 | 약 12~14ms | 미조사 |

- 60fps에서 한 프레임은 16.7ms이므로, 40~80ms는 **3~5프레임이 끊기는 것**이다.

## 3. 원인과 조치
- **한글 글 Label을 새로 만들거나 트리에서 뺐다 넣으면 글자 배치(shaping)를 처음부터 다시 한다.** 이 컨테이너에서는 한글 224자에 20~28ms, 영문 385자에 0.2ms였다. 줄바꿈 옵션(autowrap 끄기·고정 폭)을 바꿔도 거의 같아(105~120ms vs 117ms) 줄바꿈이 원인이 아니고 글자 자체의 비용이다. 글꼴 파일을 직접 지정해도 28→20ms로 크게 줄지 않았다.
- 조치: 정보 탭(`management_menu.gd`)의 글 칸을 **트리에 둔 채 숨기고 다시 쓴다**(`_reset_info_labels`, `_add_store_info_text`). 같은 글이면 `text` 대입이 아무 일도 하지 않는다. 트리에서 뺐다 넣는 방식은 효과가 작았다(81→61ms). 이정표 탭은 자식이 쪽 둘뿐이어야 해서 이때만 글 칸을 비운다.
- 결과: 정보 탭 전환 **81ms → 0.2~0.3ms**(다시 열 때). 처음 한 번 열 때의 약 80ms는 남는다.

## 3-1. 탭 전환 2차 (설계도·생산·인벤토리)

| 탭 | 전 | 후 | 방법 |
|---|---|---|---|
| 설계도 | 45~52ms | 0.3ms | 목록(분류+이름)이 같으면 버튼을 다시 만들지 않음 |
| 생산 | 42~55ms | 2.8ms | 탭 전환은 `refresh(false)`로 책 내부 서명 비교 사용 |
| 인벤토리 | 22~38ms(탭 전환 시 2회 호출) | 0.2ms | 중복 호출 제거 + `refresh_inventory_if_changed()`로 상태 서명 비교 |

- 확인: 관련 check 씬 통과(`check_village_smithy` 1건 실패는 변경 전에도 동일). 
- 확인 못 함: PC 실측. 같은 헤드리스 컨테이너 수치이며 한글 폰트가 없는 환경이다.
- 남음: 일정 탭 11ms(매번 전부 삭제·재생성).

## 4. 아직 못 한 것·다음 후보
1. **PC에서 같은 도구를 돌려 숫자 확인**. 이 컨테이너의 한글 비용이 Windows에서도 같은지 모른다. 숫자가 작으면 이 최적화는 이득이 작다.
2. 같은 방식으로 설계도(약 50ms)·생산(약 45ms)·인벤토리(약 38ms) 탭의 새로고침을 점검한다. 매번 노드를 지우고 다시 만드는지, 바뀐 것만 갱신할 수 있는지.
3. 시작 시간 약 3.5초: 무엇을 읽고 만드는지 쪼개 본다(관리 책·가구·직원 이야기 등을 처음 열 때까지 미룰 수 있는지).
4. 처음 한 번 열 때의 끊김은 게임 시작 때 미리 만들어 두면 사라진다.
5. 손님·직원이 많은 영업 중 프레임 비용은 이번에 못 쟀다(손님이 생기지 않았다). 가게 배치(출입문·진열대)를 갖춘 상태에서 다시 잰다.
6. 로드 시 경고 `아이콘 없음: fish_*`(낚시 어종 아이콘이 없다)가 매번 쏟아진다. 성능과 무관하지만 로그를 어지럽힌다(그림 담당 확인).
