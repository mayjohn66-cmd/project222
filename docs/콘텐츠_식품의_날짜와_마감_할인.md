# 식품의 날짜와 마감 할인

2026-10-05 · 사용자 승인: 첫 장사 전 날짜 걱정 독백 + 제안한 유통기한 기능 전체 구현. 작업은 `main`.

## 실제 플레이 흐름

1. 새 게임 도입부에서 **나**가 함께 옮겨 온 빵의 날짜를 떠올린다. 현지 화폐나 상인을 알기 전이다. 날짜가 가까운 것은 싸게 먼저 내놓고 오래 둘 것은 차갑게 보관하려 한다.
2. 기존 가게 확인 → 진열 → 델빈 실제 결제 → 타블렌 물물교환 → 원정 → 원재료 실제 판매를 유지한다. 이 핵심 안내 동안 식품은 늙지 않는다. 안내 중 재고 조회 없이 여러 날을 보내도 끝난 날에 과거의 시간을 한꺼번에 차감하지 않는다.
3. 첫 원재료 판매 뒤 선택 안내 **남은 식품 챙기기**가 나온다. **손님이 없는 계산대 안쪽에서 E → 마감 정리**를 열고 **돌아가기**로 확인하면 완료된다. 완료는 기존 대화 완독으로 기록한다. 주민 콘텐츠는 이미 이용할 수 있고, 현지식 빵 만들기는 기존 첫 주민 정착 조건을 유지한다.
4. 마감 할인은 기본 ON이다. 계산대의 마감 정리에서 변경할 수 있다. 가장 빨리 기한이 오는 재고를 먼저 판매한다. 기한이 지난 상품은 자동으로 판매 가능한 재고에서 분리하고 계산대에서 폐기하거나 퇴비 재료로 정리한다.
5. 아침 시작 시각에 하루 한 번 품목들을 묶어 먼저 살펴볼 식품을 안내한다. 메뉴를 다시 열거나 저장을 불러왔다고 같은 날짜의 안내를 반복하지 않는다. 오늘 먼저 내놓을 식품과 분리한 만료품만 마감 정리에서 다시 볼 수 있다.

닫힌 문 때문에 게임 날짜가 진행하지 않으면 식품도 늙지 않는다. 현실 시간이나 개별 초 단위 타이머를 추가하지 않았다.

## 식품 초기값

기한은 입고/제작 수령일부터 세는 게임 날짜다. 예를 들어 1일차 입고한 현지식 빵은 3일차에 30% 할인, 4일차에는 판매 재고에서 분리된다.

| 식품 ID | 상온 기한 | 냉동 가능 |
|---|---:|---|
| bread | 6일 | 가능 |
| camp_bread | 3일 | 가능 |
| herbal_bread | 4일 | 가능 |
| berry_filled_bread | 3일 | 가능 |
| packed_mushroom_meal | 2일 | 가능 |
| mushroom_stew | 2일 | 가능 |
| traveler_stew | 3일 | 가능 |
| berry_juice | 3일 | 불가 |
| herb_drink | 4일 | 불가 |
| dried_fruit | 14일 | 가능 |

생수와 표에 없는 상품에는 식품 기한을 적용하지 않는다. 기존 봄 새순/여름 물박하의 계절 변형, 서리 얼음의 다음 아침 변형, 말린 계절 재료의 영구 보존은 그대로 유지한다. 일반 말린 열매 식품은 14일 기한을 가진다.

- 마감 1일 전부터 30% 할인. 혼합 입고 묶음은 각각 계산한다. 마지막 날 현지식 빵 2개와 신선한 1개라면 `70×2+100=240G`.
- 플레이어/직원/원정 중 직원 매출 계산은 같은 가격 함수를 사용한다. 결제창 표시와 실제 매출 금액도 같다. 미결제 반환에도 기존 날짜가 이어진다.
- 냉장함에서는 기한이 상온의 두 배 천천히 줄어든다. 냉동 가능한 식품은 냉동함에서 진행이 멈춘다. 꺼내면 남은 기한부터 상온 진행을 재개한다. 냉장함도 식품을 영원히 보존하지 않는다.
- 냉장·냉동 각 용량 12개를 기존 계절 재료와 공유한다. 기존 유료 설치/실물 가구 첫 상호작용 무료 설치가 모두 작동하고, 동일 가구 여러 대는 같은 보관함을 공유한다.
- 만료품은 원래 상품과 별도 수량으로 저장한다. 판매/제작/부탁 전달에 사용할 수 없다. 폐기는 추가 벌금이나 평판 손실이 없다. 지정 재활용은 만료품 2개 → `food_compost` 퇴비 재료 1개(5G)다. 홀수 남은 1개는 보관하거나 폐기할 수 있다. 재활용을 반복해 수량을 복제할 수 없고 식품으로 되돌리는 경로도 없다. 농사/퇴비 설비 기능을 약속하지 않는다.

## 저장과 연결

- 새 핵심 로직: `FoodShelfLife`, 설정: `FoodShelfLifeSettings`/`default_food_shelf_life.tres`, 품목: `data/shop/catalogs/food_shelf_life.csv`.
- 기존 저장 `preservation.food` 안에 창고/냉장/냉동 입고 묶음, 만료품, 할인 설정, 아침 안내 날짜, 관리창 확인 기록, 튜토리얼 보호 전환을 저장한다. 저장 버전은 바꾸지 않았다.
- 진열대와 창고 선반 슬롯의 `food_batches`는 `{amount, age, day}` 배열이다. 같은 식품도 다른 날짜 재고를 유지하고 동일 상태 묶음은 합쳐 저장 크기를 줄인다. 저장 시 수량 합계/날짜/형식을 검사한다.
- 입고 묶음은 공용 재고 → 수동/직원 진열 → 손님 → 반환, 공용 재고 ↔ 창고 선반/냉장/냉동 전 구간에서 유지한다. 창고 슬롯 부분 합치기/전체 교환에도 날짜가 유지된다.
- 실제 매장 객체와 저장 배치는 같은 재고의 두 표현이다. 매장이 없을 때는 저장 배치를 정산한다. 창고의 `storage_slots`/`warehouse_slots` 두 구형 키는 한 번만 만료 정산한다. 실제 객체를 저장할 때 식품 슬롯 사본을 갱신해 이미 팔거나 만료된 물품이 재등장하지 않게 했다.
- 기존 저장에 기한 정보가 없으면 **현재 게임 날짜**에서 최초 등록한다. 과거 재고를 갑자기 모두 폐기하지 않고, 이전 튜토리얼의 위치도 되돌리지 않는다. 새 독백/선택 안내는 새 게임용이다.
- `GameState`는 입고/소비/저장 검사에 작은 연결만 추가했다. `day_manager.gd`, `worker.gd`, `build_manager.gd`, `expedition.gd`에 새 로직을 쌓지 않았다.

## 인벤토리 부담 줄이기 (2026-10-05)

- 인벤토리의 별도 식품 관리 버튼/전체 식품 목록을 제거했다. 식품 날짜 묶음은 내부 데이터로만 유지하며 기존 재고 이동은 그대로 사용한다.
- 손님이 없는 계산대 **안쪽**에서 E 또는 화면의 **마감 정리** 버튼으로 들어간다. 문을 닫은 뒤에도 가능하다. 손님이 있으면 기존 직접 결제가 우선이다. 직원이 결제 중이면 예약을 침범하지 않는다.
- 창에는 오늘 먼저 내놓을 식품 요약, 자동 할인 ON/OFF, 기한이 지난 식품의 폐기/재활용만 둔다. 기한·할인율·보상 수치는 바꾸지 않았다.
- 오래된 재고 우선 판매와 마감 할인은 기본 자동이다. 플레이어가 매번 날짜별 식품을 분류하거나 할인 가격을 정하지 않는다.
- 오래 보관하려면 실물 냉장함·냉동함에서 상호작용한다. 기존 계절 재료 보관 기능의 인벤토리 바로가기는 유지한다.
- 정리창 동안 월드가 멈춘다. 돌아가기/창 닫기/창 숨기기/매장 제거 때 이전 일시정지 상태로 돌아간다. 다른 이유로 멈춰 있었으면 임의로 해제하지 않는다.
- 선택 튜토리얼과 아침 안내도 계산대 경로를 사용한다. 이미 관리창 확인을 끝낸 저장의 `learned` 값은 그대로 인정한다.
