## 크기와 연결

- 배치 기준 1×1칸. 기존 바닥 한 칸은 64×32픽셀이다.
- 각 그림의 투명 캔버스는 64×96, 지면 기준점은 (32,64).
- 담장은 칸 중심을 지나가는 낮고 얇은 벽이다. 칸 전체를 두꺼운 돌 덩어리로 채우지 않는다.
- 이번 3종은 같은 축의 **끝·반복·끝**이다. 길은 화면 왼쪽 위에서 오른쪽 아래로 이어진다.
- 다음 칸의 기준점은 이전 칸에서 (32,16) 이동한다. 같은 높이의 가로 나열이나 임의 간격으로 배치하면 연결되지 않는다.
- 좌측 끝 → 중간 0개 이상 → 우측 끝 순서로 사용한다. 미리보기는 좌측 끝 + 중간 4개 + 우측 끝, 총 6칸이다.
- 담장 자체는 약 0.25칸 두께, 게임용 보이는 높이는 약 21픽셀이다.
- 반대 축과 모서리, 단독 한 칸의 양끝 마감은 이번 제작 범위에 포함되지 않았다.

## 픽셀 정리

새 우물의 따뜻한 회색 돌색과 기존 2:1 바닥 기울기를 참고했다. 3개 생성 원본과 프롬프트는 아래에 보존했다.

- [중간 원본](중간_원본.png) · [최종 프롬프트](중간_프롬프트.txt)
- [좌측 끝 원본](좌_원본.png) · [최종 프롬프트](좌_프롬프트.txt)
- [우측 끝 원본](우_원본.png) · [최종 프롬프트](우_프롬프트.txt)
- [크기·원본/결과 SHA·공통 연결 영역 기록](선택_기록.json)

원본마다 알파 기준 128로 외곽을 정리하고, 종횡비를 유지한 채 전체를 최근접 축소했다. 끝 그림은 평행 이동으로 위치를 맞췄다. 가운데의 32픽셀 공통 구간을 세 그림 모두에 사용하며, 좌·우 그림에서 해당 끝의 4픽셀 마감 부분만 합성했다. 반복 구간에는 끝면 그림자를 넣지 않아 연결마다 검은 세로선이 생기는 것을 줄였다. 세 PNG는 공통 48색 팔레트와 0/255 알파를 사용한다.

재생성: 저장소 루트에서 `python tools/prepare_stone_wall_modules.py --install`. 쓰기 없는 검증: `python tools/prepare_stone_wall_modules.py`.

## 연결 상태

**이번에는 그림 제작과 연결 규격 준비까지 완료했다. 게임의 마을 배치에는 아직 적용하지 않았다.** 기존 낮은 담장은 4×0.5칸 오브젝트이므로, 이 1×1 모듈을 그 경로에 덮어써서 늘리는 방식으로 연결하면 기울기와 크기가 어긋난다. 실제 적용 단계에서는 1칸씩 나누어 배치하고 끝·중간을 선택해야 한다. 기존 우물과 낮은 담장 그림, 배치·충돌·조명은 유지했다.

## 검증

- 3개 PNG: 64×96, 공통 연결 영역 동일, 공유 48색 이하, 알파 0/255.
- 연결 경계의 위·아래 높이는 2:1 이동량에서 1픽셀 이내로 이어짐.
- 원본과 결과 SHA 기록, 기본 검증으로 결과 재현 확인.
- 별도 PNG 3개와 실제 바닥 위 6칸 연결을 눈으로 확인.
- 게임 코드와 데이터는 변경하지 않았다. Godot 실행 연결 검사는 적용 단계에 수행한다.
- 전체 에셋 검사 FAIL 0 / 기존 WARN 28, 문서의 깨진 링크·목록 누락 0. 후보 PNG는 별도 재현 검사로 픽셀 규격을 검증했다.
