등각 가구 정렬본 규격 (원본 픽셀 그대로, 크기 조절 없이 투명 여백만 추가)
- 캔버스: 1x1 = 64x128, 2x1 = 128x128, 작은 장식(plant_small) = 64x64 (에셋 규격서 "64의 배수")
- 기준점: 칸 윗면 마름모의 중심 = (가로 중앙, 아래에서 24px). 바닥 타일(64x64, 마름모 중심이 아래에서 24px)과 같은 규칙.
- 게임에서는 점유한 칸들의 마름모 중심에 그림의 (가로 중앙, 아래에서 24px) 지점을 맞추면 된다. 가구마다 따로 오프셋을 줄 필요 없음.
- 방향 번호는 임의(rot0=south-west, rot1=north-west, rot2=north-east, rot3=south-east). 게임 회전과의 대응은 코드 확인 필요.
- 기준점은 그림의 바깥 상자 가로 중심과 (폭/4) 위 지점으로 추정한 값이다. 눈으로 확인했다.
- 예외: 합성본(shelf_2x1_합성, magic_oven_합성)은 두 개를 이어 붙여 아래로 더 길어진다. magic_oven_합성 = 128x192 캔버스, 기준점(마름모 중심) = (가로 64, 위에서 152). shelf_2x1_합성 은 128x128, 기준점 (64,104) 그대로.

- 게임 회전 대응(2026-10-09 코드 확인): 파일 번호(rot0~3)는 카메라에서 본 앞면 방향 SW/NW/NE/SE 순이다. 게임 회전과는 다르므로 반드시 가구_등각/회전_대응.csv 를 쓴다.
  · 바닥 가구(furniture_footprint.gd, furniture_assets.gd 의 앞 방향 0=+z,1=+x,2=-z,3=-x): 게임 회전 0,1,2,3 -> SW, SE, NE, NW  (파일 rot0, rot3, rot2, rot1)
  · 벽 부착물(문 3종, 포스터·지도·깃발; store_view_3d.gd 의 wall_front_rot [0,3,2,1]): 게임 회전 0,1,2,3 -> SW, NW, NE, SE  (파일 rot0, rot1, rot2, rot3)
  · 2x1 가구는 게임 회전 1, 3 에서 1x2 로 바뀐다. SE/NW 그림은 긴 변이 "/" 방향이라 맞는다.

- wood_register 는 크기가 기존 계산대보다 커서(폭 99px) 소형판(wood_register_소형, 기존 계산대를 스타일 참조로 다시 생성)으로 대신한다. 회전_대응.csv 는 소형판을 가리킨다. 큰 판은 비교용으로 남김.
- 알려진 문제: 폭 96px 를 넘는 2x1 후보(wood_register 큰 판, shelf_2x1 rot1·rot2, magic_oven_ref)는 128x128 캔버스 아래쪽이 1~4px 잘렸을 수 있다. dough_table(폭 71px)은 64px 캔버스에 잘려 있으므로 합성에는 후보8방향 원본을 쓴다.

- 창고 선반은 게임이 저장 물품(층마다 최대 6개, 최대 3종)을 모델 위에 따로 올려 놓으므로(furniture_assets.gd _rack) 그림은 빈 틀을 쓴다. 회전_대응.csv 의 warehouse_rack, steel_warehouse_rack 은 *_empty 를 가리킨다. 물품이 그려진 기존 그림과 wood_warehouse_rack(물품 조금 있음)은 비교용으로 남김.
- 빈 틀 그림은 선반 판이 2단(맨 위 판 + 아래 판 1장)이다. 코드의 모델은 판 3장 + 맨 위 판이다.
