# 원정 보스6종 정적 그림 후보 (2026-10-11)

사용자의 계속 빈 그림 출력 요청에 따라 Codex 내장 `image_gen`으로 각 보스를 개별 생성하고, 이미 허용한 Python 픽셀 보정으로 정리했다. 기본 일반 몬스터3장의 외곽선·명암·등각 시점을 참조했다. 게임 실행에는 아직 연결하지 않았다. 애니메이션은 사용자 결정으로 보류한다.

- 공통 투명 캔버스128×128, 발밑 기준점 제안(64,112), 남서 방향 기본 자세1프레임. 비율을 유지하는 최근접 축소·32색 이하·이진 알파·투명RGB0. 캔버스 크기와 기준점은 후보 규격이며 타일 크기/충돌 크기를 뜻하지 않는다.
- 원본은 [생성_원본](생성_원본), 픽셀 정리본은 [픽셀_정리](픽셀_정리), 전체 프롬프트·참조·생성 경로는 [프롬프트.json](프롬프트.json)에 보존했다. 생성 결과를 다른 모델로 다시 그리지 않고 허용된 픽셀 정리만 했다. 원본의 종횡비를 왜곡하지 않았다.
- [보스 비교](보스_6종_비교.png)와 [일반/보스 같은 배율 비교](일반_보스_크기_비교.png). 유적 수호자의 두 눈과 가슴 문양은 원본 청록 영역 중심의 표본을 보존한다. 올리브색은 별도 강조색 팔레트로 처리한다.
- 바람갈기 수호수의 사자형 외형은 그림 후보 제안이며 종족·스토리·전투 능력의 확정을 뜻하지 않는다. 갈대뿌리 수호자는 뿌리·부들풀·돌의 실루엣으로 구분한다.

## 데이터 및 재현

[후보 목록](후보_목록.json)에 실제 enemies.csv의 ID·이름·boss 전리품 테이블·전투 이벤트를 대응했다. 데이터 몬스터24종(일반18/보스6)의 정적 기본 자세 후보가 모두 준비됐다. [전체24종 목록](../전체_후보_목록.json)과 [미제작 목록](../미제작_목록.json)을 참조한다. 반대 방향/전용 노멀맵/애니메이션까지 완성됐다는 뜻은 아니다.

저장소 루트에서 `python -X utf8 docs/그림_작업/받은그림/원정_몬스터/보스/픽셀_정리.py`로 보관된 원본을 재정리한다. 첫 원본 복사만 `--source-root C:/`를 붙인다. 원본은 덮어쓰지 않는다. 세 묶음(기본4/일반14/보스6) 중 어느 재현 스크립트를 실행해도 공통 [목록 갱신](../목록_갱신.py)이 전체 후보를 유지한다.

## 검사와 연결 후속

- [픽셀 검사](검사_결과.json): 6장 규격·알파·색 수·원본/정리본 SHA256 통과. 실제 CSV ID와 보스 테이블·전투 이벤트 대응 확인.
- [보존 검사](보존_검사.json): 기존 후보39PNG와 실행147+332PNG 해시 유지, 실행 manifest 의미 동일. 기존 일반18 재현 후 PNG 해시도 동일하고 세 재현 경로 모두 전체24종/미제작0을 유지했다.
- 후보 전체는 원정44종45PNG(채집15+상자1+회복샘1+환경3종4PNG+몬스터24종). 현재 게임 미연결이다.
- 게임 연결 때 방 모델의 원래 enemy ID를 유지해야 한다. 현재 `_build_enemies`는 공용 도형을 사용하며 보스 반경0.55/일반0.3으로 표시한다. PNG의 표시 크기는 실제 방에서 조정하되 공격 도달거리·충돌·가림을 그림만 보고 변경하지 않는다.
- 실제 시간대 빛/조명·노멀맵/전투/경제/저장 코드는 바꾸지 않았다. 이번에는 Godot 실행 검사를 새로 하지 않았다. 실제 보스 전투와 보행 가림 검사는 연결 후 필요하다.
- 문서 검사: 깨진 링크0/목록 누락0. 에셋 검사: FAIL0/WARN28(기존 경고 유지). diff 공백 검사 통과. docs 후보는 실행 에셋 검사의 대상이 아니므로 위 픽셀/해시 검사로 따로 확인했다. 다음 미제작 우선순위는 낚시터3곳이다.
