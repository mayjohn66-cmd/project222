# 매장 벽·창문·문 픽셀 후보
작성: 2026-10-10 · 기준: main의 기존 받은그림

## 1. 작업 범위와 승인

3D 표시를 그림으로 전환할 때 필요한 우선순위 1번 부품을 만들었다.
사용자가 이번 묶음은 Codex 이미지 생성을 허용했고, 기존 그림과 맞추도록 요청했다.
고해상도 후보의 픽셀 보정도 사용자가 명시적으로 파이썬 사용을 승인했다.
일반 Claude/Pixel Lab 담당 규칙은 그대로 적용한다.

기존 게임의 문·생산실 문·창고 문·진열대 그림을 참조했다.
원본 그림은 덮어쓰지 않았으며 이번 출력은 선택용 후보이다.
실행용 art/ 연결 및 3D 제거 코드 변경은 포함하지 않았다.

## 3. 픽셀 보정 방식

1. 알파 160 이상인 부품을 분리했다.
2. 최근접 축소로 64×128 캔버스에 배치했다.
3. 벽·창문은 공통 팔레트, 문은 기존 문 3종을 포함한 공통 팔레트로 정리했다.
4. 디더링 없이 불투명 색을 32개 이하로 줄이고 알파를 0 또는 255로 정리했다.
5. 열림·닫힘에는 쌍마다 같은 배율과 위쪽 문틀 기준을 적용했다.
6. 개별 프레임을 다시 확대하지 않고 아틀라스에 복사했다.

표시 기준 칸은 64×32, 선언 기준점은 (32,104)이다.
현재 게임 좌표의 96×48 크기와 저장/충돌 규칙은 변경하지 않았다.
캔버스 규격이 맞는 것과 실제 벽 한 칸의 길이·높이가 맞는 것은 별도로 확인해야 한다.
각 부품 바닥 정렬 기준은 y=116이고, 실제 연결 시 벽·문 배치를 조정해야 한다.

스크립트는 기존 픽셀_정리 폴더가 있으면 중단하여 결과를 덮어쓰지 않는다.
재생성은 검토 후 별도 출력 위치를 명시해 진행한다. 기존 후보를 삭제하고 실행하지 않는다.
Pillow와 Windows 맑은 고딕 글꼴을 사용한다. 프롬프트 재실행 결과가 같은 그림일 것을 보장하지 않는다.

## 4. 확인한 범위

- 개별 프레임 48개: 모두 RGBA 64×128, 알파 0/255, 불투명 RGB 32색 이하, 비어 있지 않음.
- 개별 PNG·고해상도 원본·기존 참조 그림의 SHA256을 기록값과 대조.
- 아틀라스 각 칸과 해당 개별 PNG의 픽셀 일치 확인.
- 기존 그림 크기 비교 및 전체 시트를 시각 검토.
- 문은 기존 갈색 문틀과 청록 계열 장식을 참고했으며 유리 색은 원본보다 민트색에 가깝다.

기존 validate_assets.py 검사는 전체 저장소의 FAIL 유무를 확인한다.
이번 docs/ 후보는 실행 에셋 분류에 포함되지 않으므로 위 개별 검사를 별도로 수행한다.
이번 작업은 실행 코드·씬·게임 데이터에 연결하지 않아 게임 실행 검증을 새로 수행하지 않았다.

### 저장소 검사 결과

- 개별 검사: 48프레임·48아틀라스 칸·원본 3장·참조 4장, 실패 0.

- python -X utf8 tools/code/docs_check.py: 깨진 링크 0, 목록 누락 문서 0.
- git diff --check: 오류 0.

## 5. 실제 연결 전에 남은 조정

- 방향 번호 0~3은 생성 시트의 슬롯이다. 게임의 회전 대응을 확정한 값이 아니다.
  일부 앞/뒤 후보가 비슷하여 실제 네 방향으로 모두 확인했다고 할 수 없다.
- AI가 문틀 형태도 일부 변경했다. 같은 배율·문틀 상단 정렬만으로 문틀/문턱이
  열림·닫힘 사이에 픽셀 단위로 동일하다고 보장하지 않는다. 문짝만 움직이도록 추가 합성이 필요할 수 있다.
- 벽·모서리·창문 간 길이·높이와 반복 이음새는 실제 지도에서 맞춰야 한다.
- 2D 전환 코드의 실제 경계 구간을 기준으로 연결하고 충돌·Y 정렬·문 통과·확장/방 전환을 확인한다.
- 사용자가 선택한 부품만 art/에 복사한 뒤 문 상태 전환과 벽 렌더링을 연결한다.

후속 담당자는 픽셀 후보를 연결 완료 에셋으로 간주하지 않는다.
기존 그림 복구는 실행 코드 변경이 없으므로 필요하지 않다.

## 6. 연결 후 반복 면 보정 (2026-10-10)

사용자 요청으로 실행용 중앙 면 8장(높은 벽/창문 각4방향)의 불규칙한 경사를 2:1로 보정했다.
이 문서의 픽셀_정리 원본48장은 그대로다. 수정본은 `art/received/shop_shell/*_tile.png`에 연결했다.
[재현 도구](../../../../tools/art/normalize_shop_wall_tiles.py)는 원본 색상열에서 최근접으로 보정하며
기준점(32,104)·반복 폭32·높이 이동±16·공통 테두리/띠를 맞춘다. 새로운 이미지 생성 호출 없음.
`--check`로 8장과 팔레트/알파/이음새를 검사한다. 원본 덮어쓰기 없음.
자세한 실행·화면 검사 및 한계는 [매장 상태 그림 연결](../../../콘텐츠/검토/매장_상태_그림_연결.md)의 마지막 절.

## 7. 높은 벽 끝단 옆면 연결 (2026-10-14)

사용자 실행 화면의 왼쪽·오른쪽 모서리는 높은 벽과 낮은 창문 벽의 접점이다. 반복 타일의 기울기와 바닥 경계 좌표는 맞았지만 높은 벽에 끝단 옆면이 없어 잘라 놓은 종이처럼 보였다.

- `WallJunctionArt`가 실제 경계 선분 중 높이가 바뀌는 직각 접점만 찾는다. 기존 벽 두께0.3칸에 해당하는 **원본 타일 끝10px**를 옆면으로 표시한다.
- `ReceivedWorldArt.billboard`에 선택적인 표시 영역을 추가했다. 같은 원본 PNG의 색·노멀맵·ID 마스크 영역을 함께 참조한다. 기준점(32,104)·배율1·2:1 기울기를 유지하고 좁은 면을 늘리지 않는다.
- 원본PNG·해시 목록·저장·충돌·가구·문 배치·낮밤 조명은 유지한다. 새 그림 파일이나 모델 폴백을 추가하지 않는다. 벽이 다시 만들어지면 끝단도 갱신하며 중복되지 않는다.
- 기본 매장 네 모서리를 같은 카메라/정오 조명·3배 확대에서 비교했다. 높이 전환2곳은 보정됐고 높은 벽끼리/창문 벽끼리 만나는 나머지2곳의 캡처 픽셀은 전후 동일하다.

실제 GPU `check_pixel_shop_art` **1958항목 실패0**: 기존 원본 해시·가구 상태·문·조명·반복 면 검사와 두 끝단의 원래10px 폭·색/ID 영역 일치·원본 재사용·재생성 중복 방지를 확인했다. 모든 사용자 저장 배치를 직접 플레이한 검증은 아니며 사용자 디자인 확인은 별도다.

가져오기2회 ERROR/SCRIPT ERROR0, 임시 캡처 장면을 포함한 전체972 리소스 로드실패0, 에셋FAIL0·기존WARN23, 문서 링크/목록0. 이전 Windows RC1은 재빌드하지 않았다.

## 8. 벽 두께 보강 (2026-10-14)

사용자 후속 요청으로 공통 표시 두께 `StoreView3D.WALL_THICKNESS`를 **0.3칸→0.5칸**으로 늘렸다. 끝단 옆면은 원본10px 대신16px를 참조하므로 픽셀을 늘리거나 새 PNG를 만들지 않는다. 같은 두께를 읽는 매장·생산실·창고의 표시 범위도 함께 반영된다.

두께는 실내 경계 바깥으로 늘린다. 기존 벽 높이·실내 바닥 크기·문 기준점과 물리 충돌선은 유지한다. 모서리의 몰딩·띠·걸레받이도 같은 원본16px를 사용하며 기존 노멀맵 조명을 받는다. 다음 두께 조정도 이 공통 상수에서 한다.

실제 확대 화면의 양쪽 끝단을 확인했고 GPU `check_pixel_shop_art` **1960항목 실패0**: 기존 그림·가구·문·방·조명 검사와16px 원래 비율/바깥0.5칸 범위를 확인했다. 사용자 디자인 확인은 별도다.

가져오기 첫 시도는 CSV 재가져오기 중 엔진 자체가0xC0000005로 종료됐으나 이후2회 모두 정상 종료/ERROR·SCRIPT ERROR0였다. 전체972 리소스 로드실패0, 에셋FAIL0·기존WARN23, 문서 링크/목록0. 이전 Windows RC1은 재빌드하지 않았다.
