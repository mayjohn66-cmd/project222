# 직원 진열 동작 — 2026-10-13

## 적용 범위

사용자 요청: 직원이 진열하는 스프라이트를 출력하고 게임에 적용한다.
플레이어는 진열 UI가 가리므로 동작을 추가하지 않는다. 다른 업무 동작은 이번 범위에 포함하지 않는다.

- 기존 직원 `worker_001`, `worker_002`, `worker_003`의 얼굴·모자·머리와 발 그림을 유지한다.
- 남동·남서·북서·북동 4방향, 방향마다 4장, 총 48장이다.
- 작은 상자 들기 → 손 뻗기 → 놓기 → 손 거두기. 상품별 그림을 생성하지 않는다.
- 북동 방향은 생성된 북서 **팔 부분만 반전**하고, 기존 북동 얼굴·머리·발에 합성했다. 별도 북동 생성 원화라고 표현하지 않는다.
- 남서 방향의 두 번째 자세는 원화가 반대쪽으로 뻗어 남동 팔 부분을 반전해 보정했다. 각 프레임의 원화 행과 반전 여부를 목록에 기록했다.
- 기준은 기존 64×64 캔버스·기존 방향별 발 앵커와 인물 배율이다. 가로·세로를 따로 축소하지 않았다.

## 원본과 제작

내장 `imagegen`으로 기존 직원 참조 시트와 동작 시트를 만들었다. 최초 결과는 행 누락·방향 전환 때문에 보류하고, 한 번 수정해 4열×9행(836×1881 RGBA) 원본을 얻었다. 모델 이름은 별도로 확인되지 않았으므로 추정하지 않는다.

- [게임용 동작 점검 시트](동작_점검.png)
- [반복 미리보기 GIF](진열_미리보기.gif) — 120/240/280/160ms, 반복은 미리보기용이며 실제 작업은 한 번만 재생한다.
- [프레임 경로·SHA256·반전 출처](프레임_목록.json)
- [최종 생성 프롬프트](생성_프롬프트.txt)
- 분리·최근접 축소·원본 팔레트 정리·머리/발 합성: `tools/art/prepare_employee_restock.py`.
- 원본 얼굴 영역의 불투명 픽셀과 발 영역(51~63행)을 보존한다. 상자와 팔이 얼굴 주변의 투명 영역으로 뻗을 수 있게 얼굴 아래쪽은 마스크로 보존했다. 몸통 중간의 팔·상자 영역은 새 그림이다.
- 게임 PNG는 알파 0/255, 원래 직원 색상에 상자 색 3개만 추가한다. 원래 걷기·정지 PNG는 수정하지 않았다.

```text
python -X utf8 tools/art/prepare_employee_restock.py
```

기본 실행은 저장된 48장·해시·보존 픽셀을 검사한다. 다시 추출할 때만 `--write --source <생성 원본 경로>`를 사용한다.

## 게임 연결

`EmployeeRestockAnimation`은 실제 직원의 `RESTOCK` 상태와 `pending_shelf`를 읽는다. 이동 중에는 기존 걷기를 사용하고, 도착한 뒤 진열대 중심을 향해 작업한다. 완료·상태 변경·진열대 제거 시 작업 그림을 해제한다. 일시정지 동안 진행률은 멈춘다.

`StoreView3D`와 `PixelActorFigure`의 기존 도트·알파 정렬·법선 광원 경로로 출력한다. 이름에 3D가 들어가지만 새 입체 인물 모델을 만들지 않고 PNG 프레임을 바꾼다.

기존 `worker.gd`, 진열 시간·교육 효과·재고 소비·진열대 용량·급여·고용·저장은 변경하지 않았다. 렌더러는 아이템을 지급하거나 소비하지 않는다. 재고 이동은 기존 `worker_restock()` 한 번으로 처리한다.

## 검증

- PNG 48장: SHA256·64×64·알파·원본 머리/발 보존 검사 통과.
- 실제 직원 3명·기존 진열 타이머·실제 진열대 보충 GPU 검사: **162개, 실패 0**. 네 작업 프레임 출력·컬러/정렬 마스크 일치·일시정지·완료 복귀·진열대 삭제·중복 재고 이동 방지·플레이어 제외 확인.
- 기존 플레이어·손님·직원 방향/걷기 검사 **1809개, 실패 0**. 작업 상태가 없는 연출용 인물도 안전하게 제외한다. 전체 스크립트/장면 로드 927개 실패0, 가져오기 2회 ERROR0, 그림 검사 FAIL0/WARN23(기존 경고), 문서 링크/목록 문제0.
- 최신 `main`의 낚시 변경 `72adfa86`을 충돌 없이 통합한 뒤 가져오기 2회 ERROR0, GPU 진열162 실패0, 전체 로드 **931개 실패0**를 재확인했다. 직원 연결 소스는 `006cb414`이다.
- 실제 실행 프레임 4장: [손 뻗기](실행_확인/진열_002.png). 검사 장면은 진열 기능을 분리 확인하는 격리 저장을 사용한다.
- 정적 원화와 실행 프레임은 확인했다. 사람이 동영상 재생을 보며 평가하는 동작 품질 검토는 미확인이다.
- 기존 Windows RC1 실행 파일은 이번 변경으로 재빌드하지 않았다. 적용 대상은 프로젝트 소스이다.
