# 그림 파일 정리 계획과 완료 기록

2026-10-12 사용자에게 계획을 공유한 후 「목록의 64개와 동반 import 삭제 진행」 승인을 받았다. 아래 정확한 그림64개·import64개 삭제를 완료했다. 아래 계획 절은 승인받은 범위의 이력이다.

## 최신: 정리 완료

- 최신 main `5a0afa53`에서 참조를 다시 검사해 승인 목록64개가 일치함을 확인했다. 백업 SHA256·128개 파일의 해시·최종 절대경로가 저장소 art/ 내부인지 모두 확인한 뒤 파일만 삭제했다. 폴더 전체 재귀 삭제는 하지 않았다.
- 삭제된 그림15,603,069바이트(14.88MiB), import64개 별도. 삭제 Git diff가 승인한128파일과 정확히 일치한다. `files.txt`에 남아 있던80개 이전 파일 항목도 정리했다.
- [삭제 후 참조 요약](삭제후_참조_목록.json): art/2,012개는 정적참조1,001·동적루트보호1,011로 유지. 같은 보수적 검색 기준의 추가 미참조 후보0. 동적 루트 내부 전체가 실제 사용된다는 뜻은 아니며, 폴더별 추가 정리는 실제 로더/데이터 검토가 필요하다.
- 남은 추적 그림5,908개(받은 원본·보정본·검사 그림 포함)의 SHA256이 삭제 전과 모두 동일하다. 원본을 이동하거나 덮어쓰지 않았다.
- 삭제된 파일과 `.godot` 캐시가 없는 새 격리 복사본을 만들고 Godot4.7.1 가져오기2회·2차 ERROR0를 확인했다. 기존 캐시로 누락이 가려지는 상황을 제외했다.

| 확인 | 항목 수 | 실패 |
|---|---:|---:|
| 전체 gd/tscn 로드 | 914 | 0 |
| 활성 그림 감사 | 1777 | 0 |
| 매장 진열·문·벽·빛 실제 GPU | 1954 | 0 |
| 원정 인물·몬스터·채집 그림 실제 GPU | 1014 | 0 |

| 실제 타이틀→새게임→첫대화 GPU | 14 | 0 |

- 실제 매장·숲 원정·낚시·첫 대화 캡처를 확인했다. 캡처와 로그는 작업 폴더 `work/art-cleanup-*`에 보관하고, 검사용 그림을 중복해서 실행 art/에 넣지 않았다.
- 에셋 검사 FAIL0/WARN23(삭제 전30), 문서 검사 깨진 링크/미등록0. 기존 번역 NUL·문 Collision 경고는 그대로다. 최종 SCRIPT ERROR/ERROR0.
- 초상화 옛 검사에서 「앉으면3D모델」 기대가1개 실패했다. 테스트 복사본에128개 삭제 파일을 모두 복원한 baseline에서도 동일43항목/1실패였으므로 삭제 때문이 아님을 확인했다. `dev/script/check_player_portraits.gd`를 현재 남녀4방향 좌식 그림이 읽히고 미제작 자세만 fallback 되는 기준으로 갱신해59항목/0실패. 테스트의 튜토리얼 자동 연출도 끄고 독립적으로 검사한다. 실제 게임 자세 로직은 수정하지 않았다.
- 첫대화 임시 smoke 검사는 처음에 숨겨진 다른 대화창을 찾아3개가 실패했다. 실제 TutorialDirector.dialogue와 Label의 font 속성을 검사하도록 준비 코드를 정정한 뒤14/0실패·실제 표시 확인. 이 준비 코드는 소스 저장소에 넣지 않았다.
- 복구 ZIP128파일은 아래 백업 경로에 유지하고, [삭제 경로·기존 해시·검사 결과](삭제_후보.json)에 완료 상태를 기록했다. 기존 Windows RC1은 그대로이며 용량 변화는 다음 빌드에서 별도 확인한다.

## 1. 범위와 결과

- 검사 기준 main 커밋: `72987750a021ce5f60d12ce9943b578f0c5d01e3`. 삭제 실행 직전에 최신 main으로 다시 검사한다.
- Git에 등록된 그림 5,970개 검사. art/ 2,076개 중 정적 경로 참조1,001·동적 폴더 보호1,011·미참조 후보64. 정적 참조는 모든 기존 코드/데이터 기준이며 현재 main 씬에서 실제 도달함을 증명하는 수치는 아니다.
- docs/ 원본·후보·비교·검사 그림3,760개, dev/84개, screenshots/·씬 검사 그림49개, 에디터 플러그인 아이콘1개는 이번 삭제 대상에서 제외한다.
- 문자열로 조립하는 회전/표정/타일·노멀맵과 제작 매니페스트가 지정한 원본을 보호한다. 특히 art/received/ 및 art/actors/·world3d/ 같은 동적 루트는 보수적으로 보존했다.
- 단순히 폴더에 v1/v2가 붙었다는 이유로 지우지 않는다. 현재 경로 참조가 남은 파일은 보호한다.

## 2. 제안하는 첫 정리

아래 64개와 각 파일의 `.import` 64개(합계128파일)만 삭제 대상으로 제안한다. 그림 합계15,603,069바이트(14.88MiB). 게임의 활성 그림·CSV·코드·공통테마 참조를 삭제하는 계획은 아니다.

| 폴더 | 그림 수 | 근거 |
|---|---:|---|
| `art/expedition/` | 8 | 현재 원정 그림으로 교체된 옛 지역 배경 PNG4·임시 SVG4 |
| `art/portraits/player/` | 14 | 현재 aligned/14종 사용. 옛14종은 받은그림 원본과 SHA256동일 복사본이며 원본 보존 |
| `art/ui/pixel_theme/` | 26 | 현재 테마/씬/코드에서 참조하지 않는 이전 아이콘·슬롯·탭·슬라이더 조각 |
| `art/ui/reference_theme/` | 1 | 테마에서 참조하지 않는 title.png |
| `art/world/cozy_v3/` | 4 | 현재 그림 연결에서 사용하지 않는 초기 단색 바닥4종 |
| `art/world/ground/` | 6 | 현재 그림 연결에서 사용하지 않는 초기 바닥6종 |
| `art/world/plaza_props_v1/` | 5 | 현재 매니페스트/코드에서 선택하지 않는 초기 약초 노점·수레 시안5종 |

파일명 검색만으로 삭제를 확정하지 않는다. 동적 폴더를 제외하고 현재 코드·데이터·장면·테마에서 정확한 경로/변형 패턴을 다시 검토한 후보다. 옛 문서·files.txt의 역사적 파일 목록에 남은 경로는 함께 검토하고, 활성 검사·재현 도구 입력이 새로 발견되면 후보에서 뺀다.

## 3. 백업과 삭제 후 검사

- 삭제 전 복구 ZIP: `work/image-cleanup-backup-20261012.zip` (15,515,800바이트,128파일). ZIP CRC 검증 통과. SHA256 `401e2c97392d045b10e01225d28236849e8aff9b26f4de0d5d0d2fc97bbbccbd`.
- 승인 후에는 최신 main 참조와 모든 후보/동반 import의 해시·최종 절대 경로가 저장소 art/ 안인지 재검증하고 목록의 파일만 지운다. 폴더 전체 재귀 삭제는 하지 않는다.
- 원본·받은그림·보정된 초상화·실행에 연결된 회전/상태 그림은 보존한다. 삭제 목록과 기록은 Git으로도 복구 가능하다.
- 삭제 후 가져오기2회·전체 gd/tscn 로드·활성 그림 감사·에셋 검사·새게임/첫 대화/원정/진열/낚시의 대표 그림 표시를 확인한다. 실패하면 해당 후보를 복구해 삭제 커밋에서 제외한다.
- 이번 준비 단계: 부제 없는 실제 GPU 타이틀92항목 실패0,1152×648/800×600·새게임/이름창/취소 확인. 기존 활성 그림 감사1777 실패0. 아직 그림을 삭제하지 않았으므로 삭제 후 성공으로 보고하지 않는다.
