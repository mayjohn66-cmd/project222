# 날씨를 따라온 인사

2026-10-05 · main 콘텐츠 추가

날씨를 바라보는 주민의 말이 진열 준비와 실제 구매로 이어지는 생활 이야기 3개다. 기존 공용·계절 매장 행사와 함께 작동한다. 처음 이야기를 만나는 조건만 날씨로 정하며, 이야기를 들은 뒤에는 날씨와 계절이 바뀌어도 기다릴 수 있다.

## 이번에 추가한 이야기

| 이야기 | 첫 만남 조건 | 말하는 사람 | 실제 진열 구매 | 구매 다음 날의 최초 답례 |
|---|---|---|---|---|
| 비를 기다리는 도시락 | 계절 무관, 지금 비가 내림 + 현지식 빵 제조법 학습 | 기존 배낭 여행자 | 현지식 빵 ×2 | 밀 ×2, 평판 +1 |
| 볕 아래 열매 한입 | 여름, 지금 맑음 | 기존 마을 주민 | 야생 열매 ×2 | 숲 약초 ×2, 평판 +1 |
| 눈길의 마른 불쏘시개 | 겨울, 지금 눈이 내림 | 기존 광부 | 마른 가지 ×3 | 석탄 ×2, 평판 +1 |

모두 핵심 튜토리얼 완료와 첫 주민 정착으로 마을 게시판이 열린 뒤 시작한다. 빵은 처음 편의점에 남았던 `bread`가 아니라 현지 재료로 만드는 `camp_bread`다. 여름 볕은 온도 모형을 새로 만들지 않고 기존 여름·맑음 조건을 사용한다. 가을에도 비 이야기와 기존 가을 콘텐츠를 만날 수 있다.

## 실제 진행

1. 해당 날씨에 마을 게시판 근처의 방문자에게 가까이 가서 [E]. 말을 끝까지 듣는다. 비에 불을 피우지 못하거나, 볕 아래 열매를 찾거나, 눈길에서 불쏘시개를 찾는 구매 이유를 설명한다.
2. 수첩에서 필요한 진열 상품과 수량을 확인하고 가게를 연다. 대표 손님이 해당 재고가 충분할 때 기존 손님 생성 흐름에 합류한다. 우선 처리 중인 첫 방문 소개·단골·원정 만남은 유지한다. 주문 상품은 진열대에서 꺼내며 기존 직원/직접 계산 흐름으로 실제 결제한다.
3. 실제 결제 직후 구매 이유를 짧게 말한다. 이 말은 기존 짧은 손님 발언 표시를 사용하므로 다른 발언이 표시 중이면 생략될 수 있다. 이야기 진행은 발언 표시 여부와 무관하게 실제 결제로 기록된다.
4. 구매 다음 날 이후 같은 직군의 대표 방문자가 게시판 근처에 돌아온다. [E] 대사를 끝까지 들을 때만 작은 재료 답례와 평판을 최초 1회 지급한다. 추가 창고 재료 전달은 없다. 상품 대금은 결제 당시 기존 가격으로 이미 받은 금액이다.
5. 답례 다음 날 이후 [E]로 후일담을 듣고 수첩에 기억을 남긴다. 추가 선물은 없다.

재고 부족·대화 중단·가게 닫기·날씨 종료에 벌점이나 기한이 없다. 소개를 아직 듣지 않았다면 날씨가 끝날 때 방문자가 물러나고 다음 적합한 날씨에 다시 기다린다. 소개 완독 이후는 계절이 넘어가도 구매·답례·후일담이 이어진다. 화면의 현재 날씨와 다른 날의 회상은 구별하여 대사를 작성했다.

## 연결과 저장

- `WeatherLifeFlow`가 현재 가게 `DayManager`의 시·분과 `WorldWeatherData.forecast()`를 읽는다. 실제 비/눈 시간 경계와 3D의 F7 개발 날씨를 함께 사용한다. 하루 예보만 보고 온종일 비라고 판정하지 않는다.
- 기존 `RegularCustomerDirector`를 별도 설정으로 재사용한다. NPC가 플레이어·다른 배우·시설에 겹치지 않는 기존 배치 규칙, 접근 E, 대화 중 시간/이동 정지와 이전 상태 복원을 유지한다.
- 최신 3D 통합 `main` @ c24adc9를 먼저 받았다. `VillageResident`를 기존 3D 배우 그룹에 등록하고 그림 노드 이름을 맞춰, 방문자도 실제 3D 인물로 표시하면서 2D 그림만 숨기고 상호작용/이름표는 유지한다. 기존 주민·단골·원정 방문자가 같은 공통 처리를 사용한다.
- 같은 이벤트의 쇼핑 손님이 남아 있으면 대화 방문자를 복제하지 않는다. 첫 소개·단골·원정 만남과 날씨 이야기는 별도 메타/진행 키를 사용한다. 같은 직군의 보통 손님이나 미결제·다른 상품·부족 수량 구매로는 진행되지 않는다.
- `weather_life:<id>:intro/bought/done/after` 날짜를 기존 `PlayerProgress.story_beat_days`에 저장한다. 평판은 `resident_request:reputation:weather/<id>`를 사용한다. 저장 형식·버전을 늘리지 않았다. 옛 구매를 소급 인정하지 않고 새 게임에서는 초기화한다.
- 수첩에 첫 만남 조건·제조법 조건·진열 준비·답례·기억과 실제 방문자 위치를 등록한다.

## 대사 보강

이번 추가는 **생활 이벤트 3개·대사 12장면**, 전체 대사 CSV **289행**이다. 기존 개인 부탁 20개·단골 3개·원정 만남 3개를 유지한다. CSV 행 수는 퀘스트 수가 아니다.

`default_weather_life.tres`의 기계 `events`를 제외하고 글 `moments`만 기존 `service_text`로 등록했다. `requests_text.csv`에 초안, 별도 `content_voices.csv`에 장면 제약을 남겼다. 정식 이름·말투 기준은 유지한다. API 호출 없이 사용자가 다음 명령으로 Gemini에게 보강을 맡길 수 있다.

```bat
dev\gemini\run_request_text.bat draft service_text --ids weather_rain_lunch_intro,weather_rain_lunch_bought,weather_rain_lunch_finish,weather_rain_lunch_after
dev\gemini\run_request_text.bat draft service_text --ids weather_summer_berries_intro,weather_summer_berries_bought,weather_summer_berries_finish,weather_summer_berries_after
dev\gemini\run_request_text.bat draft service_text --ids weather_snow_kindling_intro,weather_snow_kindling_bought,weather_snow_kindling_finish,weather_snow_kindling_after
```

현지인은 자신의 생활 경험과 상품을 찾는 이유를 말한다. 상품 수량·가격·평판·조작은 UI 몫이다. 새 인물 이름·시설·제조법·무료 상품·회복·확정 인파를 약속하지 않는다.
