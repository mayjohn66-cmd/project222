# 그림 규격서 — 3D 도트 방식 (초안 v0.1)

작성일: 2026-10-02 · 근거: `docs/그림_3D/도트_기법_참고.md`(기법과 시험 결과), `dev/spike3d/`(시험 장면)
관련: `docs/그림_3D/에셋_규격서.md`(기존 2D 규격. 월드·매장 그림은 이 문서가 **우선**하고, 아이콘·UI·원정 2D 그림은 기존 규격을 따른다 🟡)

## 0. 사용법

- 태그: ✅ 사용자가 결정 / 🟡 초안 제안(시험으로 확인 중) / ❓ 미정
- 그림을 만드는 쪽은 **3장(칸·질감), 4장(오브젝트), 5장(캐릭터), 6장(빛·법선 맵)** 의 표를 따른다.
- 이 방식은 **3D 모델에 작은 도트 질감을 씌워 낮은 해상도로 그린 뒤 정수 배로 늘려** 도트처럼 보이게 한다. 그래서 "스프라이트 한 장"이 아니라 **면별 질감**을 그린다.
- 지금까지의 시험은 이 개발 환경의 **소프트웨어 렌더링**에서만 했다. 실제 PC(GPU)에서 같은지는 확인 전이다. 질감은 코드로 만든 임시 그림이었고, Pixel Lab 으로 이 규격의 그림을 만들 수 있는지도 확인 전이다.

## 1. 결정 사항

| 항목 | 내용 | 상태 |
|---|---|---|
| 표현 방식 | 3D 로 그리고 낮은 해상도 → 최근접 확대(Never's End 방식). 픽셀 스냅, 정렬 순서 깊이, 한 픽셀 윤곽선 사용 | ✅ |
| 확대 배율 | **3배** (2배는 선명하지만 3D 느낌이 강해서 제외). 2.5배는 정수 픽셀이 안 맞아 쓰지 않는다 | ✅ |
| 칸 크기 | 낮은 해상도 기준 **36×18** (2.5배에 가까운 쪽. 화면에서 칸이 기존 96×48 보다 약 12% 크게 보임) | ✅ |
| 캐릭터 비율 | **3등신** — 머리·몸통 크기는 기존 2.5등신 캐릭터 그대로, **팔다리만 늘림** | ✅ |
| 캐릭터 제작 방식 | **상자 캐릭터**(부품 상자에 면별 질감) | ✅ |
| 표정 | 월드 캐릭터는 **표정을 그리지 않는다**(눈 점 1px 정도까지). 구분은 머리색·옷색·모자 실루엣, 감정은 머리 위 아이콘, 표정은 대화 초상화에서만 | ✅ |
| 시점 | 위에서 30° 내려다봄, 45° 돌림(2:1 마름모). 완전한 정면이 아님 | ✅ |
| 빛 | **법선 맵**으로 요철 음영을 만들고, 낮/밤은 빛의 방향·색·세기로 구분 | ✅ (시험 전) |

## 3. 질감 규격 (칸·바닥·벽)

| 종류 | 크기 | 비고 |
|---|---|---|
| 바닥 질감 | **18×18** (이음매 없이 반복) | 한 칸에 1장. 위에서 보면 마름모로 보인다. 칸 폭의 절반 = 질감 한 변이라야 질감 1픽셀 = 화면 1픽셀이 된다 |
| 벽·가구 옆면 | 폭 **18** × 높이 **22 × 블록 수** | 한 칸 폭이 화면에서 18px 로 보임 🟡 (시험은 18×18 반복이라, 높이는 실제 그림으로 확인 필요) |
| 윗면 | 칸 수 × 18 | 2×1 칸 윗면 = 36×18 |

- ✅ **색 수**: 질감 한 장당 8~12색, 장면 전체 공용 팔레트 ❓ (기존 규격 3장 5항과 같은 이슈).
- ✅ 알파는 쓰지 않는다(불투명). 투명이 필요한 소품은 4장의 스프라이트형으로 만든다.
- 🟡 **외곽선을 그림에 넣지 않는다.** 물체 경계의 1px 윤곽선은 코드가 후처리로 그린다(기존 규격 3장 3항과 다름). 벽돌 줄눈·판자 틈 같은 **안쪽 선**은 그려도 된다.
- 🟡 질감의 **그림자·빛 표현을 넣지 않는다.** 밝고 어두움은 코드의 빛(6장)이 만든다. 질감은 "빛이 없을 때의 색"으로 평평하게 칠한다.

## 4. 오브젝트(가구·소품) 규격

두 종류로 나눈다.

**A. 상자형 (진열대, 계산대, 테이블, 벽, 문틀 등)** — 대부분
- 크기: **발자국 칸 수(가로×세로) × 높이 블록 수**로 정한다.
- 그림: 윗면, 앞면(왼쪽 아래를 보는 면), 옆면(오른쪽 아래를 보는 면) 질감 3장(+법선 맵 3장). 뒷면은 안 보인다.
- 발자국 상자가 **충돌 범위이자 정렬 범위**다(별도 충돌 모양을 그리지 않는다).

| 오브젝트(시험 값) | 발자국 | 높이 |
|---|---|---|
| 진열대 | 2×1 (실제 두께는 0.6칸) | 1.6블록 (35px) |
| 진열 테이블 | 2×1 | 0.9블록 (20px) |
| 계산대 | 1.5×1 | 1.1블록 (24px) |
| 벽 | 길이 × 두께 0.5 | 3블록 (66px) — 시험 장면 값. 실제 게임은 안쪽 2.0 / 도로 쪽 1.3 |
| 문 | 2칸 폭 개방(입구/출구) | — |

→ 위 값은 시험용이다. **실제 게임의 값**(`build_objects.csv`, 각 `*_visual.gd` 에서 읽음, 자세한 표는 `docs/그림_3D/매장_3D_적용_계획.md` 1.2):

**단위 정정(2026-10-02)**: 앞서 이 표의 "3D 환산" 열은 2D 의 화면 px 를 낮은 해상도 블록(22px)으로 바로 나눠서 **3배 크게** 나왔다(화면 3px = 낮은 해상도 1px). 올바른 환산은 `낮은 해상도 px = 2D px × 36 ÷ 96`(= ×0.375)이다. 캐릭터도 2D 64px → 24px 로 3D 캐릭터(25px)와 맞는다.

| 가구 | 발자국 | 기존 2D 높이(96칸 기준 px) | 올바른 환산(낮은 해상도 px) | 블록(22px) |
|---|---|---|---|---|
| 진열대 한 층 | 1~3 × 1 | 22 (최대 3층) | 8px | 0.4 (그림은 이보다 높게 그려져 있어 기하 높이로는 부적절) |
| 계산대 | 2×1 | 24 | 9px | 0.4 (같은 이유) |
| 문 | 1×1(벽에 붙음) | 110 | 41px | 1.9 |
| 창고 선반 | 2×1 | 36 | 14px | 0.6 |
| 매장 안쪽 벽 | 얇음 | 120 | 45px | 2.0 |
| 도로 쪽 벽 | 얇음 | 75 | 28px | 1.3 |

- 가구(진열대·계산대)는 2D 코드값이 작아서(그림이 따로 높게 그려짐) **캐릭터 25px 와의 비율**로 정한 값(아래 표)을 쓴다. 벽·문은 2D 값의 환산을 그대로 쓴다.
- 생산 설비·장식은 코드값이 없어 제안값을 쓴다.

**확정 높이(3D, 블록 = 22px)** 🟡 — 2D 코드의 px 값은 그림이 따로 높아서 기하 높이로는 부적절해, **캐릭터(25px)와의 비율**로 다시 정했다. 사용자 승인(2026-10-02)에 따라 이 값으로 진행하고 시험하며 조정한다.

| 가구 | 상자 높이(블록) | 비고 |
|---|---|---|
| 진열대 | 1단 **1.4**, 쌓을 때마다 **+1.0**(최대 3단 3.4) | 상자형, 발자국 N×1, 두께 0.5칸 |
| 계산대 | **1.1** | 상자형 2×1, 두께 0.5칸 |
| 매장 안쪽 벽 | **2.0** (45px) | 2D 120px 환산 |
| 도로 쪽 벽 | **1.3** (28px) | 2D 75px 환산 |
| 문(벽에 붙음) | 구멍 높이 **1.9** | 2D 110px 환산. 도로 쪽 벽(1.3)보다 높아 안쪽 벽에만 달 수 있음 ❓ |
| 음료 제조기 | **1.6** | 상자형 1×1 |
| 화덕 | **1.4** | 상자형 2×1 |
| 작은 화분 | **0.8** | 스프라이트형 |
| 심야의 등불 | **1.8** | 스프라이트형(밤에 발광 ❓) |
| 골동품 진열장 | **1.8** | 상자형 1×1 |
| 벽 포스터·세계지도·깃발 | 판 높이 **1.0**, 바닥에서 **1.0** 위 | 벽 면에 붙는 얇은 판 |
| 창고 선반(범위 밖) | **1.8** | 2×1 |

- 진열대와 계산대의 충돌·정렬 상자 두께는 **0.5칸**(기존 `depth_ratio`), 창고 선반은 1.0칸.

**B. 스프라이트형 (병·상품·화분·장식 등 상자로 안 되는 작은 것)**
- 한 장짜리 판, 아래 크기 기준. 판은 카메라를 향해 서 있고, 정렬 상자는 발 밑 작은 상자로 쓴다.
- 크기: 폭·높이 자유(최대 64, 바닥 한 칸 폭 18 의 배수를 권장), **알파 0 또는 255**, 발 중앙 하단이 기준점.
- 법선 맵은 선택(6장).

## 5. 캐릭터 규격

### 5.1 비율과 크기 ✅
- **3등신, 전체 키 1.14칸 ≈ 25px**. 머리는 기존 2.5등신 캐릭터와 같은 크기(0.38칸 ≈ 8.4px)이고 몸통도 그대로, **팔과 다리만 길게** 한다(다리 약 10px, 팔 약 9px).
- 머리 폭 약 9px(높이의 1.1배), 몸통 폭 약 7px, 팔·다리 폭 2~3px.
- 정정: 앞서 표에 "3배에서 캐릭터 약 21px"라고 적었는데 실제로는 약 18.6px(32×16 칸 기준)였다. 정렬 상자 높이를 캐릭터 키로 오해한 계산 실수.

### 5.2 구분 방법 (표정 대신) ✅
- 머리색(5종 이상), 옷색, 모자·앞치마·가방 같은 **실루엣 소품**으로 구분한다.
- 얼굴은 눈 점 1px 두 개까지만 허용, 입은 생략한다.
- 감정(화남, 만족, 대기)은 머리 위 **아이콘 8×8**(별도 UI 스프라이트)로 보인다.

### 5.3 만드는 방식 ✅ 상자 캐릭터
머리·몸통·팔×2·다리×2 상자에 면별 질감을 씌운다. 어느 방향이든 돌려서 맞고, 걷기는 코드가 4단계로 끊어 팔다리를 흔든다(보간 없음). 3D 정렬·윤곽선·빛(6장)에 그대로 맞는다. 그려야 하는 것은 부품당 앞·옆·윗면(약 8장)과 법선 맵(선택).

### 5.4 부품 질감 크기(A안, 1질감 픽셀 = 화면 1픽셀) 🟡
| 부품 | 앞 | 옆 | 윗면 |
|---|---|---|---|
| 머리 | 9×8 | 9×8 | 9×8 (가르마·머리결: 위에서 내려다보므로 윗면이 크게 보임) |
| 몸통 | 7×7 | 4×7 | 7×4 |
| 팔 | 2×9 | 2×9 | 2×2 |
| 다리 | 3×10 | 3×10 | 3×3 |

- 앞머리가 이마를 덮고 얼굴은 앞면 아래쪽에 둔다(윗면이 크게 보이는 시점이기 때문).
- 뒷면은 윗면의 머리카락 색으로 대체한다.

## 6. 빛과 법선 맵 ✅ (시험 전)

### 6.1 목적
빛의 방향·색·세기만 바꿔서 **낮과 밤이 달라 보이게** 하되, 그림은 한 벌만 만든다. 법선 맵이 있으면 방향이 있는 빛(해)이 움직일 때 벽돌 줄눈·나무결·천 주름의 **음영이 같이 바뀌어** 시간대가 더 잘 느껴진다.

### 6.2 법선 맵 규격
- 각 질감 `X.png` 마다 선택적으로 짝 `X_n.png`. **같은 크기**, 최근접 필터, 압축 없음.
- Godot(OpenGL) 방식: 평평한 곳 = (128,128,255), 빨강 = 오른쪽, 초록 = **위쪽**.
- 🟡 요철은 **약하게, 단계는 적게**(기울기를 8방향·1~2단계 정도). 도트 한 칸 단위의 홈과 볼록만 표현하고 부드러운 곡면 그라데이션은 쓰지 않는다. 안 그러면 도트 느낌이 흐려진다.
- 평평한 면은 법선 맵을 생략한다(코드가 기본값 사용).

### 6.3 빛의 구성 🟡
| 시간대 | 해(방향광) | 환경광 | 기타 |
|---|---|---|---|
| 낮 | 흰색~연노랑, 높은 각도, 세기 큼 | 밝음 | — |
| 아침·저녁 | 주황, 낮은 각도(긴 그림자) | 중간 | — |
| 밤 | 파란색, 약함 | 어두움(남색) | 매장 조명·가로등·간판 점광원이 주변만 밝힘 |

- 빛 계산은 **계단식(툰 램프) 3~4단계**로 둔다. 연속 그라데이션은 도트처럼 안 보인다. (시험 방 1에서 계단식 빛은 이미 동작 확인)
- 낮·밤 전환은 하루 시간(게임 24시간)에 맞춰 코드가 값을 이어서 바꾼다. 기존 `day_night_tint.gd`와의 관계는 ❓(대체 or 병행).
- ❓ 밤에 켜지는 창문·간판 같은 **스스로 빛나는 부분**: 발광 마스크 `X_e.png`(흰색 = 발광) 를 따로 둘지.

### 6.4 법선 맵을 만드는 방법 ❓
1. Pixel Lab 등이 법선 맵을 직접 내는지 → **정보를 못 찾음(미확인)**. 확인이 안 되므로 2번을 기본 경로로 잡는다.
2. **높이 맵(회색조 도트, 밝을수록 높음)** 을 같은 크기로 그리고 `tools/height_to_normal.py` 로 법선 맵으로 변환한다(7장 가져오기 설정 절차 포함).
3. 둘 다 안 되면 법선 맵 없이 방향·색만으로 낮/밤을 구분한다(차이가 약해지는 것은 시험으로 확인).

### 6.5 시험 결과 (2026-10-02, `dev/spike3d/store_spike.tscn` N·[ ]·Y 키, `screenshots/time_normal_compare.png`)
- **시간대 구분: 확인됨.** 9시(맑은 아침, 긴 그림자) / 12시(흰 빛) / 17:30(주황빛, 낮은 해) / 21시(남색 달빛 + 매장 등이 만드는 따뜻한 빛 웅덩이)가 한눈에 구분된다. 그림은 한 벌이고 해/달 방향·색·세기, 환경광, 천장 등만 바꾼다.
- **법선 맵: 효과 있지만 은은함.** 벽돌·판자에 윗면은 밝고 아랫면은 어두운 가장자리가 생겨 입체감이 늘지만(`normal_detail_noon.png`), 시간대 구분은 법선 맵 없이도 빛 색·방향만으로 충분히 된다. 법선 맵은 "질감 디테일 보강"이라고 보는 게 맞다.
- 법선 맵은 기울기를 2단계로 끊은 쪽(도트 느낌 유지)으로 시험했다. 단계를 늘리거나 강도를 높이는 것은 아직 시험 전.
- 윤곽선·정렬 깊이와 같이 켜도 문제 없음(이 환경 기준). **GPU·실제 PC 확인 전.**
- 도구: `tools/height_to_normal.py`(높이 맵 → 법선 맵, Pillow 만 필요). 시험 장면은 같은 알고리즘을 GDScript 로 구현해 코드로 만든 임시 높이 맵(벽돌·판자 줄눈)에 적용했다. Python 도구로 만든 PNG 를 Godot 에서 불러 쓰는 경로는 아래에서 확인했다.
- **PNG 흐름 확인(2026-10-02, `png_texture_check.tscn`)**: 높이 맵 PNG → `tools/height_to_normal.py` → 법선 맵 PNG → Godot 가 불러 렌더링. 가져온 알베도·법선 PNG 4장이 원본과 **픽셀 단위로 동일**(다른 픽셀 0, 최대 차이 0)했고, 같은 장면(12시, 법선 켬)을 코드 질감과 PNG 질감으로 그렸을 때 746,496 픽셀 중 3,579(약 0.5%)만 아주 조금 달랐다(큰 차이 0, 8비트 반올림 수준). 이미지: `screenshots/png_vs_code.png`(왼쪽 코드, 가운데 PNG, 오른쪽 차이 12배 증폭).
- **주의(가져오기 설정)**: Godot 기본값(`detect_3d/compress_to=1`)은 3D 에 쓰는 질감을 **손실 압축(VRAM)으로 다시 가져와 도트가 번진다.** 질감 PNG 의 `.import` 는 `compress/mode=0`(무손실) + `detect_3d/compress_to=0` 이어야 한다. 시험 질감에는 이 값을 고쳐서 커밋했다. 새 그림을 넣을 때마다 같은 설정이 필요하므로 **폴더 단위 기본 설정(또는 `validate_assets.py` 검사)** 으로 자동화하는 방법은 ❓.
- 질감 크기를 18 로 바꾸면서 줄눈 패턴을 3줄(18=6×3)·벽돌 폭 9 로 바꿨다(이음매 없이 반복).

## 7. 파일 규칙 🟡

- 폴더: `art/world3d/` 🟡 (기존 `art/world/` 와 섞지 않는다). **마을 건물·소품은 자산마다 폴더 `art/world3d/<자산id>/<면이름>.png`**(법선 `<면이름>_n.png`) — 코드가 이 위치를 자동으로 읽어 임시 질감을 대체한다(`VillageAssets.apply_overrides`). 넣는 도구: `tools/ingest_world3d.py`. 게임에서 F8 로 다시 읽기. 높이 맵 원본은 `art/world3d/_src/` 에 두고 **그 폴더에 빈 `.gdignore` 파일을 넣는다**(Godot 가 가져오지 않음).
- 이름: 소문자·숫자·밑줄. **알베도 `X.png`, 법선 맵 `X_n.png`, 발광 `X_e.png`, 높이 맵 원본 `X_h.png`**. 면 구분은 이름에 넣는다(`shelf_a_front.png`, `shelf_a_front_n.png`).
- 버전 폴더(`_v1`)는 만들지 않는다(git 으로 관리).
- **가져오기 설정(중요)**: 질감 PNG 의 `.import` 는 `compress/mode=0`, `detect_3d/compress_to=0`, `mipmaps/generate=false` 여야 한다. Godot 가 새 PNG 를 처음 가져오면 기본값(`compress_to=1`)이 들어가서 도트가 번지므로, **새 그림을 넣을 때마다**:
  1. Godot 에서 프로젝트를 한 번 열어 `.import` 가 생기게 한다.
  2. `python tools/fix_texture_import.py` 로 설정을 맞춘다(`--check` 는 검사만).
  3. Godot 에서 다시 가져온다(프로젝트 다시 열기).
- **검증**: `python tools/validate_assets.py .` 가 `art/world3d/` 를 검사한다.
  - FAIL: 반투명 픽셀, 알베도 색 16개 초과(규격 8~12), 법선·발광 크기가 알베도와 다름, 가져오기 설정이 위 값이 아님, 원본 폴더에 `.gdignore` 없음, 이름 규칙 위반.
  - WARN: `.import` 아직 없음, 짝(알베도)이 없는 법선·발광, `_src/` 밖의 높이 맵.
- ❓ 프로젝트 전체 기본값(`project.godot` 의 `[importer_defaults]` 에 `texture` 의 `detect_3d/compress_to=0`, `compress/mode=0`)을 바꾸면 위 2단계가 필요 없어지지만, 모든 텍스처에 영향을 주고 공용 파일을 건드리므로 사용자 확인 후에 결정한다.
