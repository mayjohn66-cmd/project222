# 이미지 제작 목록과 Pixel Lab 프롬프트 (초안 v0.1)

작성일: 2026-09-30 · 관련 문서: `docs/그림_3D/에셋_규격서.md`(규격), `AI_협업_규칙.md`

이 문서는 **아직 이미지가 없는 항목**과 Pixel Lab에 넣을 프롬프트 초안입니다. 이미지는 사용자가 만들거나, 사용자가 승인한 자동 생성(`tools/art/pixellab_batch.py`, Claude가 실행)으로 만듭니다. ChatGPT는 만들지 않습니다.
태그: 🟡 제안 / ❓ 미정. 목록은 `data/core/items.csv`의 `icon_path`와 실제 파일을 비교해 만들었습니다(2026-09-30 기준).

## 0. 작업 순서 제안 🟡

1. **기준 그림 정하기**: 기존 `art/items/pixel_v1/`의 진짜 픽셀 아이콘(예: `forest_herb.png`, `bread.png`)을 스타일 기준으로 삼습니다. 처음 1~2장을 만들어 기준과 비교하고 스타일을 굳힌 뒤 나머지를 만듭니다.
2. **우선순위**: (1) 첫 원정 흐름에 필요한 것 → (2) 숲 재료·상품 → (3) 광산·늪 → (4) 유적 → (5) 손님·NPC·타일.
3. 만든 파일을 `upscale_icon.py`로 64×64로 바꾼 뒤 위 표의 경로에 **그 이름 그대로** 넣고 `python tools/art/validate_assets.py .`로 FAIL이 없는지 확인합니다.
4. 크레딧이 소모되므로 한 번에 다 만들지 말고 5~6개씩 확인하면서 진행합니다.

## 1. 공통 스타일과 제작 방식 🟡

**목표 스타일(사용자가 고른 참고): 스타듀밸리풍.** 짙은 외곽선, 따뜻하고 채도 있는 색, 왼쪽 위 하이라이트 1~2점, 칸을 채우는 단순한 실루엣.

**제작 방식: 작은 격자로 만들어 정수 배로 확대**
1. Pixel Lab에서 **32×32**(더 굵은 도트를 원하면 16×16)로 만듭니다. 64×64로 직접 그리면 도트가 너무 잘아서 화면에서 얇고 깨져 보였습니다(2026-09-30 확인).
2. 저장 전에 `python tools/art/upscale_icon.py 파일.png`로 **64×64로 정확히 2배(16px이면 4배) 최근접 확대**합니다. 반투명은 자동으로 정리됩니다.
3. 결과는 `art/items/pixel_v1/`에 들어가며 파일 규격(64×64, 색 32 이하, 반투명 없음)은 그대로입니다.

공통 프롬프트(영어, 32×32 기준, 2026-10-07 2차 시험 방식으로 변경):

```
32x32 pixel art item icon, single object filling almost the entire canvas (tight crop), centered,
farming-sim game style like Stardew Valley, thick dark outline, chunky compact shape, 3-4 tone shading,
white highlight pixels top-left, no drop shadow, no anti-aliasing
```

Pixel Lab MCP(`create_image_pixflux`) 설정: `width=32, height=32, no_background=true, outline="single color black outline", view="low top-down"`(동전처럼 정면이 나은 물건은 `view="side"`).

**2026-10-07 시험 결과(9장, `docs/그림_작업/받은그림/아이템/_시험5_비교.png`):**
- 1차(갈색 외곽선 + 짧은 대상)는 석탄이 갈색 돌, 보석이 둥근 덩어리, 동전이 나무 단면, 룬 가루가 돌처럼 나와 **물건이 읽히지 않았다.**
- 2차(검은 외곽선 + 색·형태·재질을 적은 대상)는 기존 아이콘(`forest_herb`, `iron_ore` 등)과 외곽선·도트 굵기가 맞고 한눈에 읽혔다.
- 그래서 **"프롬프트용 대상"은 색·형태·특징을 한 문장으로 구체적으로 적는다**(예: `lump of coal` → `lump of black coal, jet black and charcoal grey angular chunk ...`). 가루·액체처럼 모양이 없는 재료는 담는 그릇(주머니, 병)과 함께 그린다.
- **가구 아이콘도 32×32 격자**로 만든다(64×64 직접 생성과 비교해 아이템과 도트 굵기가 맞음, 2026-10-07). 가구 공통 앞부분: `32x32 pixel art furniture icon for a cozy fantasy shop build menu, single object filling almost the entire canvas (tight crop), centered, 3/4 view from slightly above, Stardew Valley style, thick dark outline, warm colors, 3-4 tone shading, no drop shadow, no anti-aliasing.` 바닥 그림자가 회색으로 남으면 그 색만 지운다. 색 상한은 48.
- 기존 그림이 이미 보기 좋고 색 수만 넘는 경우(`wild_berry`, `treasure_map`)는 새로 만들지 않고 원본을 32색으로 줄였다.
- 생성 뒤 반투명은 알파 128 기준으로 정리하고, 32×32에서 색이 32개를 넘으면 32색으로 줄인 뒤 2배 확대한다.

- 개별 항목은 `Subject: <대상>` 형식으로 뒤에 붙입니다. 표의 "프롬프트용 대상" 열을 그대로 쓰면 됩니다.
- 색 수는 32×32 격자에서는 16~24색이 적당합니다(64×64 기준의 32색 상한은 그대로 유지).
- 물체가 작게 나오면(2026-09-30 열매 시험작) `filling almost the entire canvas, tight crop`이 빠졌는지 확인합니다.
- 실패 사례: 반투명 가장자리, 배경 그림자, 색이 너무 많음, 물체가 너무 작거나 흩어져 있음 → 프롬프트에 `chunky compact shape, touching each other`를 유지하세요.

### 문 (월드 그림 3종, 2026-10-01 코드 기울임 방식으로 변경)

월드는 **2:1 마름모(아이소메트릭) 타일**(96×48)이라, 문은 타일 한 변에 서는 평행사변형 모양이어야 합니다. **그림은 "정면"으로만 만들고, 기울기·크기·위치는 코드(`door_visual.gd`)가 계산합니다.** `tools/art/iso_shear.py`로 미리 기울일 필요가 없습니다.
- 그림 규격: **정면에서 본 문(문틀 포함), 투명 배경, 문틀이 캔버스 가장자리까지 닿게 꽉 채움**. 크기는 자유(비율만 세로가 가로의 약 2배: 가로 52 : 세로 110 정도)이고, 코드가 `door_width`(52) × `door_height`(110)로 맞춥니다. 참고 그림 느낌(가로등 같은 오브젝트형 도트)으로 문틀은 돌/쇠 장식.
- 코드가 하는 일: 짝수 회전은 `\`, 홀수 회전은 `/`로 기울이고(그림 내용은 뒤집지 않음), 크기는 인스펙터의 `door_width`, `door_height`, 위치는 `art_offset`으로 조절합니다.
- 옛 방식(이미 기울인 그림)은 문 씬에서 `art_is_frontal`을 끄면 `art_scale`로 크기만 조절하는 방식으로 쓸 수 있습니다.

## 자동 생성 도구 (2026-10-07)
`python tools/art/pixellab_batch.py` 가 위 2장 "아이템 아이콘" 표를 읽어 아직 그림이 없는 항목을 Pixel Lab(REST v2 `create-image-pixflux`, 32x32, 투명 배경)으로 만든다.
- 결과: `docs/그림_작업/받은그림/아이템/<id>/<id>_32.png`·`_64.png` + 확인용 시트 `_시트/*.png`. 사용자가 시트를 보고 고른 id 만 `--ingest id,id` 로 `art/items/pixel_v1/` 에 넣고 `validate_assets.py` 를 돌린다.
- 기본은 모의 실행. `--run` 으로 실제 요청. 한 번에 `--limit`(기본 6)개, `--budget-usd`(기본 1.0) 넘으면 멈춤. 토큰은 환경 변수 `PIXELLAB_TOKEN`.
- 모의 서버로 저장·시트·반영 흐름만 점검했다. **실제 Pixel Lab 요청은 토큰이 있는 환경에서 처음 돌려 봐야 한다**(요청 인자는 OpenAPI 명세 기준).
