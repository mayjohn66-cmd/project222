# 캐릭터별 애니메이션 준비 (2026-10-07 초안)

목표: Pixel Lab 으로 캐릭터를 도트 스프라이트로 만들고 방향별 애니메이션을 붙여 게임에 넣는다. 아직 만들기 전 **준비 단계**다. 🟡 제안 / ❓ 사용자 결정 필요.

## 1. 지금 게임이 캐릭터를 그리는 방식 (확인한 것)
- 가게·마을 화면의 사람은 **3D 블록 인형**(`BlockyFigure`)이다. 외형은 `data/shop/catalogs/actor_looks_3d.csv`(키 34개: player·worker·story_npc·merchant_npc와 손님 소분류 30개)의 색·모자·등짐·손 소품 값으로 정한다. 걷기·숨쉬기·공격·피격·앉기(새로 추가) 동작이 코드로 만들어진다.
- 옛 2D 스프라이트 시트가 `art/characters/cozy_v1/`(player, normal, traveler, worker_001~003)에 있다. 시트 256×320, `frames.tres`. 지금은 3D 인형이 대신하고 있다.
- 이름 있는 NPC 10명의 외형 초안은 `docs/drafts/story/character_profiles.md`. 적은 `data/expedition/enemies.csv`에 24종.
- `에셋_규격서.md` ✅: "월드와 원정의 그림은 픽셀 스프라이트 스타일로 통일", 광원은 좌상단, 그림자는 코드에서 그린다.

## 2. Pixel Lab 캐릭터 기능 (문서 `https://api.pixellab.ai/mcp/docs` 기준)
- `create_character`(또는 `create_character_pro_flash`): 설명으로 캐릭터 생성, 4방향(south·west·east·north) 또는 8방향. 캔버스 안에서 캐릭터는 높이의 약 60%.
- `animate_character`: 템플릿 애니메이션은 방향당 1회 생성. 사람형 템플릿에 `breathing-idle`, `walk`/`walking-*`, `running-*`, `picking-up`, `drinking`, `crouching`, `getting-up`, `sad-walk`, `fight-stance-idle-8-frames`, `taking-punch`, `falling-back-death` 등이 있다. 템플릿에 없는 동작은 `action_description` 으로 custom(v3) 생성하며, 비용이 캔버스 크기·프레임 수에 따라 커진다(64px 8프레임 방향당 1, 96·128px 2).
- 작업은 비동기(2~5분). `get_character` 로 상태, `wait_for_jobs` 로 기다림, 내려받기 주소는 인증 없음.
- 사족·무정형(슬라임·박쥐) 템플릿은 별도(곰·고양이·개·말·사자뿐). 슬라임 같은 적은 custom 이 필요할 수 있다.

## 3. 결정할 것 ❓ (먼저 정해야 구현 방향이 선다)
1. **게임에서 무엇으로 그릴까?** (가) 3D 인형을 스프라이트 빌보드로 교체(캐릭터가 항상 카메라를 보는 2D 판), (나) 3D 인형 유지하고 얼굴·옷 질감만 도트로, (다) 스프라이트는 원정·대화 초상화에만. 지금 가게 화면의 사람·깊이 정렬이 3D 기준이라 (가)는 정렬·방향 처리 작업이 크다.
2. **방향 수**: 등각 화면은 대각 4방향이 자연스럽지만 Pixel Lab 은 상하좌우 4방향 또는 8방향을 만든다. 8방향이면 대각을 쓸 수 있으나 비용이 2배.
3. **크기**: 한 칸 높이 대비 캐릭터 높이와 캔버스(32/48/64px). 지금 인형의 키는 `ACTOR_TOTAL` 1.14칸.
4. **애니메이션 세트**: 기본 idle·walk, 가게 일(집기, 계산, 앉기), 프롤로그(앉기·졸기·놀람·뛰기·뒷걸음질·주저앉기), 전투(피격·쓰러짐). 어디까지?
5. **손님 처리**: 손님 소분류 30개를 각각 새로 만들지, 몸 하나에 옷 색만 바꾸는 방식으로 줄일지(비용·일관성).
6. **예산**: 캐릭터 1명 × 4방향 × 애니 3종 = 호출 12회 안팎. 호출당 비용은 확인 못 함(계정 잔액과 응답 usage 로 측정 필요).

## 4. 제안 순서 🟡
1. 결정 1~3 확정(위).
2. **시험 3명**: 점장(player), 타블렌(naru), 슬라임(field_slime)을 만들어 "기존 아이콘·3D 인형과 어울리는지"만 본다.
3. 규격이 서면 자동화: `tools/pixellab_characters.py`(새로 만들 예정) — `docs/그림_작업/characters.csv` 를 읽어 create → animate → 대기 → 내려받기 → 시트 묶기 → `frames.tres` 만들기. 아이콘 도구(`pixellab_batch.py`)와 같은 안전장치(한도·예산·덮어쓰기 금지).
4. 게임 쪽 연결(결정 1에 따라): 스프라이트 시트 로더, 방향 선택, 애니메이션 상태(idle/walk/동작) 연결.

## 5. 이미 준비한 것
- `docs/그림_작업/characters.csv`: 캐릭터 19행(주인공·직원·이름 있는 NPC 10·손님 5·적 3)의 id·우선순위·방향·애니메이션·영어 설명 초안. 우선순위 1은 점장·직원·타블렌·델빈·슬라임.
- NPC 영어 설명은 `character_profiles.md` 의 외형·의상·소품 줄을 옮긴 것이다. 새 설정은 만들지 않았다.
- 아직 안 한 것: 결정 사항 확정, 실제 생성, 게임 연결.

## 6. 목표 화풍 참고 (2026-10-07, 사용자 제시)
- 사용자가 고른 느낌: 등각 시점의 2D 도트 방 장면 + **치비(머리가 큰 2~3등신) 캐릭터**, 표정이 풍부한 얼굴, 손으로 그린 듯 디테일한 가구·바닥(나무 판자, 카펫). 기본 목표는 스타듀밸리(탑다운 3/4)이고, 이 참고 이미지는 **등각 시점**이다.
- 지금 게임 카메라가 등각이라, 이 방향이면 **화면 방식(등각)을 바꾸지 않아도 된다**(탑다운으로 가면 좌표 계산 전체를 손봐야 했다). 3D 그림 층을 2D 도트 그림으로 바꾸는 쪽이 된다.
- Pixel Lab 으로 가능한 것(문서 기준): 캐릭터 `proportions` 에 `chibi` 프리셋이 있다. 등각 소품은 `create_isometric_tile`(타일·블록·오브젝트, 32px 기본), 8방향 오브젝트(`create_8_direction_object`), 맵 오브젝트(`create_map_object`). 참고 이미지 수준의 디테일을 AI 로 얻을 수 있는지는 시험 전에는 모른다.
- 시험 재료 주문(PC): 점장 `proportions chibi`·8방향·`size 64`, 바닥(등각 타일 32px 나무 판자), 진열대·계산대(등각 오브젝트).
