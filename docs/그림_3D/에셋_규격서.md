# 에셋 규격서 (초안 v0.1)

작성일: 2026-09-29 · 함께 쓰는 파일: `validate_assets.py`(검증기), `asset_baseline_report.md`(현재 상태 측정 결과), `docs/원정_규칙서.md`

> 월드·매장 그림(3D 도트 방식)은 `docs/그림_3D/그림_규격서_3D도트.md`가 우선한다 🟡. 이 문서는 아이콘·UI·원정 2D 그림 기준이다.

## 0. 사용법

- 태그: ✅ 사용자가 결정 / 🟡 초안 제안(바꿀 수 있음) / ❓ 미정
- 이미지를 만드는 쪽(다른 AI, 픽셀 생성 도구 등)은 **4장의 규격표**를 그대로 따라 주세요. 만든 뒤 `validate_assets.py`로 통과 여부를 확인합니다.
- 규격을 바꾸면 이 문서와 `validate_assets.py` 맨 위의 `RULES`를 **같이** 고칩니다.

## 1. 방향

- ✅ 월드와 원정의 그림을 **픽셀 스프라이트 스타일로 통일**합니다.
- 🟡 새로 만드는 것부터 규격을 적용하고, 기존 그림은 4장의 기준으로 "유지 / 교체 / 삭제"를 나눕니다.

**정리 후보** (코드·CSV에서 파일 이름이 직접 나오지 않는 것):
- `art/items/expedition/` 13개, `art/items/bread.png` · `potion.png` · `water.png`: `items.csv`는 `pixel_v1`만 가리키므로 옛 버전일 가능성이 큽니다.
- 주의: 코드에서 경로를 조립해 부르는 파일(예: 방향 이름으로 캐릭터 이미지를 고르는 경우)은 이 집계에서 빠집니다. **삭제 전에 게임에서 확인**해 주세요.

**픽셀 통일 관련 화면 설정** (코드에서 확인한 것)
- 일부 UI는 이미 `TEXTURE_FILTER_NEAREST`(최근접 필터)를 쓰고 있습니다. 프로젝트 전체 기본값으로 올리는 것을 권장합니다.
- 가방 셀은 46px, 인벤토리 셀은 52px인데 아이콘은 64px입니다. 배율이 정수가 아니라서(0.72배, 0.81배) 최근접 필터를 써도 **픽셀 크기가 들쭉날쭉**해집니다. 셀 크기를 64px(또는 32의 배수)로 맞추는 것을 권장합니다 ❓.

## 3. 스타일 규칙 🟡

1. **해상도 그대로**: 확대·축소·회전한 이미지를 쓰지 않습니다. 정해진 픽셀 격자에서 그린 그대로 저장합니다. 단, **아이템 아이콘은 32×32(또는 16×16) 격자로 그려 정수 배(2배/4배)로 최근접 확대한 64×64를 허용**합니다(`tools/upscale_icon.py`). 64×64 격자로 직접 그리면 도트가 잘아 화면에서 얇게 보입니다 🟡.
2. **투명 배경**, 알파는 0 또는 255만 씁니다(반투명 금지). 예외: 이펙트류(연기, 빛)는 별도 협의 ❓.
3. **외곽선**: 1px, 순검정이 아니라 팔레트에서 가장 어두운 색을 씁니다.
4. **광원**은 좌상단. 그림자는 스프라이트에 넣지 않고 코드에서 그립니다(캐릭터 발밑 타원 등).
5. **공용 팔레트** ❓: 프로젝트 전체가 하나의 팔레트(예: 48색 이내)를 쓰면 종류가 달라도 같은 그림체로 보입니다. 팔레트가 정해지면 생성물을 이 팔레트로 변환하는 단계를 추가합니다. (검증기에 팔레트 일치 검사를 넣는 것도 가능)
6. **기준점(앵커)**: 캐릭터와 몬스터는 발 중앙 하단, 오브젝트는 바닥 접점 중앙.

## 4. 규격표 🟡

| 종류 | 폴더 | 크기 | 색 상한 | 비고 |
|---|---|---|---|---|
| 아이템 아이콘 | `art/items/` | **64×64** | 32 | 파일명 = 아이템 ID (`forest_herb.png`). 가방에서 2×1칸을 차지하는 아이템(고대 유물)도 아이콘은 64×64로 그리고, 칸에 맞춰 늘려 보이는 방식은 코드에서 정함 |
| 가구·오브젝트 | `art/furniture/` | 64의 배수 (기본 64×64) | 48 | 큰 가구는 128×64 등 |
| 플레이어·몬스터 | `art/player/`, `art/monsters/` | **프레임 64×64**, 시트는 64의 배수 | 48 | 방향과 동작은 5장 |
| 타일 | `art/tiles/` | **32×32** 타일, 시트는 32의 배수 | 32 | 방(소형 맵) 크기: 8×8타일 = 256×256 |
| 이펙트 | `art/effects/` | 프레임 64×64 | 별도 | 피격, 채집 반짝임 등 |
| UI | `art/ui/` | 8의 배수 | 제한 없음 | 아이콘은 16/32 권장 |

- 🟡 타일을 32로 잡는 이유: 캐릭터(64)가 타일 2×2를 차지해 방 안에서 움직이기에 적당하고, 방 하나가 화면 한 장에 들어옵니다.
- 🟡 **파일명**은 소문자·숫자·밑줄만 씁니다(`^[a-z0-9_]+\.png$`).
- 🟡 **버전 폴더**(`_v1`, `cozy_v10` 등)는 새로 만들지 않습니다. 버전 관리는 git 이력으로 합니다. 기존 `pixel_v1`은 경로를 바꾸면 CSV와 코드 전체를 수정해야 하므로, **git 도입 후 한 번에 정리**합니다.

## 5. 캐릭터·몬스터 구성 🟡

| 항목 | 플레이어 | 몬스터 |
|---|---|---|
| 방향 | ❓ 4방향(제안) 또는 8방향 | 4방향, 좌우 반전으로 절약 가능 |
| idle | 4프레임 | 4프레임 |
| 이동 | 6프레임 | 4~6프레임 |
| 공격 | 4프레임 | 4프레임 (예고 동작 포함, 규칙서 3.3) |
| 회피(폐기: 스킬·회피 없음) | - | - |
| 피격 | 2프레임 | 2프레임 |
| 사망 | 없음(패배는 연출로 처리) | 4프레임 |

시트는 가로가 프레임 순서, 세로가 방향 순서로 배치합니다(`down, left, right, up`).

## 7. 검증기 사용법

```
python validate_assets.py <프로젝트 루트> \
  --extra-items items_materials_draft.csv \
  --report asset_report.md
```

- 하는 일: 크기, 색 수, 반투명, 파일명, 아이콘 누락, 버전 폴더를 검사합니다.
- **FAIL**이 하나라도 있으면 종료 코드 1을 돌려줍니다(작업 흐름에 넣기 쉽게).
- 옛 대형 그림은 **LEGACY**로만 세고 검사하지 않습니다.
- 기준선 결과: PASS 58 / WARN 26(UI 크기) / FAIL 41 / LEGACY 68, 누락 아이콘 19개.
- FAIL 41개의 내역:
  - **실제로 쓰이는 것**: 가구 12개, `art/items/pixel_v1/treasure_map.png` 1개
  - **옛 버전 후보**: `art/items/expedition/` 13개, `art/items/` 직속 3개 (합계 16개)
  - **확인 필요**: `art/player/generated/` 12개 (경로를 코드에서 조립해 쓸 수 있음)
  - 옛 버전 후보를 정리하면 FAIL 수가 크게 줄어듭니다.

## 8. PixelLab 등 생성 도구 도입 시 시험 계획 (제안)

작게 시험하고 규격 통과 여부로 판단합니다.
1. 아이콘 5개 (예: `coal`, `wild_berry`, `rune_dust`, `deep_gem`, `worn_coin`) — 64×64, 규격 통과 여부와 기존 아이콘과의 어울림을 확인
2. 플레이어 1종 4방향 + idle/이동
3. 몬스터 1종
4. 평가 기준: ① `validate_assets.py` 통과 ② 공용 팔레트 일치 ③ 기존 픽셀 아이콘 옆에 놓았을 때의 어울림 ④ 생성 비용과 상업적 이용 조건
