# 주민과 남기는 작은 기억

사용자 요청(2026-10-04): 콘텐츠를 계속 이어간다. 계절 생활 재료 부탁 이후, 물품을 다시 모으지 않고 이웃과 마음을 나누는 선택형 인연 이벤트 3개를 추가했다.

## 세 주민의 이야기

| 주민 / 사건 | 두 답변 | 계절 선행 중 하나 | 최초 답례 |
|---|---|---|---|
| 타블렌 / 돌아오면 들리는 인사 | 먼저 건네는 인사 / 머무르고 싶은 자리 | 봄 간식 또는 겨울 식사 재료 부탁 완료 | 야생 열매 2·평판 1 |
| 코르빈 / 일 사이에 남은 여유 | 잠깐 멈추는 순간 / 발견을 나눌 사람 | 여름 차 또는 가을 저녁 채비 재료 부탁 완료 | 돌 조각 2·평판 1 |
| 이세르 / 적지 않아도 남는 하루 | 별일 없던 하루 / 그날 곁에 있던 사람 | 생활 재료 부탁 4개 중 아무 하나 완료 | 숲 약초 2·평판 1 |

세 이벤트 모두 안내와 첫 주민 정착·해당 주민 정착을 마치고, 제안자와 안부를 나눈 날 7일이 필요하다. 관련 계절 부탁 중 최초 완료한 날의 다음 날부터 시작한다. 이세르는 본인의 행사 후 갈대 차 부탁(`sora_autumn_tea`) 전달과 후일담 완독 다음 날 조건도 필요하다. **사계절 부탁을 전부 완료하거나 1년을 기다릴 필요는 없다.** 해당 계절/시각 제한 없이 시작하며, 이미 맡은 후에는 진행 간격·안부 조건으로 다시 막지 않는다.

조건·간격·재료 답례·평판은 `default_resident_memories.tres`의 조정 가능한 초기값이다. 선택에 따른 수치 우열·친밀도 추가 증가·별도 고객 해금은 없다. 하루 첫 인사의 기존 선물은 별개의 기존 동작으로 유지한다.

## 플레이 흐름

1. 실제 주민에게 E로 이야기한다. 소개를 완독하면 이야기를 맡고, 중간에 닫으면 맡지 않는다.
2. 다시 E로 선택 질문을 끝까지 들으면 두 답변이 나오는 창을 연다. Esc/E/닫기로 미루면 선택을 기록하지 않고 원래 시간·이동 상태로 복원한다.
3. 답변 버튼을 누르면 선택을 저장하고 해당 주민의 응답을 보여 준다. 선택만으로 답례를 받지는 않는다. 선택은 이후 변경하지 않는다.
4. 응답의 마지막 문장까지 읽었을 때 창고의 작은 선물과 평판을 한 번 지급한다. 응답을 중간에 닫아도 선택은 남으며, 다시 E로 같은 응답을 이어서 볼 수 있다.
5. 수첩에 선택한 답변 제목·완료 날짜·각기 다른 기억이 남는다. 다른 진행 대화가 없을 때 주민에게 E로 같은 기억을 다시 들을 수 있다. 재읽기와 다음 해에는 답례를 반복하지 않는다.

대화·선택 창이 열린 동안 기존 월드 상호작용을 막고 시계·이동을 멈춘다. 건축·다른 메뉴·마을 편집 중에는 시작하지 않는다. 저장 복원과 장기간 미방문에도 맡은 이야기와 선택·완료를 유지한다. 미방문 불이익과 준비 기한이 없다.

주민 개인 부탁 후일담과 기존 진행 중인 안부/마을 이야기, 이미 맡은 계절 이야기 안내는 먼저 처리한다. 새 인연 이벤트는 아직 맡지 않은 계절 제안과 기존 완료 기억 재읽기보다 먼저 소개한다. 인연 이벤트가 완료되면 새 계절 제안과 진행 안내가 재읽기보다 우선이다.

## 글과 구현

- 소개 3개 + 선택 질문 3개 + 선택별 응답 6개 = **service_text 12장면**이다. 사건은 3개이며 답변 분기만 6개다. 전체 대사 CSV는 209행이다.
- 기존 계절 사건 8개·개인 부탁 17개·개인 부탁 후일담 11개·매장 판매 행사 11개는 유지한다. 이 묶음은 게시판의 재료 전달 부탁으로 등록하지 않는다.
- `resident_memory_settings.gd` / `default_resident_memories.tres`: 선행·답례·두 선택과 실제 장면 맥락.
- `resident_memory_flow.gd`: 소개·선택·응답 완독·일회성 답례·기억 조회. 저장은 기존 `PlayerProgress.story_beat_days`의 `resident_memory:<id>:accepted/choice:<장면 id>/done`과 기존 평판 집계 키를 사용한다.
- `resident_memory_panel.gd`: 기존 게시판 창 틀을 재사용하고 현재 주민의 두 선택만 표시한다.
- `village_life_director.gd` / `village_journal_flow.gd`: 주민 E·선택 창 전환·시간/이동 복원·수첩 연결.
- `requests_text.csv` / `content_voices.csv`: 러프 글과 해당 장면의 정식 인물 말투. 정식 이름/말투 기준 파일은 수정하지 않았다.
- Gemini 글 도구: 기존 `service_text` 종류에서 moments만 읽고 기계 events 행은 제외한다.

이야기는 익숙해진 인사·머무르고 싶은 마음·성과 없이 쉬는 여유·작은 발견을 나누는 기쁨·평범한 하루를 다룬다. 새 시설/아이템/원정 지점/주민 등장, 음식 회복, 시간 건너뛰기, 영구 거주 계약이나 새 모임을 약속하지 않는다. 실제 소재 아이템의 작은 답례와 수첩 기억만 발생한다. 큰 시스템 파일·메인 씬·달력·이미지는 변경하지 않았다.

## Gemini 대사 보강

API는 호출하지 않았다. 아래 장면만 생성한 뒤 검토하여 게임 CSV에 별도로 반영한다. 두 답변은 서로 다른 마음이며 정답/오답처럼 쓰지 않는다. `title`은 실제 선택 버튼 위의 제목, `summary`는 플레이어가 전할 마음 설명, `lines`는 선택 후 NPC 응답, `completion`은 수첩과 재읽기의 실제 선택별 기억이다.

```bat
dev\gemini\run_request_text.bat draft service_text --ids naru_familiar_place_intro,naru_familiar_place_choose,naru_memory_greeting,naru_memory_staying
dev\gemini\run_request_text.bat draft service_text --ids doyun_small_discovery_intro,doyun_small_discovery_choose,doyun_memory_pause,doyun_memory_sharing
dev\gemini\run_request_text.bat draft service_text --ids sora_unwritten_day_intro,sora_unwritten_day_choose,sora_memory_ordinary,sora_memory_company
```

소개·질문·응답을 각 단계에 맞게 다듬고, 선택 제목과 완료 기억의 의미를 서로 맞춘다.
