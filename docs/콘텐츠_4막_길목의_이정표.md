# 4막: 길 위의 가게와 길목의 이정표

2026-10-05 · 인수인계 22의 구조 구현 · main

사용자가 인수인계 22의 구축을 요청했다. 사건 11개와 관리 책의 이정표 화면을 연결했다. **수량·보상은 Claude가 채우는 단계가 남아 있다.** 미정 수치가 있는 사건을 무료 요구/무료 보상으로 처리하지 않는다. Gemini의 대사 보강과 Claude의 책 화면 확인도 이어서 필요하다.

## 진행 구조

- 기존 마을 확장의 `chapter_winter_lights` 또는 `chapter_home_again` 최종 완독 뒤 4막을 연다. 첫 겨울 장면은 기존 조건상 85일 이후다. 전체 112일을 보내야 시작하는 별도 조건은 만들지 않았다.
- 게시판에서 맡기 → 주민/방문자에게 소개 완독 → 실제 행동 → 다음 날 이후 마무리 완독. 취소, 부분 읽기, 장면 이탈, 준비 안내 완독에는 완료/답례가 없다.
- 대금은 최종 마무리 때만 지급한다. 반복 주문은 회차별 대금, 평판은 첫 완료에만 적용한다. 이정표 자체는 돈이나 무료 재료를 지급하지 않는다.
- 진행·행동 기록은 기존 `PlayerProgress.story_beat_days`에 저장한다. 새 저장 형식은 없다. 새 게임에서 함께 초기화된다.
- A는 B를 요구하지 않는다. 유적을 탐험하지 않아도 마을 성장의 다섯 이정표를 모두 완성할 수 있다.

| 사건 ID | 사건 | 실제 행동과 마무리 |
|---|---|---|
| a1_road_sign | 길목의 표지 | 가지·돌 창고 전달 → 다음 날 타블렌 완독 |
| a2_far_caravan | 먼 곳에서 온 짐수레 | a1 다음 날, 쉼터 첫 모임·등불 길손 마무리 필요. 채집한 물·열매의 상단 실결제 → 다음 날 상단 완독 |
| a3_traveler_rest | 길손의 잠자리 | 소개 후 나무 보관 선반 실제 제작 및 가구 창고/가지 전달 → 다음 날 길손 완독 |
| a4_on_the_map | 지도에 오르는 마을 | a3·설정 평판 조건 → 이세르 소개 → 다음 날 완독, 먼 곳 주문 카드 접근 |
| a5_regular_order | 상단의 정기 주문 | 야영 빵·말린 열매 창고 전달 → 다음 날 상단 완독/대금. 완료 7일 뒤 반복 |
| a6_crossroad_market | 길이 모이는 날 | a5 뒤 계절 변화, 기존 계절 모임 철(8~20일)에 맡기/실제 열매·빵 판매 → 다음 날 타블렌·코르빈·이세르 후일담 모두 완독 |
| b1_old_coin | 낡은 동전의 무늬 | 유적에서 실제 얻어 정산한 동전 → 보여주기(소비 없음) → 다음 날 이세르 완독/단서 |
| b2_rune_and_power | 룬석과 발전기 | 정상 마석 계산대·유적 룬석 발견 → 기술자에게 보여주기(소비 없음) → 다음 날 기술자 완독/단서 |
| b3_secret_merchant | 한밤의 물음 | 두 번째 실제 심야 상인 방문 이후 소개 → 소개 뒤 지도 실구매 → 상인 완독 → 다음 날 이세르에게 남긴 말 완독 |
| b4_blank_of_map | 지도의 빈칸 | b1·b2와 설정 유적 횟수 충족 → 소개 뒤 새 유적 탐험/정산 → 다음 날 이세르 완독/단서 |
| b5_question_stays | 질문으로 남기다 | b1~b4·112일 이후 → 타블렌/다음 날 코르빈/이세르 완독. 기존 단서를 대화 UI에 함께 보여주며 답은 확정하지 않음 |

a3은 현재 **기존 나무 보관 선반 제작·전달과 쉼터의 짐 놓는 자리**로 구현했다. 지붕·침상이라는 새 가구, 숙박료/회복 효과는 만들지 않았다. 추후 승인된 가구가 생기면 `furniture` 요구 항목을 바꿀 수 있다. a6은 기존 행사 철에 실제 진열/판매하는 사건이며 별도의 가격 배수·방문 증가·자동 판매를 만들지 않았다. 계절별 요구 품목/수량은 Claude 검토 항목이다.

## 이정표와 화면

1. **길목에 선 표지**: a1. 일반 손님 풀에 `road_wayfarer` 접근.
2. **첫 상단**: a2. 일반 손님 풀에 `road_caravan` 접근.
3. **쉬어 가는 길손**: a3. 기존 등불 길손과 같은 저녁/심야 시간대에 쉼터 근처 길손 방문/짧은 인사. 보상 없음.
4. **지도에 오른 마을**: a4+a5. 먼 곳 주문 카드를 맡고 첫 정기 주문까지 완독해야 한 칸이 찬다. 주문 반복은 이정표를 다시 올리지 않는다.
5. **길이 모이는 날**: a6의 세 후일담 모두 완독. 일정 탭에 매 계절 장터를 기록한다. 다음 계절 행사 철에 다시 맡을 수 있다.

- 관리 책 → 정보 → 이정표. 4막 전에는 버튼과 게시판 사건을 숨긴다. 새 게임/이전 진행으로 돌아가면 기본 정보로 전환한다.
- `BookLayout.limit_to_left_half`와 `BookFlowVBox`를 그대로 사용한다. 왼쪽 진행 5단계/현재 목표, 오른쪽 **마무리한** B 단서만 표시. SubViewport 안의 실제 쪽 폭을 따르고 가운데 제본 홈을 비운다. 긴 단서는 기존 세로 스크롤로 읽는다.
- 4막의 소탭 5개는 `기본 / 상세 / 매출 / 기록 / 이정표`로 표시해 글자가 잘리지 않는다.
- 완료 기록에서 매번 계산하며 별도 이정표 보상/저장 키를 만들지 않는다.
- 기존 3D 장식 렌더러에 작은 나무 표지와 쉼터 짐 선반의 진행 모양을 추가한다. 기존 장소 안에서 보이며 새 충돌/동선 변경이나 이미지 생성은 없다.

## 실제 행동 연결

- 손님 `checkout_item()`의 정상 결제 이후에만 판매량을 쌓는다. 다른 손님 종류, 미결제, 재시도 중복은 a2의 기록에 넣지 않는다. 일반 단골/원정 지인 진행도 유지한다.
- a2 소개 뒤 지정 물품이 진열되어 있으면 기존 행인 생성기가 하루 한 번 첫 상단 구매자를 준비한다. 다른 주민 첫 소개를 덮어쓰지 않는다. 기존 결제/실재고/정상 가격을 사용한다.
- 새 두 손님은 기존 배낭 여행자/행상인의 방문 가중치·수요·3D 외형을 이어받는다. 미해금 상태에는 일반 추첨에서 제외한다. 별도 큰 주문 수량/계절 선호 배수는 미설정이며 Claude가 필요 여부를 검토한다.
- 가구는 재료를 실제 소비하는 `FurnitureObjectCatalog.craft()` 성공 뒤에만 제작 기록을 쌓는다. 예전 소유/구매/철거 회수로 대체하지 않는다.
- 유적은 원정 방을 한 곳 이상 완료하고 성공한 결과 정산에서만 기록한다. 출발 시의 시작 노드 한 개, 즉시 철수, 다른 지역은 제외한다. 같은 영업일 정산 재시도/체크포인트 재로드는 중복 집계하지 않는다.
- 지도는 실제 방문한 상인의 정상 판매 창에서 돈을 지불하고 재고가 줄어든 뒤에만 기록한다. 수락 전 구매, 첫 방문, 잔액 부족/빈 재고에는 기록하지 않는다. 가격·지도 공급은 바꾸지 않았다.
- 심야 상인의 실제 E 처리에도 대화 우선순위를 연결했다. 소개 완독 뒤 구매를 기다릴 때는 준비 대화가 E를 가로채지 않고 판매 창을 연다. 실구매 후 E로 상인의 단서를 듣는다.
- 순회 기술자의 룬석 소비 여부는 초안에서 미정이므로 **보여주기만**으로 연결했다. 기존 저장의 정상 계산대도 b2에 접근할 수 있다.
- 방문자는 기존 외부 타일·충돌·플레이어/다른 이야기 NPC와의 간격 검사를 사용한다. 대화 동안 이동/시계를 멈추고 종료 시 이전 상태를 복원한다.

## Claude가 채울 설정

`scenes/shop/requests/default_act_four.tres`의 `null`은 미확정이다. 숫자 0과 구별한다. `configuration_issues(id)`가 미확정/미등록 물품/잘못된 수량을 반환하며 그 사건의 수락·소비·완료를 막는다. 숫자는 `.tres`의 정수로 채운다. 검사 장면만 메모리에서 임시 수치를 넣었다가 복원한다. 게임 설정/사용자 저장에 검사 수치를 쓰지 않는다.

| 사건 | 채울 항목 |
|---|---|
| a1 | `money`, `reputation`, 가지/돌 `requirements[].amount` |
| a2 | `money`, `reputation`, 물/열매 `sales[].amount` |
| a3 | `money`, `reputation`, 나무 선반 `furniture[].amount`, 가지 수량 |
| a4 | `minimum_reputation` (별도 경제 답례 없음) |
| a5 | `money`, `reputation`, 빵/말린 열매 수량·기존 반복 주문 단가와 비교 |
| a6 | `money`, `reputation`, `sales` 품목/수량. 계절별 품목이 필요하면 먼저 협의 |
| b4 | `minimum_ruins` (초안의 3회는 미확정이며 코드에 고정하지 않음) |

수치가 채워지면 다음 실행에서 자동으로 조건을 평가한다. 기본 데이터에서는 A 사건 6개와 B4의 수치가 미정이므로 아직 수락할 수 없다. 나머지 B 사건은 별도 돈/평판/선물이 없으며, 실제 발견/구매 및 선행 완료 조건을 따른다.

## Gemini에게 넘기는 글

- 기존 `service_text`만 사용. 새 종류를 도구에 요구하지 않는다.
- `requests_text.csv`에 **51행**: 실제 진행 34장면, 게시판 제목/요약 11행, 단서 5행, 쉼터 안부 1행. 전체 452행.
- `default_act_four.tres`의 `moments`와 `content_voices.csv`에 화자/진행 문맥 등록. 화자 원본 `character_names.md`, `character_voices.csv`는 수정하지 않았다.
- 새 인물 이름은 역할명만. 주민은 타블렌·코르빈·이세르. 현대 기기 사용 안내나 전이 원인 확정, 무료 지도/물품, 지붕·침상·숙박 효과를 대사에 약속하지 않는다.
- 제목/요약/단서 행은 NPC 대사가 아니므로 해당 필드만 보강한다. 대사에는 수량·금액·평판·조작 키를 넣지 않는다. 중간 단계 답례를 약속하지 않는다.
- `dev/gemini/request_text_tools.gd` 원본 목록에 등록했다. 사용자 실행 예시: `dev\gemini\run_request_text.bat draft service_text --ids act4_a1_intro,act4_a1_delivery,act4_a1_finish --chunk 3`. 나머지 ID도 사건별로 골라 실행하고 `validate`/검수 뒤 반영한다. 이번 작업에서는 API를 호출하지 않았다.

## 검증

- Godot 4.7.1 import 두 번 성공, 스크립트 오류 없음. 전체 659개 로드 실패 0.
- 새 4막 검사 159개 통과. 실제 결제·물품/가구 소비·지급 중복 방지·소개 이후 행동·다음 날·취소·저장/새 게임·A/B 독립·방문자 배치·책 두 쪽·달력·3D 진행 표시와 심야 상인의 대화→판매 창→구매 후 대화 E 경로를 확인했다.
- 기존 검사: 마을 확장 1155, 단골 281, 가구 563, 계산대 수리 38, 통합 88, 수첩/글 도구 모두 통과. 마을 검사의 수는 무작위 방/실재 판매에 따라 달라진다.
- 직접 원정 16/16 완료, 막힘 0, 스크립트 오류 없음.
- 전체 대사 452행 오류/주의 0. 실제 그래픽 검사 159개 통과, 펼친 책에서 두 쪽과 소탭 이름을 확인했다.
- 기존 CSV 경제 기준선은 객단가 276G/가정 일매출 7448G/초기 급여 0G. 재고 충분·기존 가중치의 계산이며 새 4막 요구/답례와 해금 뒤 손님 비율은 평가하지 않는다. 미정 수치가 채워진 뒤 Claude의 경제 검토가 필요하다.
