# 배운 상품이 이웃의 일상으로

## 방향

교류로 제조법을 배우고 시제품을 나눈 뒤, 그 상품이 이웃의 생활에 쓰이는 작은 부탁을 이어 붙인다. 원정 재료 → 배운 제조법 → 완제품 → 주민의 생활 → 다음 날 사용 후일담의 흐름이다. 기존 세 주민과 게시판·수첩을 사용한다.

## 부탁 3개

| ID | 주민 | 선행 제품 이야기 | 완제품 | 최초 전달 대금 | 평판 |
|---|---|---|---|---|---|
| naru_trail_snacks | 타블렌 | craft_trail_food 시제품 나눔 완료 | 말린 열매 2 | 530 G | +1 |
| doyun_pocket_warmth | 코르빈 | craft_clear_water 시제품 나눔 완료 | 손난로 1 | 250 G | +1 |
| sora_evening_tea | 이세르 | craft_shared_meal 시제품 나눔 완료 | 갈대 차 2 | 530 G | +1 |

- 각 주민 정착·핵심 튜토리얼·안부 3일·해당 제조법 학습이 필요하다. 해당 제품 이야기의 소개나 제조법 습득만으로는 열리지 않는다. 실제 제작 수령과 시제품 전달을 마친 **다음 날** 게시판에서 맡을 수 있다.
- 대금은 현재 일반 상품 가격 × 전달 수량 + 작은 사례비 30 G로 정한 초기값이다. 무료 시제품 이후에도 완제품을 공짜로 계속 주는 흐름이 되지 않게 했다. 동적 가격이나 행사 배율은 적용하지 않으며 수치는 `.tres`에 있다. Claude 경제 검토 대상이다.
- 주민 E 대화에서 부탁을 들은 뒤 **게시판에서 맡기/전달하기**를 누른다. 완제품은 일반 창고에서 소비한다. 원재료를 갖고 있는 것만으로 전달하지 않는다. 게시판 버튼으로 실제 전달과 대금·평판 지급이 이루어지며 대화 완독을 전달 조건으로 추가하지 않는다.
- 맡기 전에 만들어 둔 상품도 사용할 수 있다. 계절·날씨·기간 제한이 없고 맡은 뒤 오래 쉬어도 유지된다. 기존 고객 해금용 정착 부탁 완료 개수는 늘리지 않는다.

## 다음 날 후일담 3개

| ID | 내용 |

전달 당일에는 완료 기록에 다음 날 안내를 남기고, **전달 다음 날 이후** 기존 주민 E 대화에서 후일담을 들을 수 있다. 완독해야 수첩 기억을 기록한다. 중간에 닫거나 장면을 나가면 아직 듣지 않은 상태로 남는다. 이전 후일담이 밀려 있다면 기존 순서대로 먼저 듣는다. 후일담에 추가 물품·돈·평판은 없다. 하루 첫 안부의 기존 선물은 별개다.

길을 떠나거나 차를 마시는 이야기는 대사로 표현한다. 새 여행 이동·음용 연출·회복·추위 피해·장비 능력치·고객 수요 변화·건물 배치를 추가하지 않는다. 현재 날씨를 단정하지 않으며 현대 가게 설비 조작을 현지인이 가르치지 않는다.

## 연결과 저장

- `default_workshop_requests.tres`: 기존 `MarketAfterglowSettings`의 requests/moments를 재사용한다.
- `WorkshopRequestFlow`: 해당 제품 이야기의 실제 완료/다음 날 조건만 검사한다.
- `PersonalRequestFlow`: 새 부탁을 기존 등록 목록에 추가하고 제품 선행 조건을 확인한다. 개인 부탁 총 20 → **23개**.
- `MarketAfterglowFlow`: 새 순간 3개를 추가하고 각 순간의 `days_after_delivery`를 확인한다. 기존 순간의 기본값은 0이라 당일 듣던 흐름을 유지한다. 후일담 총 11 → **14개**.
- 기존 주민 E, 게시판 카드, 완료 버튼 비활성화, 수첩 목적지, `personal_request:<id>:accepted/done`와 `market_afterglow:<id>:heard` 저장 키를 사용한다. 자동 수락/선행 기록 이식은 없다. 이전 저장도 선행을 실제로 완료하면 접근할 수 있다.

## Gemini 대사 보강

기존 `personal_request` 3행, `service_text` 3행을 `requests_text.csv`에 등록했다. 추가 문맥은 `content_voices.csv`에 있으며 정식 이름/말투 파일은 변경하지 않았다. SOURCE_FILES와 혼합 리소스 읽기, 프롬프트에 실제 단계·지급 시점·완제품 조건을 등록했다. API는 호출하지 않았다.

```bat
dev\gemini\run_request_text.bat draft personal_request --ids naru_trail_snacks,doyun_pocket_warmth,sora_evening_tea
dev\gemini\run_request_text.bat draft service_text --ids workshop_afterglow_naru,workshop_afterglow_doyun,workshop_afterglow_sora
dev\gemini\run_request_text.bat sync
```

출력은 검수 전 초안이다. 보강할 때 수량/키/금액은 UI에 맡기고, 이미 지급한 대금을 후일담에서 다시 약속하지 않는다. 사용 후기의 기능적 효과와 무료 상품을 새로 약속하지 않는다.

## 검증

`check_workshop_requests`에서 실제 제조 설비의 제작/수령→시제품 선행 완료→다음 날 부탁→주민 E→게시판 수락/전달→다음 날 E 후일담을 확인한다. 부족한 완제품·동일 날 진행·중복 대금·부분 읽기·건축 모드·저장 왕복·계절 변경·기존 손님 해금 규칙을 검사한다. 기존 개인 부탁/장터 후일담/쉼터 부탁/제품 발전/단골/원정 만남/날씨/통합 검사도 함께 확인한다.

- Godot 4.7.1: 새 부탁 **118개 검사 실패 0**, 기존 장터 후일담 97/생활 부탁 98/제품 발전 120/단골 281/원정 만남 336/날씨 177/3D 통합 88/도입 독백 34/첫 거래 80 실패 0. 개인 부탁·수첩·글 도구·런타임 대사 검사도 통과했다.
- 원격 main의 3D 진열대/Visual 좌표 복구/2D 캐릭터 제거 `1d5c71f`까지 포함했다. 새 세 주민의 실제 3D 등록과 E 대화를 확인했다. 삭제된 2D Visual을 찾던 날씨 검사의 전제만 현재 3D NPC 상태로 수정했고, 수정 후 177개 실패 0이다.
- 전체 리소스 **617개 로드 실패 0**. import 2회와 기본 실행 240프레임 종료 0, SCRIPT/Parse 오류 없음. 기존 Windows 인증서 저장소 경고와 기존 누락 아이콘 경고는 남아 있다. 사용자 화면의 대사 호흡은 별도 확인 대상이다.
- 전체 대사 CSV **298행**, 오류/주의 0. 반복 어구와 창고→게시판 전달 안내를 새 행에서 다듬었다. 종류나 검수 규칙은 늘리거나 완화하지 않았다.
- 기존 경제 기준선 도구 종료 0: 객단가 257 G/가정 일매출 6,946 G/초기 직원 급여 0. 기준선은 새 부탁의 상품 대금·사례비 경제를 모델링하지 않으므로 신규 수치는 Claude 검토 요청으로 남긴다.
