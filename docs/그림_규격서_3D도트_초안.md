# 그림 규격서 — 3D 도트 방식 (초안 v0.1)

작성일: 2026-10-02 · 근거: `3D_도트_기법_참고.md`(기법과 시험 결과), `dev/spike3d/`(시험 장면)
관련: `에셋_규격서_초안.md`(기존 2D 규격. 월드·매장 그림은 이 문서가 **우선**하고, 아이콘·UI·원정 2D 그림은 기존 규격을 따른다 🟡)

## 0. 사용법

- 태그: ✅ 사용자가 결정 / 🟡 초안 제안(시험으로 확인 중) / ❓ 미정
- 그림을 만드는 쪽은 **3장(칸·질감), 4장(오브젝트), 5장(캐릭터), 6장(빛·법선 맵)** 의 표를 따른다.
- 이 방식은 **3D 모델에 작은 도트 질감을 씌워 낮은 해상도로 그린 뒤 정수 배로 늘려** 도트처럼 보이게 한다. 그래서 "스프라이트 한 장"이 아니라 **면별 질감**을 그린다.
- 지금까지의 시험은 이 개발 환경의 **소프트웨어 렌더링**에서만 했다. 실제 PC(GPU)에서 같은지는 확인 전이다. 질감은 코드로 만든 임시 그림이었고, Pixel Lab 으로 이 규격의 그림을 만들 수 있는지도 확인 전이다.

## 1. 결정 사항

| 항목 | 내용 | 상태 |
|---|---|---|
| 표현 방식 | 3D 로 그리고 낮은 해상도 → 최근접 확대(Never's End 방식). 픽셀 스냅, 정렬 순서 깊이, 한 픽셀 윤곽선 사용 | ✅ |
| 확대 배율 | **3배** (2배는 선명하지만 3D 느낌이 강해서 제외). 2.5배는 정수 픽셀이 안 맞아 쓰지 않는다 | ✅ |
| 칸 크기 | 낮은 해상도 기준 **32×16** | 🟡 (대안: 36×18 — 화면에서 칸이 약 12% 커 보임. 같은 장면으로 비교 후 결정) |
| 캐릭터 비율 | **2.5등신** | ✅ |
| 표정 | 월드 캐릭터는 **표정을 그리지 않는다**(눈 점 1px 정도까지). 구분은 머리색·옷색·모자 실루엣, 감정은 머리 위 아이콘, 표정은 대화 초상화에서만 | ✅ |
| 시점 | 위에서 30° 내려다봄, 45° 돌림(2:1 마름모). 완전한 정면이 아님 | ✅ |
| 빛 | **법선 맵**으로 요철 음영을 만들고, 낮/밤은 빛의 방향·색·세기로 구분 | ✅ (시험 전) |

## 2. 화면 기준표 (3배)

| 항목 | 값 |
|---|---|
| 실제 창 | 1152×648 |
| 낮은 해상도(그림이 그려지는 크기) | **384×216** (1픽셀 = 화면 3픽셀) |
| 카메라 | 정사영, 위에서 30°, 45° 회전 |
| 칸 한 개 | 낮은 해상도에서 **32×16** 마름모 (화면에서는 96×48 — 기존 게임과 같음) |
| 블록 높이 | 1블록 = 세로 **20px** (정수 픽셀이 되도록 정함) |
| 캐릭터 키 | 약 0.95칸 ≈ **21px** 🟡 (24~25px 로 키우는 안은 ❓, 5장) |

## 3. 질감 규격 (칸·바닥·벽)

| 종류 | 크기 | 비고 |
|---|---|---|
| 바닥 질감 | **16×16** (이음매 없이 반복) | 한 칸에 1장. 위에서 보면 마름모로 보인다 |
| 벽·가구 옆면 | 폭 **16** × 높이 **20 × 블록 수** | 한 칸 폭이 화면에서 16px 로 보임 🟡 (시험은 16×16 반복이라, 높이는 실제 그림으로 확인 필요) |
| 윗면 | 칸 수 × 16 | 2×1 칸 윗면 = 32×16 |

- ✅ **색 수**: 질감 한 장당 8~12색, 장면 전체 공용 팔레트 ❓ (기존 규격 3장 5항과 같은 이슈).
- ✅ 알파는 쓰지 않는다(불투명). 투명이 필요한 소품은 4장의 스프라이트형으로 만든다.
- 🟡 **외곽선을 그림에 넣지 않는다.** 물체 경계의 1px 윤곽선은 코드가 후처리로 그린다(기존 규격 3장 3항과 다름). 벽돌 줄눈·판자 틈 같은 **안쪽 선**은 그려도 된다.
- 🟡 질감의 **그림자·빛 표현을 넣지 않는다.** 밝고 어두움은 코드의 빛(6장)이 만든다. 질감은 "빛이 없을 때의 색"으로 평평하게 칠한다.

## 4. 오브젝트(가구·소품) 규격

두 종류로 나눈다.

**A. 상자형 (진열대, 계산대, 테이블, 벽, 문틀 등)** — 대부분
- 크기: **발자국 칸 수(가로×세로) × 높이 블록 수**로 정한다.
- 그림: 윗면, 앞면(왼쪽 아래를 보는 면), 옆면(오른쪽 아래를 보는 면) 질감 3장(+법선 맵 3장). 뒷면은 안 보인다.
- 발자국 상자가 **충돌 범위이자 정렬 범위**다(별도 충돌 모양을 그리지 않는다).

| 오브젝트(시험 값) | 발자국 | 높이 |
|---|---|---|
| 진열대 | 2×1 (실제 두께는 0.6칸) | 1.6블록 (32px) |
| 진열 테이블 | 2×1 | 0.9블록 (18px) |
| 계산대 | 1.5×1 | 1.1블록 (22px) |
| 벽 | 길이 × 두께 0.5 | 3블록 (60px) |
| 문 | 2칸 폭 개방(입구/출구) | — |

→ 위 값은 시험용이다. 실제 가구 목록의 발자국·높이는 **기존 가구 데이터를 읽어 표로 맞춘다** ❓(다음 단계).

**B. 스프라이트형 (병·상품·화분·장식 등 상자로 안 되는 작은 것)**
- 한 장짜리 판, 아래 크기 기준. 판은 카메라를 향해 서 있고, 정렬 상자는 발 밑 작은 상자로 쓴다.
- 크기: 16의 배수 폭 × 높이 자유(최대 64), **알파 0 또는 255**, 발 중앙 하단이 기준점.
- 법선 맵은 선택(6장).

## 5. 캐릭터 규격

### 5.1 비율과 크기 🟡
- 전체 키 약 **21px**(0.95칸), **2.5등신** → 머리 높이 약 8~9px, 몸통 약 7px, 다리 약 6px.
- 머리는 폭 약 9px(높이의 1.1배), 몸통 폭 약 7px, 팔·다리 폭 2~3px.
- ❓ 키를 24~25px 로 키울지(칸 대비 약 1.2배, 얼굴·실루엣이 조금 더 읽히지만 가구와 비율이 어긋남).

### 5.2 구분 방법 (표정 대신) ✅
- 머리색(5종 이상), 옷색, 모자·앞치마·가방 같은 **실루엣 소품**으로 구분한다.
- 얼굴은 눈 점 1px 두 개까지만 허용, 입은 생략한다.
- 감정(화남, 만족, 대기)은 머리 위 **아이콘 8×8**(별도 UI 스프라이트)로 보인다.

### 5.3 만드는 방식 — 두 갈래 ❓
사용자 결정 전. 매장 시험은 **A**로 만들었다.

| | A. 상자 캐릭터 | B. 도트 판 |
|---|---|---|
| 구성 | 머리·몸통·팔×2·다리×2 상자에 면별 질감 | 방향별 걷기 프레임 시트 |
| 방향 | 어느 방향이든 돌려서 맞음 | 4방향 × 4프레임(좌우 반전 가능) |
| 그려야 하는 것 | 부품당 앞·옆·윗면 (머리 3장, 몸통 3장, 팔 1장, 다리 1장 등 약 8장) | 약 16~24프레임 |
| 걷기 | 코드로 4단계 끊어 흔듦(보간 없음) | 그려진 프레임 |
| 강점 | 3D 정렬·윤곽선·빛에 자연스럽게 맞음 | 도트 손맛, Pixel Lab 으로 만들기 쉬움(확인 전) |

### 5.4 부품 질감 크기(A안, 1질감 픽셀 = 화면 1픽셀) 🟡
| 부품 | 앞 | 옆 | 윗면 |
|---|---|---|---|
| 머리 | 9×8 | 8×8 | 9×8 (가르마·머리결: 위에서 내려다보므로 윗면이 크게 보임) |
| 몸통 | 7×7 | 4×7 | 7×4 |
| 팔 | 2×6 | 2×6 | 2×2 |
| 다리 | 3×6 | 3×6 | 3×3 |

- 앞머리가 이마를 덮고 얼굴은 앞면 아래쪽에 둔다(윗면이 크게 보이는 시점이기 때문).
- 뒷면은 윗면의 머리카락 색으로 대체한다.

## 6. 빛과 법선 맵 ✅ (시험 전)

### 6.1 목적
빛의 방향·색·세기만 바꿔서 **낮과 밤이 달라 보이게** 하되, 그림은 한 벌만 만든다. 법선 맵이 있으면 방향이 있는 빛(해)이 움직일 때 벽돌 줄눈·나무결·천 주름의 **음영이 같이 바뀌어** 시간대가 더 잘 느껴진다.

### 6.2 법선 맵 규격
- 각 질감 `X.png` 마다 선택적으로 짝 `X_n.png`. **같은 크기**, 최근접 필터, 압축 없음.
- Godot(OpenGL) 방식: 평평한 곳 = (128,128,255), 빨강 = 오른쪽, 초록 = **위쪽**.
- 🟡 요철은 **약하게, 단계는 적게**(기울기를 8방향·1~2단계 정도). 도트 한 칸 단위의 홈과 볼록만 표현하고 부드러운 곡면 그라데이션은 쓰지 않는다. 안 그러면 도트 느낌이 흐려진다.
- 평평한 면은 법선 맵을 생략한다(코드가 기본값 사용).

### 6.3 빛의 구성 🟡
| 시간대 | 해(방향광) | 환경광 | 기타 |
|---|---|---|---|
| 낮 | 흰색~연노랑, 높은 각도, 세기 큼 | 밝음 | — |
| 아침·저녁 | 주황, 낮은 각도(긴 그림자) | 중간 | — |
| 밤 | 파란색, 약함 | 어두움(남색) | 매장 조명·가로등·간판 점광원이 주변만 밝힘 |

- 빛 계산은 **계단식(툰 램프) 3~4단계**로 둔다. 연속 그라데이션은 도트처럼 안 보인다. (시험 방 1에서 계단식 빛은 이미 동작 확인)
- 낮·밤 전환은 하루 시간(게임 24시간)에 맞춰 코드가 값을 이어서 바꾼다. 기존 `day_night_tint.gd`와의 관계는 ❓(대체 or 병행).
- ❓ 밤에 켜지는 창문·간판 같은 **스스로 빛나는 부분**: 발광 마스크 `X_e.png`(흰색 = 발광) 를 따로 둘지.

### 6.4 법선 맵을 만드는 방법 ❓
1. Pixel Lab 등이 법선 맵을 직접 내는지 → **확인 전**(사이트가 이 환경에서 안 열림). 사용자가 확인.
2. 안 되면 **높이 맵(회색조 도트, 밝을수록 높음)** 을 같은 크기로 그리고 `tools/` 스크립트로 법선 맵으로 변환한다(이 스크립트는 아직 없음 — 필요하면 만든다).
3. 둘 다 안 되면 법선 맵 없이 방향·색만으로 낮/밤을 구분한다(차이가 약해지는 것은 시험으로 확인).

### 6.5 확인할 시험 (다음 작업)
- 매장 시험 장면에 법선 맵 한 장(벽돌)과 해 각도·색 슬라이더(시간)를 넣어, 낮/아침/저녁/밤이 구분되는지 본다.
- 윤곽선·정렬 깊이와 법선 맵이 같이 켜져도 문제 없는지(셰이더 충돌) 본다.

## 7. 파일 규칙 🟡

- 폴더: `art/world3d/` ❓ (기존 `art/world/` 와 섞지 않는다). 하위: `floor/`, `wall/`, `furniture/`, `props/`, `actors/`.
- 이름: 소문자·숫자·밑줄. `shelf_a_top.png`, `shelf_a_front.png`, `shelf_a_side.png`, 법선 맵은 `_n` 접미(`shelf_a_front_n.png`), 발광은 `_e`.
- 버전 폴더(`_v1`)는 만들지 않는다(git 으로 관리).
- 검증: `tools/validate_assets.py` 는 아직 이 규격을 모른다. 규격이 확정되면 `RULES` 에 **크기(16 배수)·알파 0/255·색 상한** 검사를 추가한다.

## 8. Pixel Lab 요청문 초안 (만들 수 있는지는 확인 전)

공통 문구(영문): `pixel art texture, flat unlit colors, no outline, no shadows, no lighting, limited palette 8-12 colors, seamless, nearest-neighbor, size WxH`

1. **바닥 16×16**: `wooden plank floor, seamless 16x16, warm brown, subtle grain, flat unlit` (필요하면 높이 맵: `same texture as grayscale height map, grooves darker`)
2. **벽 16×60(3블록)**: `brick wall side face, 16x60, pale blue-gray bricks, dark mortar lines inside only, flat unlit`
3. **진열대 앞면 16×32 / 윗면 32×16**: `convenience store shelf front, 3 shelf boards with colorful goods, no outline`
4. **캐릭터 머리 앞 9×8**: `top-down-ish 3/4 view chibi head front, brown hair bangs covering forehead, two 1px dark eyes, no mouth`
5. **캐릭터 머리 윗면 9×8**: `top view of chibi head, brown hair, side parting line`

## 9. 오픈 이슈

1. 칸 32×16 vs 36×18 (2장)
2. 캐릭터 키 21px vs 24~25px (5.1)
3. 캐릭터 제작 방식 A(상자) vs B(도트 판) (5.3)
4. 공용 팔레트 색과 개수 (3장)
5. 법선 맵 생성 방법과 Pixel Lab 지원 여부 (6.4)
6. 발광 마스크 도입 여부 (6.3)
7. `day_night_tint.gd` 와의 관계 (6.3)
8. 폴더 `art/world3d/` 확정 (7장)
9. 실제 가구·문·벽의 발자국·높이 목록 확정 (4장)
10. 실제 PC(GPU)에서 시험 결과 일치 확인
