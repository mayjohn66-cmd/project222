# 등불 아래의 길손 (2026-10-03)

퀘스트·이벤트 콘텐츠 추가 순서의 첫 번째. 두 번째 **이세르의 마을 이야기**는 `docs/콘텐츠_이세르의_마을_이야기.md`에 이어진다. 다음 **작은 노점의 첫 장터**는 아직 구현하지 않았다.

## 플레이 흐름

1. 튜토리얼과 공동 부탁 `path_light`(길목에 작은 등불)을 완료한다.
2. 저녁·심야 18시부터 다음 날 6시 전까지 등불 근처에 **불빛을 따라온 길손**이 나타난다. 일반 손님 무작위 추첨과 별도인 이야기 인물이다.
3. 가까이에서 E로 첫 대화를 끝까지 듣는다. 물/빵 전달 화면에서 **창고의 물 1개 또는 빵 1개 중 한 가지**만 선택해 건넨다. 대화만으로 물품을 가져가지 않는다.
4. 아직 준비하지 못했으면 창을 닫고 나중에 다시 찾아온다. 첫 부탁을 들은 후에는 낮에도 길손을 만날 수 있고 기한이 없다. 진열대와 원정 가방의 물품은 사용하지 않는다.
5. 건네준 물품에 맞는 대화를 한 뒤 길손이 떠난다. 전달한 게임 날짜의 다음 날부터 다시 나타나며 재방문에는 시간대·기한 제한이 없다. 하루 경계는 기존 06시 정산 규칙을 따른다.
6. 재방문 대화를 끝까지 듣고 **밀 2개·평판 1**을 한 번 받는다. 돈 지급과 손님 유형 해금은 없다. 수첩에는 다시 만난 날짜와 기억을 남긴다.

수량·평판·등장 시간·재방문 간격은 초기 조정값이며 `LanternWayfarerSettings`와 `default_lantern_wayfarer.tres`에서 바꾼다. 기존 2/4/6 주민 부탁의 손님 해금 개수에는 더하지 않는다.

## 연결·저장

- NPC는 기존 배낭 여행자/여행자 외형을 재사용한다. 새 이미지·캐릭터 고유 이름은 만들지 않았다.
- 기존 바닥의 장애물이 없는 등불 접근 위치를 사용한다. 사용자가 지운 등불은 복구하지 않으며, 남아 있는 복제본 또는 기존 게시판을 이용한다. 두 장소 모두 없으면 NPC 위치를 만들지 않고 수첩에서 진행 상태를 확인할 수 있다.
- 마을 수첩의 **등불 아래의 길손** 항목으로 NPC 또는 대기 장소를 표시한다. 완료 후에는 날짜와 기억을 확인한다.
- 진행 키는 `village_event:lantern_wayfarer:accepted/helped/choice:<id>/done`. 기존 `PlayerProgress.story_beat_days`에 저장하므로 저장 형식 변경이 없다.
- 첫 대화 도중 종료하면 부탁을 받은 것으로 기록하지 않는다. 전달 버튼 이후 종료해도 선택·전달은 보존되고 중복 차감하지 않는다. 재방문 대화 도중 종료하면 답례를 지급하지 않고 다시 이야기할 수 있다.
- 대화·전달 화면은 시간과 플레이어 이동을 잠시 멈추고 다른 상호작용을 막는다. 창을 닫거나 장면을 나가면 이전 상태로 복원한다.

## 제미나이의 글 작업

새로운 종류 없이 기존 `service_text`를 쓴다. 기계 항목은 `default_lantern_wayfarer.tres`의 `moments`, 임시 문장은 `data/shop/requests/requests_text.csv`, 상황별 말투는 `docs/drafts/story/content_voices.csv`에 있다. 정식 인물 기준 파일은 수정하지 않았다.

| ID | 역할 |
|---|---|
| `lantern_wayfarer` | 제목·수첩 소개·첫 만남 대사·완료 기억 |
| `lantern_wayfarer_water` | 물 선택 제목·물을 받은 반응 |
| `lantern_wayfarer_bread` | 빵 선택 제목·빵을 받은 반응 |
| `lantern_wayfarer_return_water` | 물을 받았던 길손의 재방문 |
| `lantern_wayfarer_return_bread` | 빵을 받았던 길손의 재방문 |

- 글 도구의 원본 목록에 다섯 항목을 등록했다. 프롬프트에 인물과 장면 순서가 전달된다. 기존 `sync`, `draft service_text`, `polish`, `validate`, `accept` 경로를 사용할 수 있다.
- 서로 다른 전달 반응과 재방문 반응을 유지한다. 첫 만남에는 편의점의 낯선 모습에 대한 반응을 더할 수 있다. 재방문을 늦게 확인할 수도 있으므로 "어제"처럼 실제 날짜를 단정하지 않는다.
- 건네는 수량과 답례 수치를 대사에 쓰지 않는다. 정착·새 고객 해금·실제 구매·정기 재방문을 약속하지 않는다. 종료된 이벤트 인물은 사라지고 현재는 이 재회 한 번만 구현했다.
- API 호출은 하지 않았다. 사용자가 Gemini 도구를 실행하고 초안을 검사·검토한 뒤 반영한다.

## 검증

- Godot 4.7.1: 가져오기 2회, `.gd/.tscn` 전체 412개 로드 실패 0.
- `dev/scenes/check_lantern_wayfarer.tscn`: 첫 등장 시간, 실제 E 대화와 전달 버튼, 물/빵 분기, 재료 부족, 명시적 선택·중복 차감 방지, 날짜 지연, 대화 중단·재시도, 정확한 답례와 중복 지급 방지, 저장 왕복·새 게임, 이전 시간·이동 상태 복원, 사용자 지도 보존·삭제된 등불의 대체 위치, 수첩 목적지, 글 도구 등록과 장면 정보 등 47개 통과.
- 기존 글 런타임·글 작성 도구·공동 부탁 게시판·저녁 모임·마을 수첩 검사 통과.
- 593×523 창에서 전달 화면을 실제 렌더링해 물품 선택·닫기 버튼이 화면 안에 보이는 것을 확인했다. 이 렌더링 실행에서도 이벤트 47개 검사가 통과했다.
- `tools/balance_baseline.py` 실행 성공. 이 도구는 새 이벤트의 일회성 물품 교환 효과를 직접 계산하지 않는다.
- 기존 인증서 저장소 오류와 재료 아이콘 누락 경고는 남아 있다. 코드 실행 중 `SCRIPT ERROR`는 없다. 사람이 처음부터 끝까지 직접 플레이한 확인은 아직 하지 않았다.

## 확인용 브랜치

`feature/village-life`에서 확인한다. 3D 작업 브랜치에 자동 병합하거나 사용자가 Godot로 여는 폴더의 브랜치를 변경하지 않았다. 3D 쪽으로 통합할 때는 이 브랜치의 누적 콘텐츠와 함께 검토해야 한다.
