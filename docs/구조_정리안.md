# 폴더·콘텐츠 구조 정리안 (2026-10-12 초안)

> 상태: **제안(🟡), 1~2단계 완료.** 이 문서는 지금 구조를 한눈에 보이게 정리하고, 옮길 곳을 제안한다. **1단계(폴더 지도), 2단계(`tools/` 분류), 3단계(`requests/` 분할), 4단계(`shop/` 직속 정리)를 진행했다. 5단계는 남음.** 이동·이름 변경은 `AI_협업_규칙.md`에 따라 사용자 승인 뒤에 단계별로 한다.
> 참고한 형식: 폴더마다 `# 한 줄 설명`을 붙인 언리얼 프로젝트 구조(사용자가 보낸 그림 2장). 이 프로젝트에도 같은 식의 지도를 둔다.

## 4. 지금 구조의 문제

1. **`script/world/shop/requests/` 73개**가 한 폴더: 이야기 종류별로 찾기 어렵다. 같은 이야기도 `_director`(화면 담당)·`_flow`(진행 규칙)·`_settings`(수치 데이터) 세 파일로 갈려 있어 이름 접두어만으로 묶여 있다.
2. **`script/world/shop/` 직속 29개**: 가게 운영(day_manager, shop_stock), 마을 건물·장식(village_*), 원정 길가(dungeon_*), 이야기(story_*)가 한 층에 섞여 있다.
3. **`tools/` 58개**: 그림 가공·밸런스 점검·이야기 내보내기·코드 검사가 한 층에 있다.
4. **`data/shop/catalogs/` 19개**: 가구·상품·상점·손님 정보가 섞여 있다(손님 정보는 `data/shop/` 직속에도 있다).
5. **`docs/`**: 앞에서 정리한 콘텐츠 문서와 그림 작업 기록이 한곳에 있고, 크기의 대부분(220MB)이 그림 작업 원본이다(`.gdignore`로 게임엔 안 들어간다).
6. 폴더를 설명하는 한 줄이 없다: 새로 들어온 사람(AI 포함)이 어디에 무엇을 둘지 알기 어렵다.

## 6. 옮길 때의 위험과 방법

- 코드는 `res://script/...` 경로를 씬 126곳, `preload` 52곳, 데이터 일부에서 문자열로 쓴다. 옮기면 **경로를 일괄로 바꿔야 하고**, 파일마다 붙은 `.uid`도 같이 옮겨야 한다.
- `class_name`으로 부르는 코드는 경로가 바뀌어도 영향이 없다(대부분의 흐름 코드가 해당).
- 확인 방법: 이동 전후에 전체 `check_*` 테스트(109개)와 `tools/code/dynamic_call_check.py`, 가져오기(`--import`)를 돌린다. 이동은 **한 묶음씩 커밋**해 문제가 나면 그 커밋만 되돌린다.
- 이름 변경은 하지 않는다(폴더만 나눈다). 파일 이름은 그대로 두어 검색·기억이 유지된다.

## 7. 사용자가 정할 것 ❓

1. 단계 1~5 중 어디까지 진행할지(권장: 1 → 2 → 3, 나머지는 목요일 이후).
2. 콘텐츠 이야기를 **막(프롤로그~4막) 기준**으로 코드 폴더를 나눌지, 위 제안처럼 **종류(주민·마을·단골·4막) 기준**으로 나눌지. 지금 이야기는 막을 가로질러 재사용되므로(예: 마을 이야기가 3막과 4막 사이) 종류 기준을 제안한다.
3. 목요일 마감 전에 이동을 해도 되는지. 이동 자체는 게임을 바꾸지 않지만 경로 오류가 숨어 있을 수 있어, 하더라도 **마감 3일 전 이후엔 하지 않는 것**을 권한다.
