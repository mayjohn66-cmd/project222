# 사계절 생활 재료 부탁

> 후속 [주민과 남기는 작은 기억](콘텐츠_주민과_남기는_작은_기억.md) 3개를 추가했다. 관련 계절 부탁 중 하나를 마친 뒤 이웃의 마음을 선택해 기록하는 이야기이며, 아래 계절 부탁 규칙은 유지한다. 최신 전체 대사 CSV는 209행이다.

사용자 요청(2026-10-04): 다음 콘텐츠를 순서대로 이어간다. 매장 행사 후 개인 부탁과 후일담 다음에, 계절마다 이웃의 생활 준비를 돕는 재료 부탁 4개를 추가했다. 소문과 판매에서 시작한 인연이 간식·차·저녁·끼니 준비로 이어진다.

## 이번 묶음

| 계절 | 이야기 / 주민 | 선행 개인 부탁과 후일담 | 창고에서 전달할 재료 | 최초 답례 |
|---|---|---|---|---|
| 봄 | 봄 향을 보탤 재료 / 타블렌 | 이웃과 나눌 약초 빵 (`naru_lunch_extra`) | 숲 약초 2 + 야생 열매 2 | 밀 2·평판 1 |
| 여름 | 차를 준비할 작은 여유 / 코르빈 | 물가의 미네랄 워터 (`doyun_waterside_flask`) | 늪 갈대 2 + 채집한 물 2 | 돌 조각 2·평판 1 |
| 가을 | 저녁 채비에 보탤 재료 / 코르빈 | 이세르의 갈대 차 (`sora_autumn_tea`) | 발광 해초 2 + 늪 갈대 1 | 석탄 2·평판 1 |
| 겨울 | 옆자리 몫을 생각하며 / 타블렌 | 코르빈의 여행자 스튜 (`doyun_winter_breakfast`) | 숲 버섯 2 + 밀 2 | 마른 가지 2·평판 1 |

가을·겨울은 앞선 이웃의 생활 이야기에서 다른 주민의 부탁으로 이어진다. 새 주민이나 방문객을 해금하는 조건으로 쓰지 않았다. 필요 수량·답례·안부 일수·진행 간격은 `default_seasonal_life_requests.tres`의 초기값이며 Claude 검토 대상이다.

## 시작과 전달

1. 튜토리얼과 첫 이웃 정착을 마쳐야 한다. 제안하는 주민도 정착해 있어야 한다.
2. 표의 선행 개인 부탁을 전달하고, 해당 주민의 후일담을 E로 끝까지 들어야 한다. 마지막 진행일의 다음 날 이후, 새 제안자와 안부를 나눈 날 3일이 필요하다.
3. 해당 계절에 제안자와 E로 이야기한다. 소개를 끝까지 읽었을 때만 부탁을 맡는다. 기존 주민 후일담·마을 이야기 등 앞선 대화가 있으면 먼저 이어진다.
4. 수첩에서 부족한 재료와 실제 전달할 주민을 확인한다. 원정에서 얻은 재료는 창고로 가져와야 한다. 가방과 진열대 재고는 세지 않는다.
5. 두 재료를 모두 준비한 뒤 주민과 E로 이야기한다. 최종 대화 완독 시 창고 재고를 다시 확인하고, 정확한 재료 소비와 답례·평판을 한 번 처리한다.

이 묶음은 기존 계절 사건의 직접 전달 흐름을 사용한다. 개인 부탁 17개와 개인 부탁 후일담 11개의 등록 수는 그대로이고, 마을 게시판에서 맡거나 전달하는 별도 개인 부탁은 아니다. 여름은 완제품 물·미네랄 워터·차 대신 **채집한 물**이 필요하다. 가을도 발광 등불 완제품 대신 원재료를 준비한다.

## 계절을 놓쳐도 천천히

- 소개 전에는 해당 계절에만 시작한다. 소개 도중 계절이 끝나면 맡은 것으로 기록하지 않는다. 다음 해당 계절에 다시 소개를 들을 수 있다.
- **소개를 완독해 맡은 뒤에는 다른 계절에도 준비·전달할 수 있다.** 이후 새 계절 제안보다 이미 맡은 계절 이야기의 안내가 먼저 나온다.
- 전달 기한과 시간대 제한은 없다. 완료 후 다음 해에 다시 답례를 받지는 않는다.
- 대화 중단·재료 부족·건축 모드에는 소비나 답례가 없다. 대화 종료 시 원래 시간 정지와 이동 상태를 복원한다.
- 기존 저장 진행 키를 재사용한다. 저장 복원 후 맡은 부탁과 완료 기억·재료·평판을 유지하고, 새 게임에서는 진행이 초기화된다.

기존 [사계절 마을 사건](콘텐츠_사계절_마을_사건.md) 4개는 각 계절의 현장 관찰·주민 이야기·물 전달 규칙을 유지한다. 이 기존 묶음은 계절 밖에서 진행을 멈췄다가 다음 해당 계절에 이어간다. 이번 생활 재료 부탁에만 맡은 뒤 계절 밖 진행을 허용했다. 계절 사건 합계는 8개, 관련 글 장면은 기존 17개 + 이번 12개 = 29개다. 매장 판매 행사는 공용 3개·계절 8개로 그대로다. 전체 대사 CSV는 197행이며 행 수는 퀘스트 수가 아니다.

## 이야기와 구현의 범위

플레이어가 이웃의 준비를 도와 재료를 나누고 수첩에 기억을 남기는 사건이다. 실제 간식·차 제조, 제조법 해금, 등불 설치/수리, 식탁/군중 생성, 음식 회복, 새로운 고객, 현금 답례를 발생시키지 않는다. 대사는 이미 준비를 시작했던 기억을 말하므로 맡은 계절이 지나도 읽을 수 있다. 새 기능이나 추가 보상을 글에서 약속하지 않는다.

- `seasonal_life_request_flow.gd`: 선행 부탁·후일담·간격·안부와 계절 조건 판정.
- `default_seasonal_life_requests.tres`: 사건 4개와 소개/기다림/마무리 12장면 문맥.
- `seasonal_village_flow.gd`: 두 설정 묶음 등록, 진행 중인 이야기 우선, 직접 전달 대상 안내. 기존 전달·재고 재검사·일회성 정산을 재사용한다.
- `seasonal_village_director.gd` / `village_journal_flow.gd`: 기존 현장/수첩 등록 연결.
- `requests_text.csv` / `content_voices.csv`: 러프 글과 장면 말투. 정식 인물 기준 파일은 유지한다.
- `request_text_tools.gd`: 기존 `service_text`로 moments만 등록하여 기계 events 행을 글과 구분한다.

메인 씬·큰 시스템 파일·이미지·달력은 이번에 수정하지 않았다. 사람 플레이와 최신 3D 작업 줄기 통합은 별도 확인 사항이다.

## Gemini 대사 보강

API는 호출하지 않았다. 기존 `service_text`에서 아래 12장면을 다듬는다. 현재 장면의 소개·부족 안내·실제 최종 전달 역할과 정식 인물 말투, 직접 E 전달과 창고 구분을 유지한다. 최종 `completion`은 수첩에 남는 실제 기억이다.

```bat
dev\gemini\run_request_text.bat draft service_text --ids spring_snack_ingredients_intro,spring_snack_ingredients_wait,spring_snack_ingredients_finish
dev\gemini\run_request_text.bat draft service_text --ids summer_reed_tea_materials_intro,summer_reed_tea_materials_wait,summer_reed_tea_materials_finish
dev\gemini\run_request_text.bat draft service_text --ids autumn_lamp_materials_intro,autumn_lamp_materials_wait,autumn_lamp_materials_finish
dev\gemini\run_request_text.bat draft service_text --ids winter_shared_meal_materials_intro,winter_shared_meal_materials_wait,winter_shared_meal_materials_finish
```

초안 생성과 게임 CSV 반영은 별도 단계다. 선행 행사에서 특정 주민이 상품을 샀다는 주장, 현재 계절/내일 일정 단정, 실제 제작·설치·새 방문객·추가 답례를 넣지 않는다. 수량은 수첩 UI가 표시한다.
