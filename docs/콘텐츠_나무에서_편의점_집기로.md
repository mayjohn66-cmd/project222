# 나무에서 편의점 집기로

사용자 요청(2026-10-05): 설치 오브젝트에 여러 종류와 설명을 만들고, 나무 진열대부터 현대 편의점 진열대까지 제작할 수 있게 한다.

## 1. 게임에서 확인

매장 관리 → **제작 → 매장 가구**에서 진열대와 계산대를, **건축**에서 창고 선반을 선택한다. 해금 전에도 목록에서 설명·실제 3D 외형·설치 크기·용량·조건·필요 재료를 확인할 수 있다. 제작 버튼은 오른쪽 하단에 고정하고 설명 영역만 스크롤한다. 제작한 집기는 가구 보관함에서 확인하고 기존 건축 방식으로 설치한다. 창고 선반은 창고에만 설치한다.

- 나무: 처음부터 제작 가능. 숲의 마른 가지와 호박 수액을 엮는 소박한 집기다.
- 보강 나무: 새 나무 집기를 한 번 제작하면 해금한다. 철광석을 더해 적층할 수 있는 틀을 만든다.
- 현대: 보강 나무 진열대를 제작하고 기존 `craft_first_shelf`(처음의 빵·생수 재현) 이야기를 **완료**하면 해금한다. 소개만 듣거나 제조법만 배우는 것으로는 해금되지 않는다.

첫 가게와 함께 온 집기 및 기존 16종의 ID·보유량·제작법은 유지한다. 새 10종을 기존 목록 뒤에 추가하여 옛 인덱스 저장의 순서를 유지한다. 새 게임에 무료 집기를 지급하지 않는다. 나무→보강→현대 조건은 이번에 추가한 집기의 제작에 적용하며 이미 소유한 집기의 설치를 막지 않는다.

## 2. 추가 집기 10종

진열대의 슬롯은 서로 다른 상품을 지정하는 칸이다. 한 층을 추가할 때는 같은 ID의 집기 한 개가 더 필요하며 최대 층수 이상 올릴 수 없다. 층수가 추가되어도 바닥의 설치 크기는 같다.

| ID | 이름 | 설치 칸 | 한 층 슬롯 × 칸당 재고 | 최대 층 | 제작 재료 | 재료 판매가 합계 |
|---|---|---|---|---|---|---|
| wood_shelf_1x1 | 작은 나무 진열대 | 1×1 | 2×3 | 1 | 가지4·수액1 | 120 G |
| wood_shelf_2x1 | 넓은 나무 진열대 | 2×1 | 3×4 | 1 | 가지6·수액2 | 200 G |
| reinforced_shelf_2x1 | 보강 나무 진열대 | 2×1 | 3×6 | 2 | 가지6·철광석3·수액2 | 320 G |
| modern_shelf_1x1 | 소형 편의점 진열대 | 1×1 | 2×8 | 3 | 철광석5·수정1 | 260 G |
| modern_shelf_2x1 | 표준 편의점 진열대 | 2×1 | 4×10 | 3 | 철광석8·수정2 | 440 G |

가격 합계는 재료를 팔았을 때의 기회비용이며 제작 시 추가 화폐를 내는 가격이 아니다. 크기·재료·해금·용량은 초기값이며 실제 가구 투자 회수 및 기존 집기와의 비교는 경제 검토 대상이다.

## 3. 설명과 외형

정식 설명은 `data/shop/catalogs/furniture_items.csv`의 `description`에 있다. 제작 상세와 가구 보관함 툴팁에서 읽을 수 있다. 수치는 설명 문구에 중복 저장하지 않고 실제 카탈로그에서 표시한다.

- 나무 진열대: 가지와 수액을 묶은 소박한 수확물 진열 자리. 나무 틀·뒷판·선반을 표시한다.
- 보강 나무 진열대: 나무틀에 철제 이음쇠를 더한 다음 단계. 앞쪽 철제 보강 부품을 표시한다.
- 편의점 진열대: 플레이어의 기억을 현지 재료로 재현한 흰 철제 선반. 회색 기둥과 흰 판·초록 가격표 띠를 표시한다. 가격표 띠는 외형이며 상품 가격 변경 기능을 추가하지 않는다.
- 나무 계산대: 나무 상판·동전함이 있는 현지 거래 자리. 기존 계산대와 같은 플레이어 직접 결제·직원 결제를 이용한다.
- 재현 계산대: 매끈한 상판·단말기 형태·초록 띠가 있는 집기. 새 자동 결제나 결제 속도 보너스는 없다.
- 창고 선반: 나무 기둥/판과 철제 기둥/판을 구분하고 실제 보관품을 표시한다. 일반 보관 집기이며 기존 별도 냉장·냉동 보존 시스템을 대신하지 않는다.

실제 매장·창고와 제작 미리보기는 같은 `ShelfAssets`/`FurnitureAssets`/`FurnitureVariantAssets` 모델을 사용한다. 래스터 이미지는 만들지 않았다. 목록 아이콘은 기존 크기별 진열대/계산대/창고 선반 아이콘을 재사용한다. 추후 전용 아이콘이 필요하면 위 10개 ID를 기준으로 사용자 이미지 도구에서 제작할 수 있다.

## 4. 데이터와 저장

- `furniture_progression.csv`: ID·기능 분류·발전 단계·선행 제작 단계·제품 이야기·해금 안내·창고 용량/슬롯·재질.
- `furniture_items.csv`: 이름·설명·분류·기존 아이콘 참조.
- `build_objects.csv`: 기존 가구 씬 참조·크기·회전·이동 차단·배치 기능·계산대 예약 영역.
- `shelf_data.csv`: 진열 슬롯·칸당 용량·최대 층.
- `furniture_3d.csv`: 새 ID의 실제 모델 분류·높이·두께.
- `furniture_recipes.csv`: 재료 소비. 10개 신규 레시피를 등록했다.

새 `FurnitureObjectCatalog`에서 필수 열/중복 ID/등록된 기능/레시피/발전 단계/창고 규격/해금 문구를 검사한다. 제작 실행 시 조건과 재료를 다시 확인하며 실패하면 집기를 지급하거나 재료를 일부만 소비하지 않는다. 기존 `ProductionRecipeService`의 재료 소비·실패 복구를 사용한다.

완료 기록은 기존 `PlayerProgress.story_beat_days`에 `furniture_craft:wood`, `furniture_craft:reinforced`, `furniture_craft:modern`으로 저장한다. 현대 집기의 제품 이야기 조건은 기존 `crafting_path:craft_first_shelf:done`을 읽는다. 새 저장 버전은 없다. 진열대 최대 층수를 설치와 복원에 적용하고, 창고는 저장 슬롯 복원 전에 종류별 용량을 설정한다. 창고 모델의 저장품 갱신을 특정 ID 한 개에서 모든 실제 창고 노드로 확장했다.

가구 설명은 이번 사용자 요청에 따른 콘텐츠 초안이다. Gemini 검토 시 이름/ID·기능·수치·조건을 유지하고 `description` 문장만 다듬을 수 있다. 현재 `requests_text` 작성 도구의 대사 분류에 가구 설명을 새 종류로 등록하지 않았다. Gemini API를 호출하지 않았다.

```powershell
Godot --headless --path . res://dev/scenes/check_furniture_objects.tscn
# 기존 기능과 전체 자원 검사
Godot --headless --path . res://dev/scenes/check_main_content_integration.tscn

Godot --headless --path . res://dev/scenes/check_manual_checkout.tscn

python tools/balance_baseline.py .
```

신규 검사: 10종 모두 실제 UI에서 재료 소비/가구 지급 → 네 방향 배치 → 종류별 용량·적층 제한 → 고객 재고 수령/계산대 실제 결제 → 같은 ID·회전·재고·층수 복원 → 같은 종류/수량 철거 회수. 창고 입고 상한과 내용물 복원, 완전한 저장 파일 쓰기/읽기/적용, 실제 매장·방 3D 생성, 잠금 중 클릭/직접 API 우회 차단, 기존 ID 순서, 관리 메뉴가 일시 정지된 상태의 미리보기·고정 제작 버튼을 검사한다.

경제 기준선은 객단가276 G·가정 일매출7456 G·초기 급여0, 종료0이다. 이 도구는 새 집기 투자·설치 크기·적층에 따른 실제 재고 운영의 투자 회수를 계산하지 않는다. 기존 원인인 인증서/누락 아이콘 경고는 신규 기능 결과와 구분한다.
